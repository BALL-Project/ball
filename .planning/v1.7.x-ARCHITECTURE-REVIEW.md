# v1.7.x Architecture Review — ownership, single source of truth, message passing

**Date:** 2026-05-20
**Trigger:** user direction — "make sure there is ONE central
class/instance that controls what is happening, to avoid the many
1.6-vs-1.7 regressions where some things worked and others didn't
after the mere redesign of interface elements. Clear message passing
could help. Resolve pre-1.6 technical debt."
**Scope:** the v1.7 BALLView VIEW/widget architecture (NOT the KERNEL
data model — that's the separate v2.0 MoleculeStore work).

---

## 1. The regression class, root-caused

The 1.6→1.7 testing pain ("works here, not there") was NOT random.
Every instance traces to **the same structural defect: more than one
code path mutates the same state, and the UI redesign rewired some
paths but not others.** Receipts from the UFG log:

| UFG | Symptom | Dual-path root cause |
|-----|---------|----------------------|
| UFG-03 | Representations + colorings don't update | Inspector Model/Coloring/Material Controllers shipped as READ-ONLY MIRRORS; mutation still went through legacy dialogs. The Inspector showed values but couldn't change them. |
| UFG-15 | Add-Hydrogens toolbar no-op while menu worked | Toolbar (`Scene::saturateWithHydrogens` → AddHydrogenProcessor) and menu (`MolecularStructure::addHydrogens` → FragmentDB) used DIFFERENT algorithms for the "same" operation. |
| UFG-07/27/31 | Selection inconsistent (tree blue vs scene yellow) | Selection had TWO meanings: Qt cursor-selection vs BALL composite-selection. Two sources of truth for "what is selected." |
| UFG-25 | Background color change not reflected | `Stage::setBackgroundColor()` stored the value but the GL `glClearColor` push lived on a separate path (`applyPreferences`) the Inspector didn't call. |
| v1.7.x-10/11 | Add-H / Optimize toolbar broke post-UFG-27 | The toolbar enable-gate and the action body consulted DIFFERENT selection sources after the selection model changed under them. |

**The common shape:** *Operation X has implementation A (legacy) and
implementation B (new UI). The redesign touched B but A stayed, or
B was a hollow mirror of A. Whichever path a given test exercised
determined whether it "worked."*

This is a **separation-of-concerns + single-source-of-truth failure**,
not a rendering bug.

---

## 2. What the architecture already gets RIGHT

The v1.7 design already names the correct central abstractions —
the problem is incomplete execution, not absent design.

### 2a. State ownership (the sources of truth) — CORRECT

| Domain | Single owner | Notes |
|--------|--------------|-------|
| Molecular hierarchy + selection | `MainControl` (owns `CompositeManager`; selection = `Composite::isSelected()`) | UFG-27 unified cursor↔composite selection — the dual-meaning defect is RESOLVED. |
| Scene / render state | `Stage` (owned by `Scene`) | background, fog, camera, lights, stereo, coordinate system |
| Per-representation state | `Representation` (owned by `RepresentationManager`) | model type, coloring, material, transparency, clipping, label |

These are genuinely single-owner. The defect was never "two owners of
the data" — it was "two paths that WRITE the data."

### 2b. Notification bus — EXISTS, under-used

`ConnectionObject` is a tree-structured message bus: `MainControl` is
the root; every `ModularWidget` registers as a child. `notify_(Message*)`
sends UP to the root, which broadcasts DOWN to all leaves except the
sender. Reply messages queue at the root. Typed messages:
`CompositeMessage`, `NewSelectionMessage`, `ControlSelectionMessage`,
`SceneMessage`, `RepresentationMessage`, …

This IS "clear message passing" for NOTIFICATIONS — but it's used
inconsistently (some state changes broadcast, some don't), and it is
NOT used for COMMANDS (mutations are direct calls).

### 2c. The mutation funnel — DESIGNED, half-built

The `Controller` layer (`source/VIEW/KERNEL/controllers/`) is the
intended single mutation funnel. `PATTERN.md` states the invariant
explicitly:

> "Both the legacy dialog and the new Inspector section bind to the
> same Controller, so the two surfaces are consistent *by
> construction* — not by message-bus discipline."

This is exactly the "ONE central thing controls each operation" the
user wants. **But only 1 of 9 Controllers (StageController) was
actually cut over to mutating at v1.7.0.** The other 8 shipped as
read-only mirrors → the Inspector could DISPLAY but the legacy dialog
still OWNED mutation → UFG-03 and friends.

(ModelController / ColoringController / MaterialController were cut
over during the rc2 UFG-03 fixes. Camera / Light / Stereo / Clipping /
Label remain read-only mirrors as of v1.7.0.)

## 3. Target architecture (the discipline to enforce)

Four rules. None require a rewrite — they require COMPLETING and
ENFORCING what's already designed.

### Rule 1 — One owner per state domain (done; protect it)
`MainControl` owns selection + composites; `Stage` owns scene state;
`Representation` owns per-rep state. **No view caches authoritative
state.** Views re-read from the owner on notification. (UFG-12 tab
resync already does this; make it universal.)

### Rule 2 — One mutation funnel per domain: the Controller (COMPLETE THE CUT-OVER)
EVERY surface that changes scene/rep state — Inspector section,
legacy dialog, toolbar action, menu action, Python — routes through
the relevant `Controller`'s `setX()` + `apply()`. No surface mutates
`Stage`/`Representation` directly.
- **v1.7.x action:** finish the 8 read-only→mutating cut-overs
  (Camera, Light, Stereo, Clipping, Label; the Rep trio already done).
  v1.7.x-01/02 (Clipping/Label sections) ARE this work.
- **Enforcement:** a grep-gate CI check that flags direct
  `stage_->setX()` / `rep->setX()` calls outside a Controller.

### Rule 3 — One notification bus: ConnectionObject (use it consistently)
After a Controller's `apply()` mutates the owner, the owner (or the
Controller) broadcasts the matching typed Message. All views react
by re-reading. No view assumes it's the only mutator.
- **v1.7.x action:** audit each Controller `apply()` — confirm it
  triggers the right notification (e.g. UFG-25's `refreshSceneRenderState`).

### Rule 4 — View = pure presentation (no business logic in widgets)
Widgets render source-of-truth + emit user intent. The
`Scene::saturateWithHydrogens`-style "toolbar has its own algorithm"
defect (UFG-15) is banned: toolbar/menu actions delegate to the same
Controller/command as everything else.
- **v1.7.x action:** systematic dual-path sweep (see §5).

### The "ONE central class" answer
There is **not one god-class**, and there shouldn't be (that's its
own anti-pattern). Instead there is a **layered single-authority
model**:
- `MainControl` = the central COORDINATOR (state owner + message-bus
  root + ModularWidget registry). This is the "one instance that
  knows what's happening."
- The `Controller` layer = the central MUTATION authority (one funnel
  per domain).
- `ConnectionObject` = the central NOTIFICATION channel.

The user's instinct is right; the fix is to make these three the
ONLY paths and delete the bypasses.

---

## 4. CommandRegistry — the missing unifier (opportunity)

`CommandRegistry` already exists (Phase 6, for the command palette):
every `QAction` registers with a canonical name + category. Right now
it's a discoverability catalog only.

**Opportunity (v1.7.x or v1.8):** make CommandRegistry the COMMAND
dispatch layer too. A toolbar button, a menu item, a command-palette
entry, and a Python call would all resolve to the same registered
command → which calls the same Controller. This structurally
eliminates the UFG-15 dual-algorithm class: there's exactly one
implementation per command, reached four ways.

Scoped as **v1.7.x-23** below (audit + converge dual-path actions
onto registered commands); full command-object/undo-redo is v2.0.

## 5. v1.7.x vs v2.0 split

### v1.7.x (discipline + completion — LOW risk, resolves the regression class)
- **Complete the Controller cut-over** (Camera/Light/Stereo/Clipping/
  Label → mutating). v1.7.x-01/02 are part of this. → **new umbrella
  v1.7.x-24.**
- **Dual-path action sweep** — find every operation with a
  toolbar+menu (or legacy+Inspector) split and converge on one
  Controller/command. → **new v1.7.x-23.**
- **Notification audit** — every Controller `apply()` fires the right
  Message; no view caches stale state. Folds into the cut-over.
- **CI grep-gate** — flag direct `stage_->`/`rep->` mutation outside
  Controllers; flag new `QAction` not registered with CommandRegistry.
  → **new v1.7.x-25.**
- The design-depth items (16/17) MUST follow Rules 1-4 — that's the
  Codex anti-regression mandate already recorded.

### v2.0 (deeper pre-1.6 debt — higher risk, separate milestone)
- **Replace the bespoke `ConnectionObject` tree** with Qt signals/slots
  or a typed event bus. The custom up-to-root-then-broadcast-down tree
  + manual message queue + `deletable` flag is pre-1.6 debt; it's
  error-prone (re-entrancy bugs like the v1.7.x-13 cascade) and
  opaque. Qt's signal/slot or a small event-dispatcher is the modern
  replacement.
- **Formal command pattern + undo/redo** on top of CommandRegistry.
- **MoleculeStore SoA** (already in KERNELV2 plan) — the data-model
  half of single-source-of-truth.
- **Kill `Scene::updateGL()`'s synchronous `paintGL()` hack**
  (TODO: remove! at scene.C) — replace with proper
  `QOpenGLWidget::update()` scheduling. The synchronous paint is what
  amplified the UFG-13 redraw-storm freeze.

## 6. Why this is the right time

The Inspector-depth work (v1.7.x-16/17) is about to ADD a lot of new
mutating controls. If the Controller cut-over isn't completed and the
discipline isn't enforced FIRST, every new control risks re-creating
the dual-path defect. Doing the cut-over + contract before the depth
work is the structural guarantee that the "works here, not there"
class doesn't recur. This is the same sequencing Codex demanded for
the reset contract (v1.7.x-18 before 16/17) — generalized.

## 7. Codex review incorporated (2026-05-20) — the analysis was too optimistic

Codex adversarial review found the §1-6 framing directionally right
but **over-compressed**. "Dual paths" is a SYMPTOM; the deeper defect
is a **missing command/transaction contract**. Twelve corrections,
folded into a revised plan:

### 7a. The real defect: no command/transaction contract
Centralizing mutation in Controllers does NOT fix the regression class
if Controllers are just *setter bundles* (`setX(); apply(); notify()`).
That still fails when:
- intermediate state is observable mid-`apply()`,
- `apply()` is RE-ENTERED through the notification it triggers
  (exactly the v1.7.x-13 cascade — the bus is NOT reliable),
- multiple Controllers mutate related domains in the wrong ORDER,
- there's no transaction boundary / preconditions / postcondition.

So Controllers must be **command handlers with an explicit contract**,
not setter bundles. The contract (the thing v1.7.x must DEFINE before
more Inspector mutation lands):

```
Controller::apply() contract — every implementation MUST:
  1. validate preconditions (active rep/scene exists; values in range)
  2. begin a re-entrancy guard (ignore notifications while mutating)
  3. mutate the single owner (Stage / Representation / Composite)
  4. emit ONE typed domain event (the notification)
  5. request render invalidation (soft refresh, not full rebuild)
  6. [v1.7.x: record a reversible intent payload; v2.0 wires undo]
  7. end the re-entrancy guard
  Ordering is part of the contract, not incidental.
```

### 7b. Re-entrancy must be designed, not assumed away
The notification bus can synchronously re-enter Controllers (proven by
the freeze cascade). Every `apply()` needs a guard (the
`ignore_messages_` pattern, generalized into the base contract). This
is **v1.7.x scope**, not v2.0 — it gates the depth work.

### 7c. Undo ownership can't be deferred wholesale
If Controllers own mutation, they must own **command-shaped boundaries
+ reversible intent payloads NOW**, even if the undo STACK lands in
v2.0. Otherwise v1.7.x bakes in APIs v2.0 must break. Revised split:
v1.7.x = command-shaped Controller API (capture before/after for each
apply); v2.0 = the undo/redo stack that consumes it.

### 7d. Python is an enforcement hole
If PyBALL can mutate `Stage` / `Representation` / `Composite` /
processors directly, the funnel is not enforced. Decision needed:
either bindings route through the Controller/command layer, or Python
is a documented privileged escape hatch (acknowledged, not silent).
→ **flagged for the v2.1 PyBALL wrap (999.15); documented now.**

### 7e. The grep-gate is mostly theatre
Grep misses aliases, helper wrappers, lambdas, macros, indirect
manager access, processor-side mutation, friend classes, Python
bindings, generated MOC code, and calls through base pointers. It
false-positives owner-internal mutation. **Replace "grep-gate" with a
layered enforcement:**
- forbidden-include dependency checks (Controllers: no `<QtWidgets>`
  — already a PATTERN.md rule; make it a CI assert),
- clang-tidy/AST check: mutating methods on Stage/Representation
  callable only from allowlisted Controller TUs,
- **contract tests** (the real enforcement): exercise the SAME
  operation via menu / toolbar / Inspector / Python and assert
  identical postconditions on the owner. This is what actually
  catches dual-path drift.
- CI assert: every registered command has exactly one implementation.

### 7f. Narrow the CommandRegistry scope for v1.7.x
Turning the discoverability registry into a generalized command bus
risks destabilizing action plumbing. **v1.7.x target = "one QAction
implementation per operation"** (converge dual-path actions), NOT a
generalized dispatcher. The dispatcher is v2.0.

### 7g. Qt lifetime & event-loop ownership is its own concern
Legacy-C++ + Qt fails through lifetime / event-loop behavior, not just
"who calls the setter" — and v1.7.0 already proved it: UFG-30
(dtor deref of a child torn down first), UFG-32 (dangling section
pointers from deleteLater), UFG-18 (GL-context init ordering),
UFG-26 (QPainter on a QOpenGLWidget off the paint cycle). The clean
architecture MUST cover: QObject parentage discipline, signal lifetime
(QPointer for cross-owner refs), queued-vs-direct connection choice,
thread affinity, and OpenGL-context ownership. → **new v1.7.x-26:
Qt-lifetime ownership audit + conventions doc.**

### 7h. Make bypass awkward by API design, not just discipline
"Discipline" decays. Owner APIs (`Stage`, `Representation`) currently
expose broad public setters → any code can bypass the Controller.
Narrow them: Controller-only friendship (sparingly), internal/private
setters where possible, explicit domain-service methods. → folds into
the cut-over umbrella (v1.7.x-24).

### 7i. Selection unification needs PROOF, not confidence
UFG-27 unified cursor↔composite selection, but that doesn't prove ALL
consumers (tree, scene picking, action enable-gates, processor
targets) read `Composite::isSelected()`. → **contract test** asserting
all four consumers agree after a selection change (part of v1.7.x-25).

### Revised v1.7.x architecture work (supersedes §5 v1.7.x list)

| Item | Title | Was |
|------|-------|-----|
| v1.7.x-24 | Complete Controller cut-over to **command-shaped** apply() contract (validate/guard/mutate/emit/invalidate/undo-payload), all 8 remaining; narrow owner setters | "cut-over" |
| v1.7.x-23 | Dual-path action convergence — one QAction impl per operation (NOT a command bus) | "command dispatch" |
| v1.7.x-25 | Contract tests: menu/toolbar/Inspector/Python → identical owner postconditions; selection-consumer agreement test | "grep-gate" |
| v1.7.x-26 | Qt-lifetime ownership audit + conventions doc (parentage, QPointer, queued/direct, GL-context) | (new) |

**Deferred to v2.0 (confirmed):** ConnectionObject→Qt-signals/event-bus
replacement; undo/redo STACK (consumes v1.7.x command payloads);
MoleculeStore SoA; CommandRegistry generalized dispatch;
`Scene::updateGL` synchronous-paintGL removal.

**Hard sequencing:** v1.7.x-24 (command contract) + v1.7.x-26 (Qt
lifetime conventions) land BEFORE the Inspector-depth work
(v1.7.x-16/17), because 16/17 add the most new mutating controls and
must be born compliant. v1.7.x-25 (contract tests) lands alongside —
it's the only real enforcement.
