# v1.7.4 — Codex adversarial plan review (2026-05-22)

**Reviewer:** Codex CLI (codex-cli 0.128.0), read-only, grounded against `source/VIEW/`.
**Verdict:** **PROCEED-WITH-CHANGES** — architecture direction right; written milestone is internally inconsistent and over-promises enforcement, Python compatibility, and effort. Fix the contradictions and stage owner-narrowing before implementation.

## HIGH

1. **`apply()` return type contradiction.** Contract says `apply()` returns `void` (`v1.7.4-ARCHITECTURE-CONTRACT.md:130`), but 999.60's re-entrancy test needs `bool apply()` (true=mutated / false=dropped) (`999.60-01-PLAN.md:144`). Decide once: `void` + separate diagnostics, or `bool` everywhere.
2. **Controller count inconsistent.** Docs say "8 controllers" repeatedly; the contract lists **9** (Model/Coloring/Material/Clipping/Label/Stage/Camera/Light/Stereo) and source has 9 QObject controllers. Breaks test scope + acceptance accounting.
3. **Owner-API narrowing fallout underestimated.** `Stage`/`Representation` setters are public and called from many non-controller sites — `displayProperties.C`, `stageSettings.C`, `stereoSettingsDialog.C`, `scene.C`, `interactionModeManager.C`, `standardDatasets.C` — not just file-IO/builder. (Note: 999.57/999.58 already relocated displayProperties + scene.C material/light/stage; interactionMode/datasets/etc. remain.)
4. **Python-binding contradiction.** 999.59 says binding regen is v2.1, but the contract/release-notes claim controller-centric Python bindings in v1.7.4 + a one-release deprecation warning. If owner setters go private before bindings are shimmed/regenerated, PyBALL breaks. Resolve before narrowing.
5. **"Always `update(false)`" too simplistic.** `ModelController::apply()` correctly uses `update(rebuild)` (model-processor changes need a rebuild); blanket `false` → stale geometry. `StageController::apply()` deletes reps on vertex-buffer toggle + switches renderers. Need **per-domain invalidation** language, not one rule.
6. **Re-entrancy guard spec exceeds reality.** Plan wants thread-safe, nest-aware RAII; current `controllerApplyGuard.h` is a plain `bool&` (not thread-safe, not nest-aware), and `ClippingController::apply()` omits the guard. Real gap to close.

## MEDIUM
- Sequencing: 999.60 tests depend on 999.59, but 999.59 acceptance depends on 999.60 tests → land the harness/compile-fail infra FIRST (disabled fixtures), then cut controllers over one-by-one.
- Python parity overstated: 999.60 skips Python when PyBALL is off, but notes promise parity → accept 3-surface parity in v1.7.4 OR put PyBALL in CI.
- CommandRegistry is QAction-discovery-based today, not "one impl per command body" → needs an explicit migration or the dual QAction/menu path stays untested.
- `friend class XController` granularity wrong for `Stage` (camera/stereo/light/background/renderer all mutate it → "private but not narrow"). Consider owner-side private methods + a `StageMutation`/builder facade.
- 999.64 reset overlaps existing `InspectorSection` reset plumbing (`controller_->revert(); apply();`) → reframe as REPLACING the two-step with single `Controller::reset()`, not adding from scratch.
- 999.63 `previewRange()` live-preview is a contract escape hatch → make it explicitly non-owner/render-only + tested, or defer to commit-on-release for v1.7.4.

## LOW
- Opaque-paint lint (grep parent chains ≤3 hops) noisy/incomplete → warn-only without a whitelist + synthetic tests.
- `ControllerJob` (async base) premature — nothing in v1.7.4 needs it; defer.
- Scope optimistic — 999.59 + friend-fallout + contract tests + histogram + reset cleanup > "~3 weeks / ~50 files" unless aggressively staged and some promises deferred.

## Answers
1. Command-shaped funnel is the right fix (convention-only would rot). Safer: standardize `apply()` + parity tests first; defer broad owner privatization + Python promises until compile-fallout is measured.
2. Owner narrowing sound in principle, not as scoped. Python is the blocking ambiguity — regenerate/shim bindings in v1.7.4 OR don't privatize externally-visible setters yet.
3. Sequencing changes: test harness first → 999.59 incremental per controller → 999.61 before/with lifetime changes → 999.63/999.64 only after ColoringController + `Controller::reset()` stable.
4. Biggest regression risks: stale rendering from wrong `update(false)`; stage renderer side-effects inside apply; material/model transparency interaction; clipping/label non-idempotence; selection-agreement tests exposing existing direct selection-mutation paths.
5. Scope realistic only if v1.7.4 reduces promises: no deep Python parity, no async base unless needed, owner-narrowing staged behind compile audits, histogram live-preview deferred.
