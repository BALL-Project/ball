## v1.7 narrative

v1.6.x cleaned the substrate. v1.7 is when BALLView becomes a real shippable application:
- end users get a signed, notarized macOS bundle they can double-click without "unidentified developer" warnings
- end users get a signed Windows installer they can run without SmartScreen warnings
- both auto-update via Sparkle/WinSparkle
- the warning census from 999.22 actually gets executed
- the v1.4 → v1.7 modernization journey gets captured in a retrospective + audit-procedure document so the next maintainer can understand what was done and why

No substrate rewrites in v1.7 — those are v2.0 (KERNEL MoleculeStore, PIPE-01 renderer, gemmi, YAML, deprecated-code removal). v1.7 is "ship the v1.6.x substrate properly to end users."

## CI matrix gating strategy

User direction (2026-05-17): **macOS only for initial test-builds → +Linux when phases complete → +Windows as v1.7 closure gate.**

### Stage 1 — macOS-only (initial, default for all early v1.7 work)
- `build (macos-arm64)` blocking
- `lint` blocking
- coverage and other Linux jobs **commented out** in matrix on v1.7-modernization branch
- Windows job **commented out** in matrix
- `build (linux-x64)`, `build (linux-arm64)` **commented out**
- macOS Phase 9 test gatekeeper still runs (it's macOS-side)
- Rationale: fastest iteration cycle for early v1.7 phase work; macOS-arm64 is the canonical dev platform here

### Stage 2 — +Linux (triggered when Wave 1 phases land + a critical mass of Wave 2 lands)
- Uncomment `linux-x64` + `linux-arm64` matrix entries (blocking)
- Uncomment `coverage (Linux, gcov, non-blocking)`
- Rationale: cross-arch + cross-toolchain regression net before approaching closure
- Promotion criterion: ≥4 of 6 Wave 1 phases COMPLETE (Phase 8, 999.22, plus any 2 of {9, 999.4b, 999.23, 999.26})

### Stage 3 — +Windows (v1.7 closure gate)
- Uncomment `windows-x64` matrix entry (blocking)
- Wire `release.yml` to v1.7 tag pattern
- Rationale: Windows is the slowest + flakiest CI surface (see v1.6.2 release pipeline 5-iteration history); save it for after everything else is green
- Promotion criterion: All Wave 1 + Wave 2 COMPLETE; ready for 999.25 closure docs; tag candidates being prepared

### Implementation
- Edit `.github/workflows/ci.yml` on v1.7-modernization branch only; v1.6-modernization branch's matrix is untouched (v1.6.2 release pipeline keeps its full matrix)
- Use commented-out matrix entries with clear "STAGE-N gate" annotation rather than `if:` conditions, so the matrix shape is the documentation

## Phase plan files to be written (delegate to gsd-planner agents)

Per-phase PLAN.md, REQUIREMENTS.md, and (where applicable) RESEARCH.md will be authored under `.planning/phases/<phase-N>/`. The orchestration:

1. **Wave 1 planning (parallel, 6 agents):** spawn one `gsd-planner` per Wave 1 phase. Each agent reads ROADMAP's existing phase entry, gathers codebase context, and writes phase-specific PLAN.md.
2. **Wave 2 planning:** dispatched as Wave 1 phases complete; planning may begin while Wave 1 executes (planning is read-only of codebase).
3. **Wave 3 planning:** waits for all phase summaries to exist (retrospective is meta-content).

## Risk register

| Risk | Mitigation |
|---|---|
| Phase 8 SignPath certificate provisioning is org-bureaucratic + may block Windows installer signing | Start cert acquisition request in W1; design Phase 8 to ship macOS signed/notarized + Linux + Windows-unsigned-with-warning as fallback if cert delays |
| Sparkle/WinSparkle integration may surface Qt 6 plugin / windeployqt issues | Build a throwaway spike (1-2 days) before committing to full 999.8 plan |
| 999.22 whole-tree census output may be larger than expected → 999.22a/c may not fit in v1.7 | Split 999.22a into "tier-A mechanical sweep" (always v1.7) + "tier-B larger swings" (v1.8 if surfaces) — already partially in census policy |
| macOS-only initial CI may miss a Linux regression that lands in stage 2 with several phases of accumulated drift | Phase 9 test triage's macOS test suite catches behavioral regressions; cross-platform compile regressions only surface on stage-2 promotion, but each phase's PLAN must include a "Linux smoke verify" step before flagging COMPLETE |
| 999.25 retrospective scope-creep (4 versions × many decisions to capture) | Hard-cap at 1 day; constraints-first writing — list the decisions, then the rationale chain, then the audit-procedure-extracted-from-rationale; no narrative |
| Windows-only closure gate (stage 3) discovers Qt 6 + vcpkg + signed-installer interaction bugs late | Allocate ≥2 weeks closure-gate buffer; cross-port v1.6.2's vcpkg artifact cache trick (already committed in 357d13e) |
