## 0. The reframing (why the scope is different than PATTERN.md says)

`source/VIEW/KERNEL/controllers/PATTERN.md` and the arch review both
describe v1.7.x-24 as *"cut over the 8 remaining read-only mirrors."*
**That inventory is stale.** Auditing the actual `apply()` bodies
(2026-05-20):

| # | Controller | PATTERN.md says | ACTUAL apply() | Re-entrancy | Validation | Invalidation hook |
|---|------------|-----------------|----------------|-------------|------------|-------------------|
| 1 | Stage     | cut-over | **mutates Stage** | ✗ none | null-check only | `scene_->refreshSceneRenderState()` |
| 2 | Camera    | read-only | **mutates Camera** | `isBusy()` defer | null + degenerate-state | `scene->update()` |
| 3 | Stereo    | read-only | **mutates eye/focal/swap** (`enabled_` still mirror) | `isBusy()` defer | null-check | (stage) |
| 4 | Light     | read-only | **upserts AMBIENT LightSource** | `isBusy()` defer | null-check | `Scene::lightsUpdated(true)` |
| 5 | Model     | read-only | **mutates (heavy, 18 sites)** | `isBusy()` defer | null-check | (rep rebuild) |
| 6 | Coloring  | read-only | **mutates (8 sites)** | `isBusy()` defer | null-check | (rep recolor) |
| 7 | Material  | read-only | **mutates per-rep Material** | `isBusy()` defer | null-check | (scene/stage) |
| 8 | Clipping  | read-only | **STUB** (Log.info + appliedStub) | — | — | none (legacy dialog owns) |
| 9 | Label     | read-only | **STUB** (Log.info + appliedStub) | — | — | none (legacy dialog owns) |

**Consequences for scope:**

- **7 of 9 already mutate.** There is no large mutation-migration left.
  The legacy `apply()` bodies were already copied into the controllers
  during the rc cycle (UFG-03 / UFG-11 cut-overs).
- **The real work is HARMONIZATION, not migration.** The 7 mutating
  controllers each invented their own discipline: Stage has *no*
  `isBusy()` guard while the other six do; only Camera validates domain
  preconditions (degenerate viewpoint); invalidation hooks are three
  different calls; **none** has a true re-entrancy guard (an `isBusy()`
  *defer* is not the same as an `ignore-notifications-while-mutating`
  guard — the freeze cascade re-entered through the *notification*, not
  through `isBusy()`); **none** captures an undo payload; and the
  "emit ONE typed event" rule is violated everywhere (per-property
  `xxxChanged` fire from the setters, `apply()` emits a generic
  `appliedStub()`).
- **Clipping + Label are NOT urgent.** They have no Inspector consumer
  (`inspectorView.C` wires only RepHeader/Model/Coloring/Material on the
  Representation tab). They cannot create a dual-path drift today because
  the only path is the legacy dialog. They stay stubs until/unless
  v1.7.x-01/02 add their sections — and that should happen *after* the
  contract exists, so they're born compliant.

So v1.7.x-24 becomes: **(A) build the shared command-contract machinery,
(B) retrofit the 7 mutating controllers onto it, (C) leave Clipping/Label
as compliant stubs.** This is lower-risk than a migration but is exactly
the regression-prevention Codex demanded.

## 1. Shared machinery to build (the contract, in code)

Today each controller is `class XController : public QObject` with no
shared base. Introduce shared machinery so the 7-step contract is
*provided*, not *re-implemented per controller*.

### 1a. `ControllerApplyGuard` (RAII re-entrancy guard)

```cpp
// include/BALL/VIEW/KERNEL/controllers/controllerApplyGuard.h
// A controller sets applying_=true for the duration of apply(); any
// notification slot checks isApplying() and returns early, breaking the
// synchronous re-entry that caused the v1.7.x-13 freeze cascade.
class ControllerApplyGuard {
  bool& flag_;
public:
  explicit ControllerApplyGuard(bool& flag) : flag_(flag) { flag_ = true; }
  ~ControllerApplyGuard() { flag_ = false; }
  ControllerApplyGuard(const ControllerApplyGuard&) = delete;
};
```

This is deliberately NOT a base-class virtual — it's a stack guard so
exceptions/early-returns always clear the flag. Each controller gets a
`bool applying_ = false;` member and every notification slot (the
`onControllerXxxChanged_` handlers in the *sections*, and any internal
revert-on-notify) early-returns when `applying_`.

### 1b. Optional base `Controller` (decide at green-light — see §5 Q1)

Two options, user picks:

- **Option A (mixin/base class):** `class Controller : public QObject`
  providing `applying_`, `isApplying()`, a pure virtual
  `doApply()`/`doValidate()`/`captureUndo()`, and a non-virtual
  `apply()` that runs the 7 steps in order. Pro: contract enforced
  structurally; impossible to get the ordering wrong. Con: touches all 9
  class declarations + MOC; bigger diff.
- **Option B (free-function skeleton + guard only):** keep each
  controller standalone; provide `ControllerApplyGuard` + a documented
  apply() skeleton comment block + the undo-payload struct. Pro: minimal
  churn, lower regression risk. Con: ordering is convention, re-checked
  by contract tests (v1.7.x-25) not by the type system.

Recommendation: **Option B for v1.7.x** (lower risk, the contract tests
are the real enforcement per §7e), **Option A deferred to v2.0** when the
undo stack lands and a base class pays for itself.

### 1c. Undo-intent payload (capture now, stack later — §7c)

```cpp
// A controller captures a reversible "before" snapshot at apply() time.
// v1.7.x only STORES it (and exposes lastUndoIntent()); v2.0 wires the
// stack that pops it. Shape is per-domain but uniform interface:
struct UndoIntent {
  std::function<void()> undo;   // restores prior owner state
  QString label;                // "Background colour", "Ambient", …
};
```

For v1.7.x the capture can be as cheap as snapshotting the controller's
mirrored fields before mutation and building a lambda that re-applies the
old values. The point (§7c) is that the *API boundary* exists now so v2.0
doesn't have to break it.

### 1d. Uniform invalidation

Pick ONE soft-invalidation entry point per owner domain and route all
controllers through it, instead of the current three-way split
(`refreshSceneRenderState` / `scene->update()` / `lightsUpdated`).
Document which call each domain uses; do NOT call full
`redrawAllRepresentations(true)` (that was the freeze, UFG-13).

## 2. The reference retrofit: StageController

StageController is the documented exemplar, so it must become the
*compliant* reference FIRST (commit 1). Current `apply()`
(`stageController.C:108`) is missing: the re-entrancy guard, domain
validation beyond null-check, undo capture, and it emits `appliedStub()`
rather than a single typed event. Target shape:

```cpp
void StageController::apply()
{
  if (applying_) return;                       // 0. re-entry shield
  if (stage_ == nullptr) { Log.warn()…; return; } // 1. preconditions
  // (Stage has no isBusy peer-state to validate beyond null)
  ControllerApplyGuard g(applying_);           // 2. begin guard
  UndoIntent intent = captureStageUndo_();     // 6a. capture BEFORE
  ColorRGBA c; c.set(background_color_);        // 3. mutate the one owner
  stage_->setBackgroundColor(c);
  stage_->showCoordinateSystem(show_coordinate_system_);
  stage_->setFogIntensity(fog_intensity_);
  stage_->setEyeDistance(eye_distance_);
  stage_->setFocalDistance(focal_distance_);
  last_undo_ = std::move(intent);              // 6b. store intent
  if (scene_) scene_->refreshSceneRenderState();// 5. soft invalidate
  Q_EMIT applied();                            // 4. ONE typed event
}                                              // 7. guard ends (RAII)
```

(`appliedStub()` → `applied()` rename is the 999.48 cleanup already
noted in the code; do it here.) Commit 1 = StageController retrofit +
the `ControllerApplyGuard`/`UndoIntent` headers + the section-side
`applying_` early-returns for StageSection/BackgroundSection.

## 3. Per-controller harmonization checklist (commits 2–7)

Each is its own atomic commit. For every controller:

- [ ] add `bool applying_` + `ControllerApplyGuard` at top of `apply()`
- [ ] section notification slots (`onControllerXxxChanged_`) early-return
      on `controller_->isApplying()` (prevents the bus re-entry)
- [ ] keep/normalize the `isBusy()` defer (it's a *separate* concern from
      re-entrancy — defer when MainControl is mid-operation)
- [ ] domain precondition validation (not just null) where the owner has
      invariants (Camera already does; add range clamps where setters
      take raw slider ints)
- [ ] capture `UndoIntent` before mutation; store in `last_undo_`
- [ ] route invalidation through the chosen per-domain soft hook
- [ ] emit ONE typed `applied()` event (rename `appliedStub`)
- [ ] confirm no `<QtWidgets>` include crept in (PATTERN.md rule → §7e CI assert)

| Commit | Controller | Owner mutated | Notes specific to it |
|--------|-----------|---------------|----------------------|
| 2 | Camera | `Stage::getCamera()` | already validates degenerate viewpoint — keep; add guard + undo |
| 3 | Stereo | Stage eye/focal/swap | `enabled_` stays mirror until Renderer/RenderSurface boundary (SEED-001 step 5) — document, don't mutate renderer mode |
| 4 | Light  | Stage AMBIENT LightSource upsert | preserve non-ambient lights; undo = restore prior ambient |
| 5 | Material | per-rep `Rendering::Material` property | heaviest seeding logic; undo = prior Material property |
| 6 | Coloring | rep color processor | 8 mutation sites; ensure single recolor invalidation |
| 7 | Model | rep model processor | heaviest (18 sites); model rebuild is expensive — verify soft-invalidate not full rebuild |

Clipping (8) + Label (9): **no change** beyond adding the guard scaffold
for uniformity; they stay `Log.info` stubs (commit 8, trivial, optional).

## 4. Owner-setter narrowing (§7h) — SCOPED DOWN for v1.7.x

The arch review folds "narrow Stage/Representation public setters so code
can't bypass the controller" into v1.7.x-24. **Recommend deferring the
bulk of this to v2.0** and doing only the cheap, safe part now:

- v1.7.x: add `// Controller-funnel: mutate via XController::apply()`
  doc-comments on the broad owner setters, and the CI forbidden-include
  assert (Controllers: no `<QtWidgets>`). Cheap, no API breakage.
- v2.0: actual friendship/private-setter narrowing — it's an API break
  that ripples through legacy dialogs + PyBALL bindings (§7d), too risky
  to bundle with the contract retrofit.

Rationale: narrowing setters while 7 controllers are mid-retrofit
multiplies the blast radius. Get the contract uniform first; lock the
doors in v2.0.

## 6. Sequencing & risk

1. Commit 1 (StageController reference + shared headers + section guards)
   — review carefully; it sets the pattern all others copy.
2. Commits 2–7 — one controller each; after each, the existing controller
   unit tests + the new v1.7.x-25 contract test for that domain must pass.
3. Commit 8 (Clipping/Label scaffold) — trivial.
4. v1.7.x-25 contract tests land **interleaved** (the test for domain N
   lands with commit N), not in a big-bang at the end — that's the only
   real enforcement (§7e).

**Hard gate (unchanged):** none of this starts until the user confirms
the Stream A freeze fixes (v1.7.x-13/14/15) hold in the running build, OR
explicitly authorizes starting without that validation. Piling a 7-
controller retrofit on an unvalidated freeze-fix base is the exact anti-
pattern that caused the 1.6→1.7 regressions.

**Estimated diff:** materially smaller than the arch review's "~600-900
LOC migration" — because the mutation already exists. Realistic: ~80-120
LOC of shared machinery + ~30-50 LOC retrofit per controller (guard +
undo capture + event rename) ≈ 300-450 LOC across 8 commits, each
independently reviewable and revertable.
