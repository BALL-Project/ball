## Gap inventory (with adversarial verdicts)

### KEEP — high value, clear gap

**G1 (→ v1.7.x-16): Model section type-specific controls**
- **Design (04-phase-inspector.md §4.3.1):** Model section's type
  dropdown swaps in type-specific controls via a QStackedWidget:
  Ball & Stick → sphere radius, bond radius, bond-order toggle;
  Cartoon → ribbon width/thickness, helix/sheet shape, smoothing;
  Surface → probe radius, transparency, mesh density.
- **v1.7.0 reality:** `ModelSection` has only generic Model / Drawing /
  Precision / Transparency dropdowns + one slider. NO per-type
  parameter controls. Verified `modelSection.C:81-89`.
- **Verdict: KEEP.** This is the single biggest Inspector shortfall —
  without it the Inspector is NOT a real replacement for
  `ModelSettingsDialog` (the design's stated goal). Reuse path
  confirmed: `modelSettingsDialog.C` already has all the sliders
  (`ball_stick_sphere_radius_slider`, `cartoon_tube_radius_slider`,
  `stick_radius_slider`, `surface_probe_radius_slider`,
  `ribbons_enabled`) + a `createModelProcessor(ModelType)` factory.
  ModelController exposes the params; ModelSection adds the
  QStackedWidget.
- **Effort:** ~300-450 LOC. Medium.

**G2 (→ v1.7.x-17): Coloring section preset swatches + per-method options**
- **Design (§4.3.2):** large preset swatches (Element / Residue / SS /
  Chain / B-factor / Custom); selecting a preset reveals
  preset-specific options (B-factor → min/max range slider + colormap
  dropdown with SVG gradient previews from `gridColorWidget`); a "…"
  advanced sheet for per-residue override.
- **v1.7.0 reality:** `ColoringSection` has only a `Method` dropdown.
  Verified `coloringSection.C:65-67`.
- **Verdict: KEEP** but TRIM the "…" advanced sheet to v1.8 (per-residue
  override is genuinely a power-user surface; the legacy
  ColoringSettingsDialog stays reachable). Ship the preset-specific
  options (B-factor range + colormap) which are the common case.
- **Effort:** ~250-400 LOC. Medium.

**G3 (→ v1.7.x-01/02, ALREADY QUEUED): Clipping + Label sections**
- Design §4 lists ClipSection + LabelSection as core Representation-tab
  sections. v1.7.0 deferred them (Controllers exist as latent stubs,
  no Inspector consumer). Already tracked as v1.7.x-01 + v1.7.x-02.
- **Verdict: KEEP (already queued).** No new entry needed.

### KEEP — medium value, low effort

**G4 (→ v1.7.x-18): Per-section reset-to-defaults**
- **Design (§4.3.3):** every section header gets a `↺` icon →
  confirm → revert just that section.
- **v1.7.0 reality:** reset glyphs exist per-SLIDER (LabeledSlider's
  reset_button_), but NOT per-section. Coarse-grained reset is missing.
- **Verdict: KEEP.** Low effort (~80 LOC — add a reset affordance to
  SectionHeader, wire to controller->revert()). Genuinely useful;
  matches the mockup.

**G5 (→ v1.7.x-19): Selection-tab quick actions (expand-by-residue, save-as)**
- **Design (§Scope):** Selection tab quick actions = invert,
  expand-by-residue, save-as.
- **v1.7.0 reality:** QuickActionsSection has Clear + Invert only.
  Expand-by-residue + save-as missing.
- **Verdict: KEEP expand-by-residue** (cheap, useful — walk selection
  up to residue granularity). **TRIM save-as** to v1.8 (overlaps with
  existing File→Save Structure; low marginal value).
- **Effort:** ~60 LOC for expand-by-residue.

**G6 (→ v1.7.x-20): "What's new" card on version bump**
- **Design (07-phase-onboarding.md §Scope):** WelcomeScreen shows a
  "What's new" card on first launch after a minor version bump.
- **v1.7.0 reality:** infrastructure EXISTS (`WelcomeScreen::showWhatsNew(markdownFile)`
  + a placeholder column at welcomeScreen.C:129) but is not WIRED to
  fire on version-bump detection, and no `whatsnew-1.7.md` content
  ships.
- **Verdict: KEEP.** Low effort (~60 LOC + a markdown file): detect
  version delta via QSettings `[General]/lastSeenVersion`, call
  showWhatsNew when it changes, ship `data/BALLView/help/whatsnew-1.7.md`.

**G7 (→ v1.7.x-21): Text-size preference (Normal / Large / Extra large)**
- **Design (08-phase-a11y.md §Scope):** a "Text size" preference that
  scales the whole UI via `QFont::pointSize` on the app font.
- **v1.7.0 reality:** absent (grep found nothing).
- **Verdict: KEEP.** Accessibility win; low-medium effort (~120 LOC:
  Preferences entry + apply app-font point-size + persist). HiDPI is
  handled, but font-scale for low-vision users is a real a11y gap.

### TRIM — fold into a single polish item

**G8 (→ v1.7.x-22): a11y tooltip + shortcut-append polish**
- **Design (§8):** every tool/icon button has a tooltip with the
  keyboard shortcut appended.
- **v1.7.0 reality:** partial — UFG-20 added some tooltips; not a
  systematic shortcut-append pass.
- **Verdict: KEEP as low-priority polish.** ~80 LOC sweep over toolbar
  actions appending the registered shortcut to each tooltip.

### DEFER to v1.8 — genuinely new feature scope

**G9: "Compare with…" multi-rep editing**
- Design §Scope lists a floating "Compare with…" button for
  multi-representation editing. This is NEW functionality, not
  gap-closure — the Inspector shell never promised it as core, and
  the design itself flags it as advanced.
- **Verdict: DEFER to v1.8.** Out of v1.7.x patch-cycle scope.

**G10: Illustrated empty states**
- Design §4.1.4 wants "illustrated" empty states. v1.7.0 ships
  functional text empty states (`InspectorEmptyState`, UFG-19 fixed).
- **Verdict: SKIP / DEFER.** Cosmetic-only; the text states work.
  Bundle the illustration into a future design-polish pass if ever.

**G11: Markdown HelpViewer replacing demoTutorialDialog**
- Design §7 wants a `QTextBrowser`-based Markdown HelpViewer +
  porting tutorial content from `demoTutorialDialog` to Markdown with
  `balview://` action links.
- **v1.7.0 reality:** the `balview://` URL handler EXISTS
  (`installBallviewUrlHandler_`), WelcomeScreen ships, but the
  demoTutorialDialog → Markdown migration didn't happen.
- **Verdict: DEFER to v1.8.** Larger content-authoring effort; the
  legacy demo/tutorial path still works. Not a v1.7.x quick patch.

## Prioritization rationale

The v1.7.x cycle's lead items remain the **regression fixes**
(v1.7.x-10..15, mostly landed) since those are user-blocking. The
design-gap items rank next because they close the "Inspector isn't a
real dialog replacement" credibility gap that the whole Refresh was
sold on:

1. **v1.7.x-16 + v1.7.x-17** (Model + Coloring depth) — these make the
   Inspector actually replace ModelSettingsDialog + ColoringSettingsDialog,
   which is the headline promise.
2. **v1.7.x-01 + v1.7.x-02** (Clipping + Label sections) — complete the
   Representation tab.
3. **v1.7.x-18 + v1.7.x-19** (per-section reset, expand-by-residue) —
   Inspector polish.
4. **v1.7.x-21** (text size) — accessibility.
5. **v1.7.x-20 + v1.7.x-22** (what's-new, tooltip sweep) — nice-to-have.

Build-infra (v1.7.x-09 PCH) runs in parallel; it's orthogonal.

## Codex review incorporated (2026-05-20)

Codex adversarial review of the above roadmap raised 5 points that
REVISE the prioritization and scope:

1. **16/17 are over-ranked + partly v1.8 scope.** Type-specific
   controls, swatches, colormap previews, B-factor min/max are
   product EXPANSION, not patch-cycle stabilization. v1.7.x is
   meant to repair confidence after 6 RCs — don't smuggle v1.8
   feature credibility into the patch train.
   → **Resolution:** take only a THIN, lowest-risk slice of 16/17 in
   v1.7.x (the most-common model types + basic per-method coloring).
   Defer the rich swatches / colormap previews / B-factor range /
   all-model-types breadth to v1.8.

2. **Hidden coupling (16/17/18/01/02 share the UI↔controller↔processor↔
   render contract).** Don't bolt controls onto each section
   independently — that duplicates conversion / default / validation /
   commit-revert logic.
   → **Resolution:** establish the reset/default + commit-revert
   contract FIRST (v1.7.x-18), then build 16/17 against it.

3. **01/02 should outrank 16/17** — they complete already-promised
   Phase-4 core (Clipping + Label sections) and reduce architectural
   inconsistency in the Representation tab. Lower risk (follow the
   established section pattern).

4. **Sequencing: reset (18) BEFORE 16/17.** Otherwise every new
   control invents its own default behavior and retrofitting reset
   exposes inconsistent defaults.

5. **Regression risk from reusing modelSettingsDialog paths is HIGH.**
   Those paths may assume modal Apply/OK lifecycle or full-scene
   rebuilds — exactly the O(scene) redraw-storm class just fixed in
   v1.7.x-13/14. **Mandatory mitigations for 16/17:** 100ms debounce
   (already the section pattern), skip-no-op commits, soft refresh
   (`rep->update(false)`) not full rebuild where possible, + smoke
   coverage for inspector edits while selection changes.

19 (expand-by-residue) also touches the just-stabilized selection
cascade — **deferred to v1.8** per codex (changes selection
semantics; risk outweighs the small value). 21 (text size) kept but
flagged: global `qApp->setFont` can disrupt dense Qt layouts — test
all dialogs.

### REVISED implementation order (codex-incorporated)

1. **Stream A regression fixes** — validate with user (13/14/15
   committed, 11 pending re-test). DON'T start depth work until the
   selection cascade is confirmed stable.
2. **v1.7.x-01 + v1.7.x-02** — Clipping + Label sections. Complete
   promised Phase-4 core via the established section+controller
   pattern. Lower risk than 16/17. Architectural consistency.
3. **v1.7.x-18** — per-section reset/default + commit-revert CONTRACT.
   Foundational prerequisite for 16/17. Low risk.
4. **v1.7.x-16 (THIN slice)** — Model type-specific controls for the
   common types only (Ball & Stick, Cartoon, Surface), built on the
   18 contract, with mandatory debounce + skip-noop + soft-refresh
   mitigations + smoke coverage.
5. **v1.7.x-17 (THIN slice)** — basic per-method coloring options.
   Defer B-factor colormap previews + per-residue sheet to v1.8.
6. **v1.7.x-21** — text-size a11y (test dense layouts).
7. **v1.7.x-20 + v1.7.x-22** — what's-new card, tooltip sweep.
8. **v1.7.x-09 PCH** — parallel/orthogonal.

Deferred to v1.8 (now also includes, per codex): the RICH parts of
16/17 (full swatch grid, colormap previews, B-factor range, breadth
across all model types), and v1.7.x-19 (expand-by-residue).
