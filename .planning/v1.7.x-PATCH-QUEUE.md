## Why this queue exists

v1.7.0 ships the BALLView Refresh + the Unified Inspector + the
WelcomeScreen-as-startup-central-widget pattern + the Wave 4 controller
cut-overs. Several items were intentionally deferred during the RC
cycle to keep v1.7.0 release-shaped:

- They have no functional impact in v1.7 (e.g. Controllers without an
  Inspector consumer)
- They are UX polish that the user did not flag during RC validation
- They depend on infrastructure that lands later in v1.7.x (e.g. the
  Stereo `enabled_` checkbox awaits Renderer/RenderSurface mode
  switching from SEED-001 step 5)

When v1.7.0 final tag ships and the master fast-forward completes, this
queue becomes the source of truth for v1.7.x patch-cycle planning. New
gsd-phase calls can pull items off this list and slot them into
`ROADMAP.md` as v1.7.1, v1.7.2, … phases.

### v1.7.x-09 — REVISED scope

**Severity:** ⚠ infrastructure / developer-experience.
**Source:** User direction 2026-05-19, after observing v1.7 RC cycle
release.yml wall time grew from v1.6's ~30 min CI to ~90 min release
(Windows-x64 Build alone takes ~52 min, plus ~20 min for the
test-suite build).
**Lead phase target:** v1.7.1 (this should be the FIRST v1.7.x phase
to land — every subsequent v1.7.x patch benefits from the faster
build).
**Two-part scope:**

1. **No debug builds — only Release.**
   - Currently CMake / release.yml build with `RelWithDebInfo` (Release
     optimization but full DWARF / PDB debug info embedded). The debug
     info doubles compile time on Windows and bloats artifacts (DMG +
     MSI + AppImage).
   - Switch to `Release` (no embedded debug syms; -O2 / `/O2`).
   - Crash-report symbolication still works via separate symbol
     artifacts:
     - macOS: `dsymutil BALLView.app/Contents/MacOS/BALLView -o
       BALLView.app.dSYM` published as a release artifact (sibling
       to the DMG).
     - Windows: `.pdb` published as a sibling to the NSIS installer +
       portable zip.
     - Linux: `objcopy --only-keep-debug` + `--add-gnu-debuglink`
       split, published as `BALLView-v1.7.1-linux-*.debug.tar.gz`.
   - CMake: switch the release-build CMake preset / CI matrix from
     `RelWithDebInfo` → `Release` + post-build `dsymutil` / `objcopy`
     /  PDB-extract step. Release.yml uploads the symbol artifacts
     alongside the binary artifacts.
   - **Expected saving:** ~20-30% compile time on each platform.
   - **Risk:** crash reports lose inline symbol resolution unless
     dSYM / PDB is available at symbolication time. Mitigated by
     publishing the symbols as release artifacts. Users running into
     a crash forward both the `.ips` + the matching symbols (or we
     publish to a symbol server later).

2. **PCH throughout BALL + VIEW.**
   - Phase 999.16 ("Build acceleration — precompiled headers for BALL +
     VIEW") was originally a v1.6.2 backlog item; never landed.
     Status quo: each translation unit re-parses the Qt + Boost + STL
     headers from scratch — collectively the heaviest part of every
     `.C` file's compile time.
   - CMake `target_precompile_headers(BALL PRIVATE …)` +
     `target_precompile_headers(VIEW PRIVATE …)` with a stable set of
     "always-included" headers:
     - BALL: `<QtCore/QObject>`, `<vector>`, `<map>`, `<string>`,
       `<boost/shared_ptr.hpp>` …
     - VIEW: BALL's PCH + `<QtWidgets/QWidget>`, `<QtGui/QPainter>`,
       `<QtOpenGL/...>` …
   - Caveats: PCH is per-target, not per-TU. ABI must be stable across
     the PCH set — anything that varies between compilation units
     (e.g., per-TU `BALL_VIEW_BUILD_DLL` define) must stay OUT of the
     PCH.
   - Test-suite build also gets PCH; this is the second-biggest win
     (test-build is ~half the size of the main build).
   - **Expected saving:** 30-50% compile time on each platform.
   - **Combined with #1:** total release.yml wall time should drop
     from ~90 min → ~35-45 min.

**Files in scope:**
- `CMakeLists.txt` (top-level) — Release default + symbol-extraction
  POST_BUILD steps
- `source/CMakeLists.txt` + per-component `CMakeLists.txt` —
  `target_precompile_headers` calls
- `.github/workflows/release.yml` — symbol-artifact upload + symbol
  release-asset wiring
- `.github/workflows/ci.yml` — same matrix swap (CI keeps test build
  but at Release config)
- New: `cmake/PCHSet.cmake` — centralised PCH header lists per target

**Validation gates:**
- Pre-PCH baseline measurement: `ninja_log` per-TU timings published
  as artifact (see Phase 999.19 — already in place).
- Post-PCH measurement: same artifact; expect top-20 slowest TUs to
  shed Qt-include time roughly uniformly.
- ABI / SONAME guard: BALL + VIEW must still link the same downstream
  callers (BALLView app, test suite) without rebuild. PCH is
  internal-only.

**Dependencies:**
- None blocking. Can land in parallel with v1.7.x-01..08.

**Adjacent quick wins (bundle into the same phase if cheap):**
- Drop the duplicate test-build + test-run from `release.yml`
  ("Phase 9 gatekeeper, blocking" jobs) — CI on the same commit
  already validates tests. Release.yml duplicates the work. Saves
  ~25 min on Windows critical path alone.
- Strip QtWebEngine from macOS bundle via
  `macdeployqt -no-plugins=quick,webengine` — QtWebEngineCore is
  134 MB of the current 159 MB DMG and is dead code in v1.7
  (HTMLPage / HTMLView are not wired in the post-Wave 4 UI).
- Better Windows ccache hit rate: dump `ccache -s` post-compile to
  baseline the hit ratio; investigate sloppiness flags / BASEDIR
  config. May be the single highest-leverage tweak on Windows alone.

### v1.7.x-13 — Hang fix: UFG-27 sync triggered full-scene redraw per click ⚠ CRITICAL

**Severity:** 🚨🚨 freeze — GUI thread saturated.
**Reported:** 2026-05-19, after v1.7.0 ship.
**Status:** ✅ FIXED commit `68ceb11df2`.
**Symptom:** User reported "trying to select or to optimize structure
make the whole app freeze without crashing."
**Root cause:** UFG-27 sync block called `mc->clearSelection()` on
every tree-row click. clearSelection walks ALL composites + emits
`redrawAllRepresentations(true)` which posts
`SceneMessage::REBUILD_DISPLAY_LISTS` — a FULL rebuild of every
representation's GL display list. For 1ubq + hydrogens (1240+
atoms) each click triggered a multi-second rebuild on the GUI
thread. UI froze.
**Fix:** replace `mc->clearSelection() + newSelection_(selected_, true)`
with a diff-based update:
```
old_sel = mc->getSelection()  (current BALL state)
new_sel = selected_           (target cursor state)
to_deselect = old_sel - new_sel
to_select   = new_sel - old_sel
newSelection_(to_deselect, false)
newSelection_(to_select,   true)
```
`newSelection_` only calls `updateRepresentationsOf(root, false)`
for touched composites — `false` = soft refresh, not full rebuild.
Per-click cost drops from O(scene) to O(|to_deselect| + |to_select|),
typically 1-2 composites.

### v1.7.x-14 — Hang fix: setSelection_ paint storm

**Severity:** 🚨 performance regression compounding v1.7.x-13.
**Reported:** 2026-05-19, adversarial review of v1.7.x-13.
**Status:** ✅ FIXED commit `f6d0d423da`.
**Root cause:** `MolecularControl::setSelection_` (UFG-31 two-way
sync) iterated EVERY tree item and called `setData` + `notifyDataChanged`
unconditionally. For 1ubq + hydrogens that's ~5000 paint events
scheduled per message, with setSelection_ running twice per
UFG-27 sync block = ~10000 paint events per click.
**Fix:** compare stored AccessibleDescriptionRole against the
wanted value; only call setData + notifyDataChanged when it
actually changed. O(N) iteration sweep is unavoidable (we must
visit every item to find which need updates), but the
dataChanged signal emission is now O(diff).

### v1.7.x-15 — Headless smoke hang: migration modal blocks main thread

**Severity:** 🚨 release-pipeline gate — could block v1.7.1 packaging.
**Reported:** 2026-05-19, adversarial review.
**Status:** ✅ FIXED commit `dbe1ab2020`.
**Symptom:** local `render-smoke-check.sh` hung at "Enabling Vertex
Buffer" until the 60s watchdog killed BALLView. The headless
`-export-png` path never reached the PDB-load step.
**Root cause:** Phase 999.44 Plan 02 added a one-shot first-run
`QMessageBox::information` migration notice. The QMessageBox uses
`QDialog::exec()` which runs a NESTED Qt event loop — it blocks
the calling thread until the user clicks OK. In headless smoke
runs there's no user; the binary hangs forever inside the modal.
**Why v1.7.0 release.yml smoke didn't catch this:** the CI runner's
QSettings was clean across runs, but the shown-flag check happens
SYNCHRONOUSLY in `Mainframe::show()`. CI runners may have set the
flag via an earlier interactive test, but local + fresh CI runs
both should have hit this hang. Investigation incomplete — for
now the env-var bypass is the surgical fix.
**Fix:** when `BALLVIEW_NO_WELCOME=1` is set (the same env var the
smoke script already exports), skip the modal AND mark the
QSettings shown-flag true so subsequent headless runs don't
re-trigger. Matches headless-runner intent.
**Verification:** local smoke now produces 2051-byte PNG + exit 0
+ "BALLVIEW_SMOKE_EXPORT path=… ok=1".

### v1.7.x-24 — Complete Controller cut-over to command-shaped apply() ⭐ FOUNDATIONAL

**Severity:** 🚨 architecture — resolves the regression class.
**Source:** arch review §2c, §7a; PATTERN.md extraction status.
**Gap:** only StageController (+ the rc2-fixed Model/Coloring/Material)
is fully mutating. Camera / Light / Stereo / Clipping / Label remain
READ-ONLY MIRRORS → the Inspector displays but legacy dialogs own

**Scope:**

   validate preconditions → begin re-entrancy guard → mutate the
   single owner → emit ONE typed domain event → request soft render
   invalidation → capture a reversible before/after intent payload →
   end guard. Ordering is contractual.

   (subsumes v1.7.x-01 Clipping + v1.7.x-02 Label).
3. Narrow owner setters (`Stage`, `Representation`) — Controller-only
   friendship / private setters where feasible, so bypass is awkward
   by API (arch review §7h).
**Files:** all 9 `controllers/*.{h,C}`, `stage.h`, `representation.h`,
new `controllers/controllerContract.h` (the guard + payload helper).
**Effort:** ~600-900 LOC. Large but foundational.
**Hard sequencing:** before v1.7.x-16/17.
