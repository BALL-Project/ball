**Status:** OPEN — accepts items deferred during v1.7.0 RC cycle.
**Captured:** 2026-05-18 (immediately after v1.7.0-rc4 packaging).
**Owner:** orchestrator + user.
**Consumes:** `.planning/v1.7-USER-FEEDBACK-GATE.md` (Deferred lines + Latent-stub deferrals table).

---

## Why this queue exists

v1.7.0 ships the BALLView Refresh + the Unified Inspector + the
WelcomeScreen-as-startup-central-widget pattern + the Wave 4 controller
cut-overs. Several items were intentionally deferred during the RC
cycle to keep v1.7.0 release-shaped:

- They have no functional impact in v1.7 (e.g. Controllers without an
  Inspector consumer)
- They are UX polish that the user did not flag during RC validation
- They depend on infrastructure that lands later in v1.7.x (e.g. the
  Stereo `enabled_` checkbox awaits Renderer/RenderSurface mode
  switching from SEED-001 step 5)

When v1.7.0 final tag ships and the master fast-forward completes, this
queue becomes the source of truth for v1.7.x patch-cycle planning. New
gsd-phase calls can pull items off this list and slot them into
`ROADMAP.md` as v1.7.1, v1.7.2, … phases.

### v1.7.x-03 — `StereoSection` enabled checkbox re-enable

**Severity:** ⚠ UX polish + functional (currently disabled +
tooltipped per UFG-11-followup, commit `dccee36754`).
**Source:** `.planning/v1.7-USER-FEEDBACK-GATE.md:183`.
**Why it was deferred:** `StereoController::apply()` deliberately
ignores the `enabled_` toggle because the renderer-mode switch for
stereo lives at the Renderer/RenderSurface boundary (SEED-001 step 5
— `.planning/RENDERER-INTERFACE-BOUNDARY.md`). The UX trap was patched
in rc3 by greying the checkbox + a tooltip pointing at the legacy
`Display › Stereo` menu, which still owns the actual mode switch.
**Required scope:**
1. Wire `StereoController::apply()` through whatever stereo-mode API
   the Renderer/RenderSurface boundary exposes once SEED-001 step 5
   lands.
2. Remove the `setEnabled(false)` + tooltip from `stereoSection.C:39`.
3. Verify the legacy `Display › Stereo` menu and the Inspector
   StereoSection now produce identical results.
**Depends on:** SEED-001 step 5 (Renderer interface boundary for
stereo).

### v1.7.x-04 — GeometricControl + DatasetControl analogous
selection-highlight redesign

**Severity:** ⚠ DESIGN-CONSISTENCY (only re-file if user surfaces it).
**Source:** `.planning/v1.7-USER-FEEDBACK-GATE.md:333`, `:348`.
**Why it was deferred:** UFG-07 redesigned `MolecularControl` (left-rail

UFG-07's redesign does NOT apply automatically.
**Action:** Wait for user re-file. If filed, mirror the UFG-07 commit
shape (`c1e4b6fbda`) onto the two sister trees, with appropriate
semantic adaptation for visibility (Geometries) and informational
metadata (Datasets) columns.

### v1.7.x-05 — Optional `theme-neutral-macos.qss` overlay

**Severity:** ⚠ polish (no current visual regression).
**Source:** `.planning/v1.7-USER-FEEDBACK-GATE.md:87`.
**Why it was deferred:** UFG-02 fix scoped bare-selector QSS rules to
`QMainWindow ...` descendants so dialogs keep QMacStyle on macOS. The
fully-correct solution would be a platform-specific overlay file
(`theme-neutral-macos.qss`) loaded under `Q_OS_MACOS` for rules that DO
want to style certain widgets on macOS. Overkill for rc2; defer until
a concrete styling request lands that the scoped rules cannot
express.
**Trigger condition:** A new theme-styling request that the current
`QMainWindow ...` scoping cannot accommodate.

## What does NOT go on this queue

- **New feature work** — those go through `gsd-new-milestone` for
  v1.8 (BALL2.x handover is the natural successor; see
  `.planning/BALL2.x-HANDOVER.md`).
- **Bug fixes surfaced post-v1.7.0** — those open as new UFG-NN
  entries in a fresh `.planning/v1.7.x-USER-FEEDBACK-GATE.md` when
  they arrive. Don't pollute the deferral queue.
- **Items already FIXED in any v1.7.0-rcN** — UFG-01 through UFG-19
  are FIXED for rc4 and are not deferred. Source of truth is the
  `Status:` line in the gate doc.

## Workflow when v1.7.0 final tag ships

1. User signals "ship v1.7.0" → final tag fires release.yml.
2. Master fast-forward + branch reconciliation.
3. Open the v1.7.x patch cycle by appending Phase rows to
   `ROADMAP.md` for the items above, in user-determined priority.
4. Each Phase row uses `gsd-plan-phase` against the corresponding item
   entry here.
5. Mark items DONE in this file as v1.7.x patches ship.
