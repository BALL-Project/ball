#### Group 2 — Qt 6 `QMessageBox` constructor deprecation (7 sites)

The `QMessageBox::question(...)`, `QMessageBox::critical(...)`, and `QMessageBox(parent, title, msg, icon)` constructor overloads with implicit-int button defaults are deprecated in Qt 6. Use the `StandardButtons` overload everywhere.

| File:Line | API |
|---|---|
| `source/VIEW/DIALOGS/dockDialog.C:732` | `QMessageBox(...)` ctor |
| `source/VIEW/DIALOGS/dockDialog.C:744` | `QMessageBox(...)` ctor |
| `source/VIEW/DIALOGS/dockResultDialog.C:397` | `QMessageBox(...)` ctor |
| `source/VIEW/DIALOGS/dockResultDialog.C:449` | `QMessageBox(...)` ctor |
| `source/VIEW/KERNEL/mainControl.C:2138` | `QMessageBox::question` |
| `source/VIEW/WIDGETS/dockingController.C:110` | `QMessageBox::question` |
| `source/APPLICATIONS/BALLVIEW/demoTutorialDialog.C:586` | `QMessageBox::critical` |

Note: this is the **constructor/static-method form** — different overload than the one fixed in v1.6.2 Phase 999.27 (`modifyRepresentationDialog.C:106`, which was the 6-int legacy overload). Census in v1.6.2 explicitly noted dockDialog.C / dockResultDialog.C as "different signature, separately tracked"; these are now scheduled.

#### Group 3 — Qt 6 `QMouseEvent::x()/y()` local-position deprecation (6 sites)

Local-position `x()`/`y()` getters on `QMouseEvent` are deprecated in Qt 6; use `position().x()` and `position().y()` (returns `QPointF`; cast to `int` if needed). Sibling of v1.6.2 Stream B B7 fix (which migrated `globalPos()` → `globalPosition().toPoint()` but didn't touch local pos).

| File:Line | Migration |
|---|---|
| `source/VIEW/KERNEL/MODES/editMode.C:279` | `evt->x()` → `evt->position().x()` (or `static_cast<int>(...)`) |
| `source/VIEW/KERNEL/MODES/editMode.C:280` | `evt->y()` → `evt->position().y()` |
| `source/VIEW/KERNEL/MODES/editMode.C:364` (x + y on same line) | both |
| `source/VIEW/KERNEL/MODES/editMode.C:456` (x + y on same line) | both |
