# K0.6 — Persistence v2 (JSON): sub-phase breakdown

**Status:** PLANNING. **Authored:** 2026-05-18.
**Pivot from spec:** [STORE-FORMAT-SPEC.md](STORE-FORMAT-SPEC.md) (630
lines) originally specified a custom binary format. After the K0.5
close, maintainer feedback (2026-05-18 chat) re-scoped the goal to
**JSON persistence** — drop the binary route, replace the v1.x
`TextPersistenceManager` text format with structured JSON via
nlohmann::json (header-only, MIT). Rationale, summarised:

- Typical BALL workloads are ≤10k atoms; custom binary's 3-4 week
  budget isn't justified by I/O profiling evidence.
- JSON gives debuggability (greppable / jq-able), zero
  endianness/alignment work, easy schema evolution.
- nlohmann::json ships as one header — no new system dep, no
  FetchContent, no Boost.JSON variant to argue over.
- Binary fast path can be added later if K0.7 perf phase finds it
  matters.

**The existing 800-line binary skeleton** (`include/BALL/KERNEL/storeFormat.h`
+ `source/KERNEL/storeFormat.C` + `test/StoreFormat_test.C`) is
**unchanged** by K0.6.0; K0.6.1 either deletes it outright or
relegates it to a clearly-labelled fast-path follow-on. Decision in
K0.6.1 once we see how much the JSON path actually costs.

---

## Library choice

**nlohmann::json** (vendored as a single header at
`include/BALL/EXTERNAL/nlohmann_json.hpp`). Reasons:

- single-include, no link
- MIT, ~25k lines, well-maintained, ubiquitous
- supports operator[] dump/load + binary CBOR/MessagePack escape
  hatch if K0.7 wants compactness without the full custom format
- bit-exact float round-tripping via `.dump(17)` (decimal) or by
  emitting positions as a hex-IEEE-754 string column for trajectory
  use cases (see K0.6.3 invariants)

K0.6.0 vendors the header. If a maintainer prefers a system dep
(`brew install nlohmann-json`) instead, swap the include path; the
single-header form means a near-zero-cost switch.

## Decision log

- **2026-05-18:** Original binary spec deprecated in favour of JSON;
  this doc supersedes [STORE-FORMAT-SPEC.md](STORE-FORMAT-SPEC.md)
  §3-§6 (wire format, chunk IDs, CRC layout). STORE-FORMAT-SPEC.md
  stays in the repo as the rejected-alternative reference; the
  binary skeleton stays for now and is reassessed in K0.6.1.
- **Vendored single-header nlohmann::json**: lowers dep surface;
  swap to system dep is a one-line cmake change.
- **Per-column SoA JSON layout** (positions: [[x,y,z], …], names:
  [...]) rather than per-atom records: 3-5× smaller JSON for the
  typical scientific workload; matches the store's internal layout;
  trivially deserialises into the column vectors.
