## 3. Remaining KERNEL phases (Track A)

### K0.3c — Graph-mutation drift fix (~1-2 weeks parallel, ~3-4 weeks sequential)

**Inserted post-Codex Round 2** (see `K0-CODEX-REVIEW-ROUND2.md`).
Closes the BLOCKER + HIGH findings on bond destruction, orphan-store
reclamation, mutable-getter drift, swap connectivity, bond metadata
mirroring, and persistence bond population.

**K0.3c.1** — `MoleculeStore::release_atom` + tombstones; `Atom::~Atom`
clears back_ptr + releases slot. Closes BLOCKER-2 (orphan leak).

**K0.3c.2** — `MoleculeStore::remove_bond` + CSR ignores tombstones;
wired into `Bond::~Bond` / `clear` / `destroy` / `Atom::destroyBond*`.
Closes BLOCKER-1 (bond shadow append-only).

**K0.3c.3** — Bond store-awareness: `Bond` holds `bond_record_idx_`;
`setOrder` / `setType` / swap mirror. Closes HIGH-5.

**K0.3c.4** — `Atom::swap` mirrors store CSR rows (swap incident-bond
adjacency for both atoms). Closes HIGH-4.

**K0.3c.5** — `Atom::persistentRead` populates store bonds after the
v1.x `bond_[]` pointer fixup. Closes MEDIUM-8.

**K0.3c.6** — Mutable-reference gap test: either ship a `PositionRef`
proxy or document the gap (v1-only writes for `Vector3& = ...` until
K0.3b.LATER's getter flip). Closes HIGH-3 + HIGH-6.

**K0.3c parallelisation:** K0.3c.1 + K0.3c.2 share MoleculeStore surface
and serialise. K0.3c.3/4/5/6 can run in parallel after both prerequisites
land. Time: 1-2 weeks with 2 FTE; 3-4 weeks at 1 FTE.

**Gate:** all 36 baseline tests still green; 6 new K0.3c tests green;
orphan-store leak < 5 atoms after running full sweep.

### K0.4 — `System::adopt(Atom&)` + per-System MoleculeStore (~3-4 weeks)

**Goal:** Atoms inserted into a System migrate out of the process-global
orphan store into the System's own per-instance MoleculeStore (per D5).
Slot data (position, charge, velocity, force, name, type_name, element,
radius, type, formal_charge) + connected bonds copy to the new store.
Atom's `store_` / `store_idx_` / `store_generation_` update atomically.

**Why this is gating:** K0.3b.LATER getter flips cannot land safely until
atoms stop accumulating in the unbounded orphan store. With per-System
stores, capacity is bounded by System size; references remain stable
across the System's lifecycle.

**Dependencies upstream:** none past K0.3b.8 (already landed).

**Deliverables:**
- `System` holds `std::unique_ptr<MoleculeStore>` member
- `System::adopt(Atom&)` — single-atom migration
- `AtomContainer::insert(Atom&)` / `prepend` / `append` — auto-adopt via root-System lookup
- Migration semantics: copy columns + bonds; clear orphan slot (mark as
  freed; reclamation TBD in K0.4b)
- `MoleculeStore::reclaim(Index)` — mark slot as freed; subsequent
  `allocate_atom()` may reuse (or compact in a sweep)
- Cross-System bond fix-up: if a bond connects atoms in different
  Systems, what happens? **Decision (matches v1.x semantics):** bonds
  are intra-System only; cross-System bonds aren't allowed at the API
  level (existing tests don't exercise it).
- New tests: `SystemAdopt_test.C` exercises (a) single Atom insert →
  adopted, (b) bulk insert via AtomContainer → all adopted, (c)
  remove from System → no-op on store (slot stays; reclamation later),
  (d) cross-System Atom move (System A's atom inserted into System B
  → re-adoption from A to B)

**Gate:** 36-test sweep + new `SystemAdopt_test` green; orphan store
size after running full test suite is < 5 atoms (i.e. ≥99% of atoms
were adopted into a System).

### K0.3b.LATER — Per-field getter flip + v1.x field deletion (~4-6 weeks, 11 atomic per-field commits)

**Goal:** Now that atoms live in stable per-System stores, flip each
Atom getter to read from the store. Delete the v1.x field. Per Codex
Path-2 amendment: **no flip until all writers for that field are
migrated** — already done in K0.3b.2a-7.

**Per-field commit shape (~1 commit per field):**
1. `getPosition()` → `return store_->position(store_idx_);`
2. Delete `Vector3 position_;` from `atom.h`
3. Delete `position_` from all ctor init lists
4. Delete all `position_ = ...` assignments in `atom.C` (already
   redundant after store-side mirrors)
5. Build + run 36-test sweep + `MoleculeStore_test`
6. Commit

Repeat for: charge, velocity, force, name, type_name, element,
radius, type, formal_charge.

**Bond field deletion (K0.3b.LATER.bonds):** more involved because
`bond_[12]` is exposed through `getBond(i)` which returns `Bond*`. Bond
itself needs to migrate (K0.3b.9 prerequisite).

**Memory budget check at the end:** sizeof(Atom) should drop from
~488 B back to ~60-70 B (handle + Composite + PropertyManager base
subobjects only; PropertyManager + Selectable not yet stubbed).

**Gate:** all 36 tests green at each per-field commit. Memory budget
checked at the end.

### K0.3b.9 — Bond handle migration (~2-3 weeks)

**Goal:** Bond becomes a handle holding `(MoleculeStore* store_,
uint32_t bond_record_idx_, uint64_t store_generation_)` plus its
inherited Composite base. `Bond::first_` / `Bond::second_` payload
moves into store's `BondRecord.a / .b`.

**Dependencies:** K0.4 (per-System store) + K0.3b.LATER (Atom payload
fully store-backed).

**Gate:** Bond_test green + AtomBondIteratorTraits_test green.

### K0.5 — Compiled selection (Expression + Selector rewrite, ~3-4 weeks)

**Goal:** Per D11 — variant-based cached AST; Selector_test ≥10×

**Dependencies:** K0.3b.LATER complete (selection bitmap lives in

**Deliverables:**

**Gate:** Expression*/Selector*/StandardPredicates_test1..4 +

## 4. Module re-enablement (Track B)

**Full plan:** see `MODULE-REENABLE-PLAN.md` for the dependency matrix
and per-phase test re-enable list.

**Summary:**

| Phase | Modules | Parallel? | Why |
|---|---|---|---|
| B0 | PLUGIN (3 sources, 0 deps) | — | Validate the BALL_CORE_ONLY toggle works module-by-module |
| B1 | FORMAT (40 sources) + STRUCTURE (77 sources) | **YES** | Both depend only on core; FORMAT unblocks 9 modules, STRUCTURE 10 |
| B2 | XRAY + NMR + ENERGY | **YES (3-way)** | All small, independent; each depends only on FORMAT/STRUCTURE |
| B3 | MOLMEC (57 sources) | — | Force-field hub; depends on STRUCTURE |
| B4 | QSAR + SOLVATION + SCORING | partial (QSAR ∥ SOLVATION → SCORING) | SCORING depends on QSAR+SOLVATION+MOLMEC |
| B5 | DOCKING + PYTHON | — | DOCKING needs the rest; PYTHON wraps everything |

**Per-module recipe (5 steps):**
1. Move module's includes out of `IF(NOT BALL_CORE_ONLY)` block in
   `cmake/BALLIncludes.cmake`
2. Build module: `ninja BALL`. Expect compile errors from store-API
   mismatches (especially after K0.3b.LATER deletes v1.x fields)
3. Re-enable module's test group: edit `test/CMakeLists.txt`
4. Build tests + run; fix until green
5. Single commit per module enable

**Tri-OS validation after every B-phase completes.**
