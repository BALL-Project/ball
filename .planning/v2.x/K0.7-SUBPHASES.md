## Decision log

- **K0.5.6's benchmark** used 50k atoms with a soft ≥5× test gate (median observed: 50.7×); the gap was to absorb CI noise. K0.7.2 tightens to ≥10× — current 50.7× has 5× headroom so the tighten is safe.
- D13 budget (160 B/atom): K0 store columns = ~84 B of SoA data per atom (3 Vector3 + 2 float + 2 short + uint8 + uint8 + 2 uint32 + 2 String + StableId + Atom* + uint8 ≈ 36+8+4+2+1+1+8+~48+8+8+1 = ~125 B from the columns alone, then string pool overhead). Per-Atom handle adds another ~32 B + Composite + PropertyManager bases. Total estimate: ~160-200 B/atom — borderline; K0.7.3 measurement decides if D2/D3/D4 thin-stub overhead pushes us over.
- D14 budget (≤2× v1.x iteration): current bench shows fast-path leaf evaluation ~50× faster than v1.x; non-bench iteration (e.g. for atom in molecule) wasn't measured. K0.7.3's instrumented run can include an iteration count.
