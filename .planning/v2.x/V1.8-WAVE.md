# v1.8 BALLView Refresh — the flag-flip release

**Status:** Forward-looking plan. v1.8 is **not** a v2.x phase — it's the
milestone between v1.7 (which ships the Refresh foundation behind
`BALL_UI_V2=OFF`) and v2.0 (which ships the substrate rewrite). v1.8 is
where `BALL_UI_V2` defaults ON and the heavier UI phases land.

**Authored:** 2026-05-17. Live source for the per-phase scopes is
`/Users/kohlbach/Claude/BALL/ball/.planning/ROADMAP.md` §Phases 999.44-999.48.

## Why v1.8 is distinct from v2.x

The BALLView Refresh (SEED-001) was split when promoted on 2026-05-17:

- **v1.7 tail subset (Wave 4):** Phases 999.40-999.43 — the foundation +
  maintainer-decision-independent subset. All behind `BALL_UI_V2=OFF`.
  Lands inline during v1.7 packaging / auto-update lead time.
- **v1.8 remainder:** Phases 999.44-999.48 — the five architecturally
  heavier UI phases. v1.8 is the **dedicated UI marketing release** where
  `BALL_UI_V2` flips to default ON (in Phase 999.48 closing).

v1.8 ships before v2.0 substrate rewrite kicks off. The compatibility
chain is: v1.7 (modernization) → v1.8 (UI refresh, flag flip) → v1.9
(removes Classic 5-dock workspace per maintainer-Q2) → v2.0 (KERNEL +
substrate).

**Goal:** Collapse the modal-dialog soup (Display, Model, Material, Light,
Stage, Stereo, Clipping, Coloring, Label, Modify Representation — 10+
dialogs) into a single **right-rail Inspector dock** with collapsible
sections, live preview, and tabs organized by subject (Selection,
Representation, Scene, Stage).

**Why v1.8 not v1.7-tail:** Biggest single architectural piece in the
entire Refresh. Gates on maintainer-Q2 (workspace classic-vs-new).
Deserves its own marketing release.

**Source:** `/Users/kohlbach/Claude/BALL/Claude Design Handover/revitalization/04-phase-inspector.md`.

**Depends on:** 999.40 (theme foundation), 999.41 (SVG icons), 999.42
(palette removal), 999.43 (simple-dialog patterns), maintainer-Q2 (RESOLVED).

**Estimated effort:** ~3-4 weeks.

**Promotion gate:** v1.7 closed AND maintainer-Q2 answered (BOTH satisfied).

### 999.46 — Menus + command palette (Handover Phase 6)

**Goal:** Re-author the top menu bar around **tasks** rather than C++
namespaces. Introduce `Cmd/Ctrl+K` **command palette** exposing every
action by name (modern app standard).

**Why v1.8:** Menu reorg touches every `.ui` menu file + invalidates
~40% of `BALLView-de_DE.ts` translations.

**Maintainer-Q1 + Q4 resolved 2026-05-17:**
- Q1 = "Keep inline menubar" → SKIP `QAction::setMenuRole` plumbing.
  Menu structure stays cross-platform-consistent (inline per-window),
  no macOS-native global-menubar work.
- Q4 = "Accept; community round during v1.8 cycle" → v1.8 ships English
  + best-effort de_DE; community translators called for in v1.8 RC notes;
  v1.8.x point release picks up completed translations. NOT a v1.8
  ship-date blocker.

**Source:** `/Users/kohlbach/Claude/BALL/Claude Design Handover/revitalization/06-phase-menus.md`.

**Depends on:** 999.44 + 999.45 (new layout context). Maintainer gates RESOLVED.

**Estimated effort:** ~2 weeks (reduced from 2-3 weeks because no
macOS-native menu role plumbing per Q1).

## Carry-over commitments

### "Retire Classic 5-dock workspace after one release" (Q2)

- **v1.8** ships **both** layouts. Workspace picker exposes Classic +
  Modern; Modern is the default for first-run users; existing users keep
  whatever layout they had. Classic carries a sunset notice in the
  picker UI ("Classic layout will be removed in v1.9").
- **v1.9** deletes Classic. Users who hadn't switched get migrated to
  Modern on upgrade with a one-time "Classic was removed; switch back?
  No — v1.9 doesn't have Classic" notice.
- This is a v1.9 milestone item, **NOT v2.0**. v2.0 should not inherit
  any Classic-layout-coexistence code.

### Community translation round (Q4)

- **v1.8 RC notes** call for community translators. Outreach via project
  README + GitHub Discussions + downstream packagers (conda-forge,
  Homebrew tap maintainers).
- **v1.8 ships** with English (canonical) + best-effort de_DE (carrying
  ~40% orphans from the menu reorg + 0% coverage of new
  command-palette strings).
- **v1.8.x point release(s)** pick up completed community translations as
  they land. Each new language added is a patch-release event with the
  contributor credited in RELEASE-NOTES.
- Not a v1.8 ship-date blocker — the call-for-translators is the v1.8 act;
  the translations themselves arrive in v1.8.x.

### `BALL_UI_V2=ON` default flip (Phase 999.48 closing)

- v1.7 ships with `BALL_UI_V2=OFF`. Foundation (999.40-999.43) is dormant
  by default; opt-in via `-DBALL_UI_V2=ON`.
- **v1.8 Phase 999.48 closing** flips the CMake default to `ON`. v1.8 is
  the first release where the new UI is the default user experience.
- v2.x assumes `BALL_UI_V2=ON` is the only mode. The `OFF` codepath can
  be deleted in v2.0 as part of Phase 999.12 (bulk deprecated-code
  removal) — flag the v1.7/v1.8 wiring as `BALL_DEPRECATED` once
  flipped, delete in v2.0.

## Routing for a fresh session

If the parallel session is starting v1.8 planning:

1. Check `git tag -l` in main repo — v1.7 must be tagged before v1.8 work
   starts. If not tagged: hold; v1.8 phase promotions are blocked.
2. Confirm v1.7 RELEASE-NOTES-v1.7.md exists (currently doesn't — see
   [GAPS-FROM-V1.7.md](GAPS-FROM-V1.7.md) §3).
3. Read the Handover Phase 4-8 docs at
   `/Users/kohlbach/Claude/BALL/Claude Design Handover/revitalization/04-*.md`
   through `08-*.md`. They are the spec.
4. Run `/gsd-review-backlog` against Phase 999.44 to start the v1.8
   cycle. 999.44 is the natural lead — 999.45 / 999.46 / 999.47 / 999.48
   serialize on it.
5. Set up community-translation outreach **early** in the v1.8 cycle so
   v1.8 RC ships with a call-for-translators ready.

If the parallel session is starting v2.x planning instead: **do not start
v1.8 work**. Read [ROADMAP-v2.md](ROADMAP-v2.md). v1.8 only matters as a
prerequisite — `BALL_UI_V2` defaulting ON and Refresh phases 999.44-999.48
all merged are gates on the v2.0 cycle opening.
