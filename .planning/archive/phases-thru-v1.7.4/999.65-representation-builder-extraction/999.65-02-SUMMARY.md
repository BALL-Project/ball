## buildCurrentSpec Field Mapping

`RepresentationSpec buildCurrentSpec() const` packs the dialog's CURRENT widget state, reproducing the exact reads of `applyModelSettings_` (displayProperties.C:444-510) and `applyColoringSettings_` (513-563):

| Spec field | Source widget / call | Null-dialog fallback |
|------------|----------------------|----------------------|
| model_type | `model_type_combobox->currentIndex()` | n/a |
| model_params | the 20 `model_settings_->getX()` getters (engine 459-479) | default `ModelProcessorParams` (if `model_settings_ == 0`) |
| coloring_method | `coloring_method_combobox->currentIndex()` | n/a |
| coloring_overrides | `coloring_settings_->buildColoringOverrides()` (engine 531) | default `ColoringOverrides` (if `coloring_settings_ == 0`) |
| drawing_mode | `mode_combobox->currentIndex()` (engine 485) | n/a |
| use_custom_surface_precision | `custom_precision_button->isChecked()` (engine 487) | n/a |
| surface_drawing_precision | `precision_slider->value()/10.0` when custom; else `SurfaceDrawingPrecisions[precision_combobox->currentIndex()]` for surface models (engine 489-497) | spec default 6.5 |
| drawing_precision | `precision_combobox->currentIndex()` (engine 493, presets branch) | n/a |
| transparency | `transparency_slider->value()` (engine 540) | n/a |
| custom_color | `custom_color_button->getColor()` -> `ColorRGBA` (RAW, no alpha — builder applies 255-transparency) | n/a |
| model_update_enabled | `model_updates_enabled->isChecked()` | true (createRepresentationMode forces it) |
| coloring_update_enabled | `coloring_updates_enabled->isChecked()` | true (createRepresentationMode forces it) |

The null-dialog guards (`model_settings_`/`coloring_settings_ == 0` -> default-constructed params/overrides) mirror the legacy `apply*` `if (… == 0) return;` early-outs: a null settings dialog means "use the compiled defaults".

## onNotify Repoint

The `CompositeMessage::NEW_MOLECULE` branch (displayProperties.C:329-348) previously did
`createRepresentationMode(); list<Composite*> clist; clist.push_back(...); createRepresentation(clist);`.
Now:

```cpp
createRepresentationMode();                 // KEPT: resets rep_=0, forces both update checkboxes true
list<Composite*> clist;
clist.push_back(composite_message->getComposite());

Notifier_ notifier(*this);                  // nested adapter -> this->notify_
RepresentationBuilder::createRepresentation(buildCurrentSpec(), clist,
                                            *getMainControl(), notifier,
                                            *model_information_);
```

`createRepresentationMode()` stays in front so the update-enable checkboxes are true when `buildCurrentSpec()` reads them — preserving the legacy "auto-rep is always built with updates enabled" semantics. The builder fires the same message sequence (`ADD_TO_GEOMETRIC_CONTROL`, then `CENTER_CAMERA` when fewer than two reps exist) through the `Notifier_` adapter.
