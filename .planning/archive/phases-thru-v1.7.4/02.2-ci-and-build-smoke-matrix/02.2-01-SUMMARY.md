**BALLView now emits a single greppable `BALLVIEW_GL_DIAG` stdout line at GL-context creation, and a dependency-free `render-smoke-check.sh` drives the existing exportPNG path headless to assert a non-blank molecule render against that line as its oracle.**

## Accomplishments
- **DIAG-01 satisfied:** `GLRenderWindow::initializeGL()` emits one machine-parseable `BALLVIEW_GL_DIAG` line carrying GL vendor/renderer/version, GL profile, QSurfaceFormat (surface_version/depth_bits/stencil_bits/samples), device_pixel_ratio, default_fbo, fbo_size, and renderer_backend — unconditional, flushed, one physical line.
- **Reusable render smoke check:** `render-smoke-check.sh` launches the built BALLView headless against a known PDB, drives BALL's existing `Scene::exportPNG()` path, asserts the PNG exists + is non-blank + has a non-degenerate viewport, and cross-checks the DIAG-01 line as the GL-context oracle (D-05). Exits 0 on a good render, non-zero with diagnostics + retained artifacts on failure.
- **Non-invasive headless trigger:** added a minimal `-export-png <path>` CLI flag to `main.C` (a `QTimer::singleShot` that calls the existing export path and quits) — no new GL harness.
- Both artifacts verified locally and ready for Plan 02 to wire into the GitHub Actions macOS/Linux matrix.

## Files Created/Modified
- `source/VIEW/RENDERING/glRenderWindow.C` - `initializeGL()` now writes the `BALLVIEW_GL_DIAG` line to `std::cout` while the GL context is current (added `<iostream>` + `<QtGui/QSurfaceFormat>` includes).

## Decisions Made

- **DIAG-01 line format** — space-separated `key=value` pairs after a stable `BALLVIEW_GL_DIAG` token, single physical line, `std::endl`-flushed. Quoted-string values for the GL vendor/renderer/version strings (they contain spaces).
- **Headless export trigger** — the plan's preferred path was the auto-loaded startup-demo peptide, but investigation showed that "demo peptide" is actually *restored session state* from `~/.BALLView` (`restoreWindows()`), not a deterministic auto-load. Used the **D-09 documented fallback**: a fixed known PDB shipped in the source tree (`data/structures/bpti.pdb`, 454 atoms), loaded via the existing `mainframe.openFile()` argv path, plus the minimal `-export-png` flag (an allowed plan-scoped `main.C` edit per D-01) to trigger the export and quit.
- **DIAG-01 fbo_size is not the dimension oracle** — `initializeGL()` fires before the widget is laid out, so `fbo_size` reads the pre-layout widget size (observed `20x1018`) which does not match the final export dimensions (observed `1510x1046`). The smoke check therefore uses the diag line's **presence + a live `gl_version` + `renderer_backend=GL`** as the GL-context oracle (the D-05 intent: prove a real context exists, catching the Phase 2 blank-render bug class) and asserts a non-degenerate viewport (>= 64x64) separately. This is documented inline in the script.
- **Non-blank PNG check** — python3 standard library only (`struct` to read IHDR, `zlib` to inflate all IDAT chunks, then count distinct byte values across the whole decompressed stream). A flat/blank render collapses to ~1-2 distinct values; the local bpti render produced 256. Zero extra dependencies on any runner.

## Issues Encountered
- `timeout` is not available on the macOS shell — the smoke-check script implements its own watchdog (background PID + poll loop) instead of relying on `timeout`/`gtimeout`. This also keeps the script portable to the Linux CI runner.
- The DIAG-01 `gl_profile` field reads `none` on macOS for the GL 2.1 compatibility context (Apple's GL driver reports no profile mask for 2.1) — this is expected, not a bug; the `surface_version=2.1` field is the meaningful capability signal there.

## Known Stubs
None. `renderer_backend=GL` is a deliberate literal (per the plan and CONTEXT D-04: the field exists so the Phase 05.1 QRhi/GL-core spike can populate it; there is only a GL backend today). This is documented, plan-scoped, and resolved by a named future phase — not a stub.
