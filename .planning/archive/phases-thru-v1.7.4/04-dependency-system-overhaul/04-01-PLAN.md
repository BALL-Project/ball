<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CMake `find_package` → installed system/Homebrew package | Untrusted package metadata + library binaries cross into the build. A malicious or hijacked package directory on `CMAKE_PREFIX_PATH` could inject code at link time. |
| Deleted bundled finders → upstream `*Config.cmake` | Build now trusts upstream-shipped CMake config scripts (executed at configure time) instead of repo-controlled finder modules. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | `find_package(... CONFIG)` resolution picking up an attacker-controlled package | mitigate | All `find_package` calls carry an explicit minimum version pin (Eigen3 3.4, TBB 2021.0, OpenBabel3 3.0, Boost 1.70, Qt 5.15) — a downgrade/substitution attack with an older planted package fails the version check. CI resolves only from the pinned Homebrew/apt package set, not arbitrary prefixes. |
| T-04-02 | Tampering | `BALL_CONTRIB_PATH` prepending an unaudited directory to `CMAKE_PREFIX_PATH` and `CMAKE_REQUIRED_INCLUDES` | mitigate | This plan deletes `BALL_CONTRIB_PATH` entirely — removing a configure-time injection vector where a stale/hijacked `ball_contrib` tree could shadow system headers and libraries. |
| T-04-03 | Elevation of Privilege | Upstream `*Config.cmake` scripts execute arbitrary CMake at configure time | accept | Config scripts ship inside the same Homebrew/apt/vcpkg packages whose libraries we already link and trust; treating their CMake configs as less trusted than their binaries is incoherent. Pinned versions + provisioning only from official package managers bounds the exposure. No additional mitigation in-phase. |
| T-04-04 | Information Disclosure | Configure log leaking absolute local paths | accept | Build-system phase, single-developer + CI; configure logs contain only local filesystem paths, no secrets. Low value, no PII. |
</threat_model>
