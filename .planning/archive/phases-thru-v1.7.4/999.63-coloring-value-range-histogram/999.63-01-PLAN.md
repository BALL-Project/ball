# `999.63` — Coloring · value-range histogram

**v1.7.x-17b** · Wave B · ~3–4 days

> **Codex reconciliation (2026-05-22, MEDIUM #11).** Live-preview is
> KEPT (full scope). The escape-hatch concern is closed by making
> `previewRange()` explicitly **non-owner / render-only** — a transient
> visual hint, never an owner mutation — and adding a contract test
> (`coloring_preview_nonmutation_test.C`) that asserts dragging does NOT
> create a second mutation path. Commit happens only on handle release
> through the §2 `apply()` contract. This aligns with
> ARCHITECTURE-CONTRACT.md §5's "render-only hints are NOT mutations"
> clause (added in the same reconciliation).

## Goal

Replace the basic `min` / `max` text inputs that shipped in
v1.7.x-17 with a histogram of the actual values across the active
selection, plus two draggable handles, plus four smart presets. The
first visible **Inspector depth** win on the v1.7.4 contract.

Visual target: `revitalization/mockups.html#v172-forward` board 05.

## Why now

The shipped basic version is functional but information-blind — the
user has to *know* what range to pick. The histogram makes the data's
shape legible and lets the user clamp to it in one drag. Small UI
investment; large user-experience leverage on value-based colorings
(B-factor / Occupancy / Distance from ligand).

The contract from `999.59` is the prerequisite: the widget commits
through `ColoringController::setRange(min, max).apply()` which goes
through the new command-shaped `bool apply()`. No new mutation paths —
and the live drag is a render-only hint, not a second mutation path.

## Scope

**In:**

1. **`ValueRangeWidget`** — new widget (~300 LOC):
   - Renders a 27-bin histogram (or N-bin if injected).
   - Draws the colormap behind the bars; in-range bins paint with the colormap, out-of-range bins are de-emphasized.
   - Two draggable handles (`min` / `max`) emit `rangeChanged(min, max)` while dragging, `rangeCommitted(min, max)` on release.
   - Two text readouts below the handles.
   - Footer row with 4 preset buttons (Auto-fit / Full range / Robust 5–95% / Reset).
   - Lives in `source/VIEW/WIDGETS/`, not `inspector/sections/` (it's reusable).
2. **`ColoringController::distribution()`** — new read-model method:
   - Returns `BinSummary { min, max, bin_edges, bin_counts }` for the current selection + coloring method.
   - Caches against `(selection_id, method)` — invalidates on selection-change or method-change notification.
   - The Controller computes once via `BALL::Statistics::Histogram`; widget reads it.
3. **`ColoringController::previewRange(min, max)`** — new RENDER-ONLY method:
   - Paints a transient semi-transparent overlay / colormap-clamp hint on the scene.
   - Creates NO `ApplyPayload`, emits NO typed event, calls NO owner setter, takes NO `ControllerApplyGuard`. It is not a mutation.
   - Idempotent and freely re-callable per drag-frame.
4. **`ColoringSection` integration** — replaces the v1.7.x-17 stacked-widget min/max page with the `ValueRangeWidget` for value-based methods.
5. **Presets** wire to controller methods, each committing through `setRange().apply()`:
   - Auto-fit → `distribution().min` / `.max`.
   - Full range → method-defined limits (e.g. B-factor: 0–100; Charge: -5–+5).
   - Robust 5–95% → percentile bin edges.
   - Reset → revert to method-defined defaults (delegates to `ColoringController::reset()` from 999.64's base).

**Out:**
- Non-coloring uses of the widget (other Sections do not consume it in v1.7.4).
- Custom colormap editor — v1.7.5+.
- Persisted user-preferred ranges per method — v1.7.5.
- Time-series histograms (trajectories) — v2.0.

## Detailed steps

### 63.1 — `ValueRangeWidget` skeleton

- `QWidget` subclass. `paintEvent` draws the histogram (per
  `mockups.html` board 05 visual).
- Mouse events on the handles — pointer-precise drag.
- Emits `rangeChanged` (during drag) + `rangeCommitted` (on release).
- Accepts `setDistribution(BinSummary)` from the section.
- No business logic; no statistics.

### 63.2 — `ColoringController::distribution()`

- New read-model on the Controller. Computes the bin summary in
  `Controller`-land, caches it.
- Cache key: `(selection_hash, method, custom_field_if_any)`.
- Cache invalidates on `CompositeMessage::selectionChanged` or
  `applyEvent(coloring.setMethod)`.
- Returns a value type, not a pointer — widget can't accidentally
  mutate it.

### 63.3 — `ColoringSection` wiring

- Remove the current min/max stacked-widget page.
- Insert `ValueRangeWidget`.
- On `rangeCommitted(min, max)` (handle release):
  - `controller_->setRange(min, max);`
  - `controller_->apply();`  // returns bool; the ONLY mutation path
- On `rangeChanged(min, max)` (drag-time):
  - Call `controller_->previewRange(min, max)` — the render-only hint.
    This does NOT call `apply()`, does NOT mutate the owner, emits no
    event. Dragging never commits a payload.
- Preset buttons call `controller_->setRange(...); controller_->apply();` (or `reset()` for Reset).

### 63.4 — Tests

- Unit test for `distribution()` against known values.
- **`coloring_preview_nonmutation_test.C` (NEW, contract test)** —
  drives a sequence of `previewRange()` calls and asserts: the owner
  snapshot is unchanged, no `applyEvent` was emitted, and the controller's
  `apply()` was never entered (no `ApplyPayload` recorded). This is the
  guard against `previewRange` silently becoming a second mutation path.
- Parity test in `999.60`'s contract harness: commit path
  `setRange(20, 40).apply()` via the widget == toolbar/menu == python
  `coloring.setRange(20, 40)`.

## Risks

- **`previewRange` render overlay is fiddly.** Live preview KEEPS full scope. If the render-side overlay needs more work than the phase budget, the fallback is a *cheaper* render-only hint (e.g. recolor the histogram bars in-range during drag rather than a scene overlay) — still render-only, still non-mutating, still a strict win over text inputs. The non-mutation contract (and its test) holds regardless of how rich the hint is.
- **Histogram resolution.** Default 27 bins is `mockups.html` board 05. For very small selections (≤27 atoms) the bins look sparse; provide a `setBinCount(N)` escape hatch on the widget.
