# Phase 02.1 Plan 02: Renderer Batched-Geometry Boundary Summary

**Additive `Renderer::renderRepresentations_(const RepresentationList&)` + `capabilities()` entry points on the `Renderer` base class; the default `renderRepresentations_()` fans out to the proven `renderOneRepresentation()` path so every existing immediate-mode renderer is untouched and behaves identically — pure refactor, BALLView builds clean.**

## Accomplishments
- `Renderer` base class gains a `Caps` struct (`retained_mode`, `offscreen`, `picking`, `stereo`) — the capability descriptor that lets `RenderSetup`/`Scene` branch on capability instead of on concrete renderer type.
- `Renderer::capabilities()` declared and implemented NON-pure, returning a default immediate-mode descriptor (`retained_mode=false`, `offscreen=false`, `picking=true`, `stereo=true`) matching today's `GLRenderer` behaviour.
- `Renderer::renderRepresentations_(const RepresentationList&)` declared and implemented with a default fan-out: iterates the list and calls the existing `renderOneRepresentation()` for each non-null `Representation*`. A Phase 5 retained-mode backend overrides THIS one method instead of faking immediate mode through ~16 per-primitive virtuals.
- Zero subclass changes — `GLRenderer`, `POVRenderer`, `STLRenderer`, `VRMLRenderer`, `XML3DRenderer`, the raytracer and `TilingRenderer` are all untouched and inherit the behaviour-preserving default.

## Decisions Made
- **`capabilities()` is NON-pure — deviation from the boundary doc.** `.planning/RENDERER-INTERFACE-BOUNDARY.md` section 1 sketches `virtual Caps capabilities() const = 0;` (pure virtual). Implemented NON-pure with a default body instead. A pure virtual would force every one of the ~7 existing `Renderer` subclasses to add an override in this plan, directly violating the ARCH-03 "additive only / existing renderers untouched" rule. The planner pre-recorded this deviation in the plan; it is honored here. A retained-mode Phase 5 backend simply overrides the non-pure default.
- **`renderRepresentations_()` is added but NOT wired in.** It is a parallel entry point this plan only *adds*. Wiring it into `RenderSetup`/`Scene` (branching on `capabilities().retained_mode`) is deliberately deferred — that is the actual Phase 5 backend work. This plan only proves the boundary exists and that the default preserves behaviour.
- **No `sources.cmake` edit.** Both `renderer.h` and `renderer.C` already exist and `renderer.C` is already in the VIEW build — the change is purely in-place additive.
