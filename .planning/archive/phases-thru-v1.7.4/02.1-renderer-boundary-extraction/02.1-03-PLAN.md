<objective>
Add a `RendererFactory` that constructs renderers and surfaces by enum, and route `Scene` through it so `scene.C` no longer names the concrete `GLRenderWindow` / `GLRenderer` types in its primary (non-deferred) rendering paths. Replace the `dynamic_cast<GLRenderWindow>` / `dynamic_cast<GLRenderer>` / `RTTI::isKindOf<GLRenderWindow>` sites and the `new GLRenderWindow` calls with factory construction + capability/`RenderSurface`-interface queries.

Purpose: This is the ARCH-02 + ARCH-04 close of the boundary. With `Scene` constructing by `Kind` and querying through the `Renderer` / `RenderSurface` interfaces, the Phase 5 backend swap is "one new `case` in the factory + two new files" — `scene.C` is not re-touched.
Output: `rendererFactory.{h,C}` (new), `Scene::registerRenderers_()` + the main-display construction routed through the factory, the concrete-type sites in the non-deferred paths removed.

PURE REFACTOR — zero behaviour change. Same pixels. This plan includes a human-verify checkpoint because ARCH-04 (identical render) is the pure-refactor guarantee and `scene.C` is the highest-blast-radius file.

SCOPE GUARD: the stereo / multi-display construction sites (`scene.C` ~2480-2900) stay GUARD-DEFERRED exactly as Phase 2 left them. Route their construction through the factory ONLY if trivial (a direct `new GLRenderWindow(...)` → `RendererFactory::makeSurface(...)` substitution with no logic change); if a site needs more than a mechanical swap, LEAVE IT and document it. Do NOT un-defer stereo. Do NOT add a new backend.

EXPECTED RESIDUALS — deferred-stereo `new GLRenderWindow`: the ~10 deferred-stereo construction sites in `scene.C` (~2480-2897) use the 3-arg ctor `new GLRenderWindow(0, "Scene", Qt::Window)`. `RendererFactory::makeSurface(Kind, QWidget* parent)` is a 2-arg signature and does NOT cover the 3-arg ctor BY DESIGN — those sites are guard-deferred to Phase 5 anyway. ALL of these ~10 deferred-stereo `new GLRenderWindow` sites are EXPECTED to remain as documented residuals. This is not a failure: the executor should not waste effort trying to route them, and the SUMMARY residual list should carry this context so it does not look alarming.

    ```cpp
    // rendererFactory.h
    namespace BALL { namespace VIEW {
      class Renderer;
      class RenderSurface;

      /** Constructs renderers and surfaces by Kind so Scene never names a
       *  concrete backend type. Phase 5 adds OpenGL_Core / QRhi as new cases.
       */
      namespace RendererFactory
      {
        enum class Kind
        {
          OpenGL_Fixed,   ///< today's GLRenderer (fixed-function compat profile)
          Raytracer,      ///< CPU raytracer (BALL_HAS_RTFACT)
          POV, STL, VRML  ///< file renderers
        };

        /// Construct a Renderer for the given Kind. Caller owns the result.
        BALL_VIEW_EXPORT Renderer* makeRenderer(Kind kind);

        /// Construct an on-screen RenderSurface for the given Kind. Caller owns the result.
        /// parent is forwarded to the underlying QWidget.
        BALL_VIEW_EXPORT RenderSurface* makeSurface(Kind kind, QWidget* parent);
      }
    }}
    ```

    Implement in `rendererFactory.C`:
    - `makeRenderer(OpenGL_Fixed)` → `new GLRenderer`. `POV/STL/VRML` → the corresponding existing renderer. `Raytracer` → `new RTfactRenderer` under `#ifdef BALL_HAS_RTFACT`, else fall back to `new GLRenderer` — match what `scene.C registerRenderers_()` does today (its `#else` branch uses the GL renderer path). `default:` returns `0`.
    - `makeSurface(OpenGL_Fixed, parent)` → `new GLRenderWindow(parent)`. For `POV/STL/VRML` (file renderers) a surface is not a window — return `0` (scene.C does not construct windows for those today; keep parity, do not invent new flows). `default:` returns `0`.
