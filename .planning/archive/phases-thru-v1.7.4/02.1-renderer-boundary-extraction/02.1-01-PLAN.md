<objective>
Extract the context-lifecycle concern that currently leaks through `GLRenderWindow` + `RenderSetup::makeCurrent()` into a Qt-GL-free `RenderSurface` interface. After this plan, `RenderSetup` talks to a backend-neutral `beginFrame()`/`endFrame()` pair instead of a GL-specific `makeCurrent()` body.

Purpose: This is the ARCH-01 half of the renderer boundary. With the context lifecycle behind an interface, a Phase 5 QRhi/GL-core surface is a new `RenderSurface` subclass — not another re-thread of the widget.
Output: `renderSurface.h` (new interface), `GLRenderWindow` adopting it, `RenderSetup::makeCurrent()` reduced to a delegation.

PURE REFACTOR — zero behaviour change. Same pixels. BALLView must build and render identically to post-Phase-2.
</objective>

RenderSetup::makeCurrent() — CURRENT body (source/VIEW/RENDERING/renderSetup.C ~line 298):
```cpp
void RenderSetup::makeCurrent()
{
  if (gl_target_ &&
      (QOpenGLContext::currentContext() != gl_target_->context()))
    gl_target_->makeCurrent();
  else
    target->prepareRendering();
}
```
`gl_target_` is a `GLRenderWindow*` member (set via `dynamic_cast` in the ctors). `target` is `RenderTarget*`.
`makeCurrent()` is called from ~13 sites in renderSetup.C plus scene.C — all GUI-thread.

Declare exactly these new pure-virtual verbs (copy signatures verbatim from the boundary doc):

    ```cpp
    class BALL_VIEW_EXPORT RenderSurface : public RenderTarget
    {
      public:
        /// Make this surface ready to receive a frame's draw calls.
        /// GL backend -> makeCurrent(); QRhi backend -> begin command buffer; no-op for file renderers.
        virtual void beginFrame() = 0;
        /// Finish the frame. GL -> implicit swap; QRhi -> submit.
        virtual void endFrame() = 0;
        /// Opaque native handle; only the matching backend casts it.
        virtual void* nativeHandle() = 0;
    };
    ```
