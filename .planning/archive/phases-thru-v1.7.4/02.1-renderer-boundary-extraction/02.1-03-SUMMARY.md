# Phase 02.1 Plan 03: RendererFactory + Scene Routing Summary

**A `RendererFactory` now constructs renderers and surfaces by enum, and `scene.C`'s
primary rendering paths name no concrete `GLRenderWindow`/`GLRenderer` type — the
contained-swap boundary for Phase 5/05.1 is in place. Pure refactor, human-verified
to render identically to post-Phase-2.**

## What shipped

- **`RendererFactory`** (`rendererFactory.{h,C}`, new; `.C` added to
  `source/VIEW/RENDERING/sources.cmake`) — `enum Kind` → `makeRenderer()` /
  `makeSurface()`. `Scene` constructs its main display + renderers through it.
- **`scene.C` primary paths cleaned** — zero `dynamic_cast<GLRenderWindow>`,
  `dynamic_cast<GLRenderer>`, `RTTI::isKindOf<GLRenderWindow>`,
  `RTTI::isKindOf<GLRenderer>` in the non-deferred rendering paths. Concrete-type
  branching replaced by `RenderSurface`/`Renderer` interface queries and
  `RenderSetup::getRendererType()`. `setDownsamplingFactor`/`setFogIntensity`
  promoted to the interfaces so their casts disappear.

## Expected residuals (not failures)

- `scene.C` retains ~9 `new GLRenderWindow(0, "name", Qt::WindowFlags)` 3-arg-ctor
  sites and ~8 `new GLRenderer` sites — all inside the stereo/multi-display methods
  (`addGlWindow`, `addRTfactWindow`, `enterStereo`, `enterActiveStereo`,
  `enterDualStereo`, `enterDualStereoDifferentDisplays`). These paths are
  guard-deferred to Phase 5; the 2-arg `makeSurface(Kind, QWidget*)` does not cover
  the 3-arg ctor by design. Routing them is Phase 5 scope.
- `check-no-legacy-gl-symbols.sh` exits 1 with the same 7 pre-existing references
  (6 historical comments + `glDisplayList.h`'s `QtOpenGL/qgl.h` include) — zero new
  legacy symbols introduced; logged in `deferred-items.md` for Phase 5.

## Notes for downstream phases

- **Phase 5 (Qt 6) / Phase 05.1 (backend spike):** a new backend is now
  `RendererFactory::Kind` + a `Renderer` subclass + a `RenderSurface` subclass —
  no `scene.C` edits. This is the contained-swap the boundary was extracted for.
- The deferred-stereo `new GLRenderWindow` sites are the remaining concrete-type
  coupling; Phase 5 either routes them through an extended factory signature or
  retires the stereo paths.
