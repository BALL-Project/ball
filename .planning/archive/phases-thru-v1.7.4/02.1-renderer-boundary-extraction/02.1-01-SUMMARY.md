# Phase 02.1 Plan 01: RenderSurface Interface Extraction Summary

**Qt-GL-free `RenderSurface` interface owning `beginFrame`/`endFrame`/`nativeHandle`; `RenderSetup::makeCurrent()`'s GL-context body moved behind `GLRenderWindow::beginFrame()` — pure refactor, BALLView builds and renders identically.**

## Performance

- **Duration:** ~6 min
- **Started:** 2026-05-14T10:04Z
- **Completed:** 2026-05-14
- **Tasks:** 2
- **Files modified:** 7 (1 created, 6 modified)

## Accomplishments
- New `RenderSurface` abstract interface (`RenderTarget` subclass) declares the context-lifecycle verbs `beginFrame()`/`endFrame()`/`nativeHandle()` with zero Qt-GL types in its signatures.
- `TRenderWindow` now subclasses `RenderSurface`; `GLRenderWindow` implements the three verbs, with `beginFrame()` holding the GL-context op (`makeCurrent()` if context not current) that was previously inline in `RenderSetup::makeCurrent()`.
- `RenderSetup::makeCurrent()` reduced to a backend-neutral delegation via `dynamic_cast<RenderSurface*>(target)->beginFrame()` — no more `gl_target_->context()` GL branch.
- `GLOffscreenTarget` also adopted the interface (its `beginFrame()` mirrors `prepareRendering()` — make the shared context current + bind FBO).

## Files Created/Modified

- `include/BALL/VIEW/RENDERING/glOffscreenTarget.h` - Declared the three `override` methods.
- `source/VIEW/RENDERING/glOffscreenTarget.C` - Implemented `beginFrame()` (delegates to `prepareRendering()`), `endFrame()` (no-op), `nativeHandle()`.
- `source/VIEW/RENDERING/renderSetup.C` - `makeCurrent()` body replaced with `dynamic_cast<RenderSurface*>` delegation; added `renderSurface.h` include.

## Decisions Made
- **`endFrame()` is a deliberate no-op for the GL backend.** `QOpenGLWidget` swaps implicitly after `paintGL()` (Phase 2 already removed manual `swapBuffers()`), so there is nothing to submit. The verb exists for a future QRhi backend (Phase 5), where it will mean "submit command buffer". No `endFrame()` call sites were added.
- **`gl_target_` left in place.** The `RenderSetup::gl_target_` member and the ~13 `makeCurrent()` call sites are untouched — only `makeCurrent()`'s body changed. Plan 03 handles the remaining concrete-type cleanup.
- **No build-file edit needed.** `renderSurface.h` is a header — BALL picks headers up implicitly via the include path (no `.cmake` listing). `glRenderWindow.C`/`renderSetup.C`/`glOffscreenTarget.C` are already in `source/VIEW/RENDERING/sources.cmake`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `GLOffscreenTarget` also needed the RenderSurface verbs**
- **Found during:** Task 2 (build verification)
- **Issue:** The plan stated "`RenderWindow` (`TRenderWindow<float>`) is only ever instantiated through `GLRenderWindow`". This is incorrect — `GLOffscreenTarget` also derives from `RenderWindow`. After `TRenderWindow` became abstract for the three new verbs, `scene.C` failed to compile: `allocating an object of abstract class type 'GLOffscreenTarget'`.
- **Fix:** Implemented `beginFrame()` / `endFrame()` / `nativeHandle()` on `GLOffscreenTarget`. `beginFrame()` delegates to the existing `prepareRendering()` (make shared GL context current + bind FBO), `endFrame()` is a no-op, `nativeHandle()` returns the `QPaintDevice*`. Behaviour-preserving.
- **Files modified:** `include/BALL/VIEW/RENDERING/glOffscreenTarget.h`, `source/VIEW/RENDERING/glOffscreenTarget.C`
- **Verification:** `make BALL VIEW BALLView -j8` builds clean.
- **Committed in:** `d3d84f8` (Task 2 commit)

**2. [Rule 3 - Blocking] `QOpenGLContext` incomplete type in glRenderWindow.C**
- **Found during:** Task 2 (build verification)
- **Issue:** `glRenderWindow.C` used `QOpenGLContext::currentContext()` in the new `beginFrame()` but only had a forward declaration of `QOpenGLContext` in scope.
- **Fix:** Added `#include <QtGui/QOpenGLContext>` to `glRenderWindow.C`.
- **Files modified:** `source/VIEW/RENDERING/glRenderWindow.C`
- **Verification:** Build passes.
- **Committed in:** `d3d84f8` (Task 2 commit)
