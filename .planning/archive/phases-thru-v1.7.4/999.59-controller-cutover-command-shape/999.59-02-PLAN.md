  <name>Task 1: Harmonize ModelController onto bool apply() with REBUILD invalidation</name>
  <files>include/BALL/VIEW/KERNEL/controllers/modelController.h, source/VIEW/KERNEL/controllers/modelController.C</files>
  <behavior>
    - ModelController inherits from BALL::VIEW::Controller; apply() overrides bool apply().
    - apply() returns false immediately when applying_depth_ > 0 (re-entry dropped).
    - apply() returns false when preconditions fail (no representation_).
    - apply() returns true after a successful model-type mutation.
    - invalidateDeclared_() requests representation_->update(true) — a display-list REBUILD, because swapping the model processor (e.g. Stick → Surface) changes the primitive set (§2a Model row). It must NOT be a soft refresh.
    - The 999.60 model_contract_test fixture asserts apply() == true and cross-surface snapshot parity → goes green.
  </behavior>
  <action>
Apply the §13 cookbook to ModelController: (1) inventory the current
`apply()` body; (2) move the existing mutation into a private
`bool applyInternal_()` (or `void` if it can't fail post-validation); (3)
rewrite `apply()` as the §2 `bool` wrapper — precondition check (fail-fast
return false on missing representation_), re-entry shield
(`if (applying_depth_ > 0) return false;` then
`ControllerApplyGuard guard(applying_depth_);`), capture an `ApplyPayload`
(command_id e.g. `"model.setType"`, before = snapshot, after = pending,
target = representation_, t_us = now), call `applyInternal_()`, emit the
ONE existing typed model/representation event (do not add a second), call
`invalidateDeclared_()`, then `recordIntent_(payload)` (capture-only — no
stack), `return true`. Make the header declare `bool apply() override;` and
`void reset() override;` and `void invalidateDeclared_() override;`.

Override `invalidateDeclared_()` to call `representation_->update(true)` —
the display-list REBUILD. Document in a comment that Model is the one
Representation-domain controller that rebuilds because a model-processor
swap changes the primitives themselves (a soft refresh would re-draw stale
geometry). NEVER a blanket full-scene rebuild (the v1.7.x-13 freeze).

Add a `recordIntent_(const ApplyPayload&)` helper (can live on the base in
Plan 01 if already present; otherwise a private member here that stores the
last payload — v1.7.4 capture-only). Keep the public binding surface
(`setModelType` etc. the Inspector section calls) unchanged — only apply()'s
internal shape changes. Do not narrow the owner setter here (that is Plan 04).
  </action>
