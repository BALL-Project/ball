# 999.59-06 — PyBALL SIP binding refresh (scope-adjusted)

## Scope decision
The plan's full scope included a `sip-refresh-check` CI job that installs **SIP
4.9** (ancient Riverbank SIP) on ubuntu-24.04 and regenerates+compiles the
bindings. Three material facts made that poor value:
1. **SIP is disabled in the modernization build** (CLAUDE.md) — the `.sip` files
   are not compiled by the product/CI build today.
2. The roadmap **replaces SIP entirely in v2.1** (Phase 6 generator bake-off).
3. SIP 4.9 on a modern runner is fragile-to-uninstallable → risk of a
   perpetually-red gate for a layer about to be removed.

User chose **"durable .sip work, skip the SIP-4.9 CI job"**: do the binding
surgery + shim that keep the `.sip` honest, and replace the regen job with a
lightweight symbol-reference lint.

## What landed
- **representation.sip**: removed the 11 narrowed setters that 999.59-04
  privatized (they referenced now-private C++ symbols — `setHidden`,
  `setDrawingPrecision`, `setSurfaceDrawingPrecision`, `setDrawingMode`,
  `setTransparency`, `setComposites`, `setComposite`, `setModelProcessor`,
  `setColorProcessor`, `setModelType`, `setColoringMethod`). Getters +
  `setGeometricObjects` + the rest of the surface kept.
- **Deprecation shims**: the 4 contract-named legacy setters (`setModelType`,
  `setDrawingMode`, `setTransparency`, `setColoringMethod`) kept as `%MethodCode`
  that emits a Python `DeprecationWarning` naming the controller replacement and
  **forwards through the command-shaped controller** (Model/Material/Coloring
  Controller → `setRepresentation` → setter → `apply()`). One-release bridge,
  removed in v1.8.
- **controllers.sip (NEW)**: exposes the 9 Controllers' real public surface
  (`apply()`/`reset()` + the verified typed setters) — bindings see Controllers,
  never owners. Mirrors the actual C++ method names (the plan's assumed
  `mainControl.coloringController()` accessor does NOT exist in C++; controllers
  are constructed against their owner, which the bindings reflect).
- **VIEW.sip**: registers `%Include controllers.sip`.
- **cmake/scripts/check-sip-symbols.sh (NEW)**: lightweight lint — every plain
  method in controllers.sip must map to a real symbol in the header its class
  `%TypeHeaderCode`-includes (skips `%MethodCode` + ctors). Catches the
  setter-rename rot §3d guards against, without SIP.
- **ci.yml**: new blocking `sip-refresh` lint job (ubuntu-24.04) running the
  script. Replaces the planned SIP-4.9 regen job.

## Verification
- `check-sip-symbols.sh`: **OK** (every plain controllers.sip method maps to a
  real C++ symbol). Negative test confirmed it FAILS on an injected renamed
  setter, then passes again after restore.
- `ci.yml`: valid YAML; `sip-refresh` job present.

## Deviations
1. **SIP-4.9 regen CI job → lightweight symbol lint** (user scope decision).
2. **No `mainControl.coloringController()` accessor** — the plan assumed one; it
   doesn't exist in C++. controllers.sip exposes the controller classes against
   the real (construct-and-attach) surface instead.
3. Real method names used (e.g. `setColoringMethod(int)`), not the plan's
   illustrative `setMethod`.

## Deferred (→ task #30 UAT batch)
The human-verify checkpoint (DeprecationWarning + legacy-attribute runtime
behavior) is **deferred and largely moot in v1.7.4**: SIP isn't compiled, so the
binding has no runtime in this release. The durable, lint-checkable binding
surface is in place; runtime exercise rides with the v2.1 PyBALL milestone.
