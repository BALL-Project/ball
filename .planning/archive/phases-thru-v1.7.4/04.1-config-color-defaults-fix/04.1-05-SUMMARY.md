## Behaviour Gate Observations (Structural — Confirmed by Code Analysis)

**Behaviour gate 1 — totally malformed token (`garbage:zz;`):**
A token like `garbage:zz` has `parts[1] = "zz"` (length 2, not 6 or 8). The length pre-check fires first: `Log.warn() << "... dropping malformed override token 'garbage:zz' (color hex must be 6 or 8 chars)"`. The loop continues to the next token. The application never reaches `toUnsignedInt("garbage")`, so no `InvalidFormat` exception is thrown. BALLView starts successfully, compiled defaults flow through for all elements.

**Behaviour gate 2 — mixed valid/malformed tokens (`6:33ff33ff;notanumber:bad;7:5151ff`):**
- Token `6:33ff33ff`: length 8, passes length check; `toUnsignedInt("6")` succeeds; `ColorRGBA("33ff33ff")` succeeds; override applied to carbon row (green `33ff33`).
- Token `notanumber:bad`: length 3, fails length check → `Log.warn() << "... dropping malformed override token 'notanumber:bad' (color hex must be 6 or 8 chars)"` → continue.
- Token `7:5151ff`: length 6, passes length check; `toUnsignedInt("7")` succeeds; `ColorRGBA("5151ff")` succeeds; override applied to nitrogen row (blue `5151ff`).
- BALLView starts successfully. Carbon shows green `33ff33`, nitrogen shows `5151ff`, malformed middle token silently skipped.

**Behaviour gate 3 — all-white sanity still fires (`6:ffffffff;`):**
Token `6:ffffffff`: length 8, passes length check; `toUnsignedInt("6")` succeeds; `ColorRGBA("ffffffff")` succeeds; `isKnownColoredElement(6)` returns true (6 is in `KNOWN_COLORED_ATOMIC_NUMBERS`); all-channel white check fires: `Log.warn() << "... dropping suspicious all-white override for atomic number 6 ..."`. Carbon row shows PyMOL green `33ff33` (compiled default). File-scope helper IS being used; inline `std::set` is gone.

Note: Manual BALLView launch was not performed in this session. The behaviour trace above is confirmed structurally by the code analysis and is consistent with the BALL exception hierarchy (both `InvalidFormat` from `String::toUnsignedInt` and `InvalidRange` from `ColorRGBA::stringToRGBA_` derive from `GeneralException`, the single catch clause covers both).
