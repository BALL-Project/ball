<objective>
Fix the read and write paths in `ColoringSettingsDialog` so `~/.BALLView` persists
only the element-color entries the user has explicitly customized — a diff against
the live compiled `ElementColorProcessor` defaults — under a new INI key
`ElementColorOverrides=`. On read, the legacy `Elements=` block is silently
discarded; the new key is parsed as a diff; an all-white override entry for any
of carbon/nitrogen/oxygen/phosphorus/sulphur is treated as corruption and dropped
so the compiled default flows through.

Purpose: structurally eliminates the bug class where a saved full-table `Elements=`
line silently shadows the compiled PyMOL palette — the persisted file no longer
contains a shadow copy of the defaults at all, so they cannot drift out of sync.
Resolves CONFIG-01 criteria 1 (defaults show through over existing config) and 2
(stale/partial detection → fallback).

Output: a single-file change to `source/VIEW/DIALOGS/coloringSettingsDialog.C`
implementing decisions D-01, D-03, D-05, D-06.
</objective>

INIFile upsert idiom (CANONICAL — apply wherever this plan writes `ElementColorOverrides=` to a non-cleared INIFile):
```
if (!inifile.insertValue("COLORING_OPTIONS", "ElementColorOverrides", value))
  inifile.setValue("COLORING_OPTIONS", "ElementColorOverrides", value);
```
Rationale: `insertValue` returns false if the key is already present (so it does NOT overwrite); `setValue` returns false if the key is absent (so it does NOT insert). The pair covers both cases. The mid-session Preferences-dialog-OK write path does not clear the INIFile before calling `writePreferenceEntries`, so a stale prior value WILL exist on the second write of a session — a bare `insertValue` is silently incorrect there. The pre-quit `MainControl::writePreferences` clears the file first (`source/APPLICATIONS/BALLVIEW/MainControl.C:634-635`), so the `insertValue` arm succeeds at quit; but the plan must be correct for both call sites.

INIFile delete-by-prefix idiom (CANONICAL — apply for removing a stale or legacy key by line scan):
```
LineIterator it = inifile.getSectionFirstLine("COLORING_OPTIONS");
LineIterator end = inifile.getSectionLastLine("COLORING_OPTIONS");
for (; it != end; ++it) {
  if (it->hasPrefix("<KEY>=")) { inifile.deleteLine(it); break; }
}
```
This is the documented `removeEntry`-equivalent — there is no single-call API; the scan is the contract.
