## CR-03 Fix Verification

**Claim (04.1-05-SUMMARY):** Per-token parse loop wrapped in `try/catch(Exception::GeneralException)`; string-length pre-check added before `ColorRGBA` construction.

**Evidence from codebase:**

Length pre-check at lines 295-300:
```cpp

{
    Log.warn() << "ColoringSettingsDialog: dropping malformed override token '"
               << tokens[t] << "' (color hex must be 6 or 8 chars)" << std::endl;
    continue;
}
```

Try/catch block at lines 304-317:
```cpp

ColorRGBA override_color;
try
{
    atomic_number = parts[0].toUnsignedInt();
    override_color = ColorRGBA(parts[1]);

{
    Log.warn() << "ColoringSettingsDialog: dropping unparseable override token '"
               << tokens[t] << "' (parse exception)" << std::endl;
```

The length pre-check fires before the `try` block — a string with incorrect length (e.g. 2 or 3 chars) is caught without reaching `ColorRGBA(parts[1])`, guarding the release-build undefined-behaviour buffer-overread documented in `colorRGBA.C:255-282`.

The file-scope anonymous-namespace helper (WR-03 closed) at lines 17-30:
```cpp

bool isKnownColoredElement(BALL::Position atomic_number) { ... }
```

Used at line 322 for the all-white sanity check: `if (isKnownColoredElement(atomic_number))`. No inline `std::set<Position> known_colored` construct remains.

**Status: CR-03 CLOSED.** Malformed tokens silently skip via `continue`; no exception propagates out of `readPreferenceEntries`; CONFIG-01 criterion 2 ("stale or partial saved color block falls back to compiled defaults") is satisfied.
