## Cache Step (verbatim)

```yaml
      # Phase 999.17 (BUILD-ACCEL-02): cache the Windows CMake build tree so warm-cache
      # Configure step skips the 2m32s vcpkg+CMake-configure rebuild when nothing
      # structural changed (CMakeLists.txt / cmake/** / vcpkg.json / CMakePresets.json).
      # Cache scope is the configure-output set ONLY — object files come from ccache,
      # not from this cache. Windows-only; macOS+Linux configure in <30s already.
      # ci.yml itself is NOT in hashFiles() — editing this comment triggers a warm run
      # that exercises the cache-HIT path without invalidating the cmake-tree key.
      - name: Cache Windows CMake build tree
        if: matrix.os == 'windows-x64'
        uses: actions/cache@v5
        with:
          path: |
            build/ci-windows/CMakeCache.txt
            build/ci-windows/CMakeFiles/
            build/ci-windows/build.ninja
            build/ci-windows/vcpkg_installed/
          key: ci-windows-cmake-tree-${{ hashFiles('CMakeLists.txt', 'cmake/**', 'vcpkg.json', 'CMakePresets.json') }}
          restore-keys: |
            ci-windows-cmake-tree-
```

## Cache Key Inputs and Scope

**hashFiles() structural inputs (4 files):**
1. `CMakeLists.txt` — drives configure shape
2. `cmake/**` — preset/module definitions
3. `vcpkg.json` — Windows package manifest
4. `CMakePresets.json` — ci-windows preset definition

**Cache path (4 entries — configure-output only):**
1. `build/ci-windows/CMakeCache.txt`
2. `build/ci-windows/CMakeFiles/`
3. `build/ci-windows/build.ninja`
4. `build/ci-windows/vcpkg_installed/`

NOT cached: `build/ci-windows/bin/` or object files (ccache handles compile artifacts).

## Fallback Decision

**Full scope retained (no fallback to vcpkg_installed-only).**

Warm-cache reduction: **57.7%** — above the ≥50% partial-success threshold documented in the PLAN and ROADMAP. The full scope (CMakeCache.txt + CMakeFiles/ + build.ninja + vcpkg_installed/) is retained.

The 57.7% reduction is below the ≥80% ideal target. The gap is explained by CMake's re-verification pass: even with a fully restored CMakeCache.txt and CMakeFiles/, CMake still re-checks all find_package() calls and compiler feature tests on a new runner instance. The vcpkg_installed/ directory is the largest portion of configure time (package discovery), and it IS in the cache — hence the 57.7% reduction. The remaining ~63s is CMake's incremental verification of the restored tree.

The restore-key prefix fallback (structural-change run, 76s) correctly demonstrates key invalidation: the exact key changed (CMakeLists.txt modified), the fallback restored the prior tree, and CMake re-verified. A new cache entry was saved under the new key (Post Cache Windows CMake build tree: 50s in run 25965469399).
