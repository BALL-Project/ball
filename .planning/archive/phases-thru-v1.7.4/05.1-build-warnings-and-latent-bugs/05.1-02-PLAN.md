<objective>
Fix BACKLOG.md Task **A2** — C4311 pointer truncation `T* -> long` on 64-bit Windows.

On 64-bit Windows (MSVC LLP64), `long` is 32 bits but pointers are 64 bits; casting
`T*` to `long` (or `unsigned long`) silently truncates the upper 32 bits, corrupting
pointer-as-identity uses (hash keys, dedup tables, identity comparison). Linux / macOS
(LP64) happen to work because `long` is 64-bit on those platforms — explains why CI was
green everywhere despite latent corruption.

**Per CONTEXT.md D-08 / Codex concern:** widening the cast alone is **not enough**.
`MMFF94StretchBend` uses `HashMap<long, Position>` and `long`-typed iterators downstream
of the cast — the storage and iterator types must also migrate to `std::uintptr_t` (or
BALL's existing `PointerSizeUInt` typedef at `include/BALL/COMMON/global.h:207`),
otherwise the truncation just moves one assignment site downstream. This plan therefore
runs an **end-to-end audit** of each cast chain, not just a cast-site rewrite.

The checkpoint (Task 2) confirms `std::uintptr_t` vs `PointerSizeUInt` after the audit
maps the downstream surface.

Purpose: BACKLOG.md task A2 (Codex-concern flagged for incompleteness; D-08 mandates
end-to-end audit). Severity: correctness on Windows — latent data corruption in MMFF94
force-field calculations.

Output: cast sites rewritten with `reinterpret_cast<std::uintptr_t>`, downstream
container / iterator types widened, header declarations adjusted to match.
</objective>
