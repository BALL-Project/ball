# Phase 05.1 Plan 07: Move BALL_EXPORT to definition site (C4910) Summary

## One-liner

Fixed MSVC C4910 (`extern template class BALL_EXPORT` is contradictory) by moving the
`BALL_EXPORT` (`__declspec(dllexport)`) attribute from the `extern template class`
declarations in `vector3.h` / `atom.h` to the single `template class` definition in the
matching `.C` file — the canonical C++ DLL-export pattern.

## What was done

Two BACKLOG tasks (B1 + B2) shared one fix pattern and landed together in commit
`d0f7261`.

### Task 1: B1 — `std::vector<Vector3>` and `TVector3<float>` (vector3.h / vector3.C)

Before — `extern template class BALL_EXPORT …;` in the header asked MSVC to both *not*
instantiate (extern) and *export* (dllexport) the same symbol, which is contradictory
(C4910). The matching `template class …;` definitions in `vector3.C` had no
`BALL_EXPORT`, so the actual instantiation was emitted unexported — clients of the DLL
could not link against it.

After:

```cpp
// include/BALL/MATHS/vector3.h:1145, 1148
extern template class std::vector<Vector3>;   // MSVC-only
extern template class TVector3<float>;

// source/MATHS/vector3.C:10, 13
template class BALL_EXPORT TVector3<float>;
template class BALL_EXPORT std::vector<Vector3>;   // MSVC-only
```

### Task 2: B2 — `std::vector<Atom*>` (atom.h / atom.C)

Before — `atom.h:1010` contained `template class BALL_EXPORT std::vector<Atom*>;`
*without* `extern`. Every TU including the header emitted a definition; MSVC's COMDAT
folding masked the duplication but slowed compile and was fragile.

After — header carries an extern declaration only; the single `BALL_EXPORT`-decorated
definition lives in `atom.C`:

```cpp
// include/BALL/KERNEL/atom.h:1010 (under #ifdef BALL_COMPILER_MSVC)
extern template class std::vector<Atom*>;

// source/KERNEL/atom.C (new line at namespace scope, under #ifdef BALL_COMPILER_MSVC)
template class BALL_EXPORT std::vector<Atom*>;
```

The `atom.C` definition is placed at namespace `BALL` scope just before the closing
`} // namespace BALL`, immediately after the existing
`# ifdef BALL_NO_INLINE_FUNCTIONS` include block. This matches the file's convention
(implementation at namespace scope, definitions consolidated near the bottom).
