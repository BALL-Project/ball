# Phase 5.1: Build Warnings & Latent Bug Cleanup — Context

**Source:** This phase was scoped end-to-end in
[`05.1-BACKLOG.md`](05.1-BACKLOG.md) before planning. The backlog has per-task
fix proposals, Codex CLI verdicts, file paths with line numbers, and severity
classification. The planner treats BACKLOG.md as the authoritative scope
document; this CONTEXT.md only locks decisions about *how to organize the
work*, not what the work is.

<domain>
## Phase Boundary

Remove the latent bugs and tame the warning surface that Phase 4's CI matrix
(run [25899905204](https://github.com/BALL-Project/ball/actions/runs/25899905204),
2026-05-15) surfaced once it reached green on macOS / Linux / Windows.

**In scope (Tier A — real bugs):**
- A1: C4717 `getline` infinite recursion in `string.iC`
- A2: C4311 pointer truncation `T* → long` on 64-bit Windows (hash, MMFF94, triangulatedSurface)
- A3: `-Wself-assign-field` in `pairExpInteractionEnergyProcessor.C`
- A4: `-Wtautological-constant-out-of-range-compare` in `representation.C`
- A5: `-Wformat-overflow` in CIF parser (sprintf → snprintf)
- A6: `-Wstringop-truncation` audit of `strncpy` sites

**In scope (Tier B — Windows DLL hygiene):**
- B1: C4910 `extern template class BALL_EXPORT` mismatch in `vector3.h`/`vector3.C`
- B2: Mirror B1 fix in `atom.h`/`atom.C`
- B3: Broaden C4251 `#pragma warning(disable: 4251)` in `global.h` (only after B1 lands and we re-measure)
- B4: C4996 `BALL::GeneticIndividual` deprecation noise (5 instances)
- B5: C4834 discarded `[[nodiscard]]` return in `regressionModel.C:258`

**In scope (Tier D — build configuration):**
- D1: Qt5LinguistTools missing on Windows vcpkg
- D2: Node.js 20 deprecation in GitHub Actions
- D3: Linux ccache cache-save tar failure (diagnosis-first)
- D5: BALLView.app Info.plist has empty bundle identity (Phase 8 prerequisite)
- D4-mac: already landed pre-phase (release.yml ad-hoc resign)
- D4: Windows release workflow `LNK1104: tbb12_debug.lib` (`--config Release` missing)

**In scope (BACKLOG bookkeeping):** D6 from BACKLOG.md (vcpkg.json missing
`qttools` — root cause of D1's `windeployqt` / `lupdate` / `lrelease`
silently skipped on Windows) is folded into Plan 10 (D1). Plan 10's
preferred option (a) — add `qttools` to `vcpkg.json` — resolves D6 at the
same time. No standalone D6 plan; the relationship is documented here per
plan-checker CONCERN-2.

**Out of scope (Tier C — defer to after Phase 5 lands):**
- `-Wdeprecated-copy` (gcc, 2488 instances)
- `-Wunqualified-std-cast-call` (clang, 1166 instances)
- `-Wdeprecated-declarations` (gcc+clang, 1709 — most vanish with Qt 6 in Phase 5)
- `-Wcatch-value`, `-Wsign-compare`, `-Wreorder`, `-Wwrite-strings`,
  `-Wunused-*` — mechanical bulk cleanup deferred
- Bison `-Wconflicts-sr` grammar conflicts (CIF parser) — separate investigation

**Requirements:** None — this phase has no formal REQ-IDs in
[`REQUIREMENTS.md`](../../REQUIREMENTS.md). The work is enumerated by the
Phase 4 CI warning census in BACKLOG.md, not by REQ-tracked deliverables.

<decisions>
## Implementation Decisions

### Plan structure
- **D-01:** **One plan per Tier-A task** (A1-A6). Each is a discrete bug fix
  with a small blast radius; bundling them into one plan would lose the
  surgical traceability that makes them easy to review and revert
  individually if needed.
- **D-02:** **One plan for Tier-B B1+B2** (sequenced — B2 mirrors the same
  fix pattern as B1, must land in the same plan to avoid leaving the
  codebase half-converted). B3 is its own plan, gated on B1+B2 measurement
  (the C4251 count may drop materially once `extern template` exports are
  honest). B4 and B5 are tiny and bundle into one "Tier-B cosmetic" plan.
- **D-03:** **One plan per Tier-D task** (D1, D2, D3, D5, D4 release/ci).
  These are independent build-system or workflow edits that touch distinct
  files; co-mingling them would muddle CI verification.
- **D-04:** **No Tier-C work in this phase.** Mass cleanup of style noise
  (`-Wdeprecated-copy`, `-Wunqualified-std-cast-call`, `-Wcatch-value`,
  etc.) is deferred to a future phase after Qt 6 lands in Phase 5 and
  strips the bulk of `-Wdeprecated-declarations`.

### Sequencing
- **D-05:** **Tier A and Tier D fixes can run in parallel** (independent
  files, no shared state). Wave 1 = A1, A2, A3, A4, A5, A6, B1+B2, B4+B5,
  D1, D2, D3, D5, D4.
- **D-06:** **B3 is wave 2**, depends on B1+B2 landing and a re-measure of
  the C4251 count. The decision tree: if C4251 count drops materially
  after B1+B2, B3 may be reduced in scope or skipped; if it stays at
  ~3495, the project-wide `#pragma warning(disable: 4251)` lands as
  planned.

### Verification
- **D-07:** **CI matrix is the verification oracle.** A successful Phase 5.1
  is a CI run that emits zero of the listed C4717, C4311, C4910,
  `-Wself-assign-field`, `-Wformat-overflow`,
  `-Wtautological-constant-out-of-range-compare`, C4834, and (post-B3)
  C4251 warnings on the matched files. CI run number to be recorded in
  each plan's SUMMARY.md.
- **D-08:** **A2 (C4311) requires end-to-end audit, not just cast-site
  changes.** Codex flagged that `HashMap<long, Position>` and `long`-typed
  iterators must also migrate to `std::uintptr_t` / BALL's
  `PointerSizeUInt` typedef (`global.h:207`). Plan A2 explicitly includes
  this downstream audit in scope — the cast-site fix alone is rejected by
  this decision.
- **D-09:** **A4 (tautological compare) preserves the meaningful half of the
  check.** `DrawingPrecision` has `DRAWING_PRECISION_INVALID = -1`, so the
  `< 0` half is meaningful; `DrawingMode` has only non-negative
  enumerators, so its `< 0` half is what's tautological. The cleaner
  alternative — adding `INVALID = -1` to `DrawingMode` — is in scope for
  Plan A4 if reading the enum definitions during implementation suggests
  it.
- **D-10:** **D5 (CFBundleIdentifier) defers the canonical-ID-string
  decision to plan-time.** Three candidate strings are listed in
  BACKLOG.md; Plan D5 must choose one and document the rationale.
  Recommended default: `de.uni-tuebingen.ball.ballview` (institutional
  reverse-DNS).

### Codex CLI cross-check provenance
- **D-11:** **Tasks A1, A2, A3, A4, B1, B2 carry a Codex-CLI verdict.** Plan
  acceptance criteria must preserve the Codex-flagged concerns: A2 audit
  scope (D-08 above), A4 asymmetric check preservation (D-09 above).
  Tasks A5, A6, B3, B4, B5, D1-D5 were not Codex-checked and rely on the
  fix proposals in BACKLOG.md plus standard implementation judgement at
  plan time.

</decisions>

<specifics>
## Specific Ideas

- **CI verification:** every plan's verification step is "push to PR
  branch, watch CI matrix run, assert the targeted warning category drops
  to zero on the matched files." The
  [25899905204](https://github.com/BALL-Project/ball/actions/runs/25899905204)
  baseline run gives the pre-fix counts.
- **Granularity is intentional.** ~12-14 plans for this phase is the
  target. Each plan is a small, reviewable, individually-revertable
  change. The phase as a whole is a janitorial sweep, not a tightly
  coupled feature.

</specifics>
