<objective>
Fix BACKLOG.md Task **D5** — BALLView.app Info.plist has empty CFBundleIdentifier (and
other bundle-identity fields). This is a **Phase 8 prerequisite**: Apple notarization
(`notarytool`) REQUIRES a non-empty `CFBundleIdentifier`; Apple Developer ID code-signing
validates the identifier against the cert's authorized bundle IDs. Without this fix,
Phase 8's signed + notarized macOS pipeline cannot ship.

Forensic state (confirmed against v1.6.0 release artifact):

    <key>CFBundleIdentifier</key><string></string>
    <key>CFBundleShortVersionString</key><string></string>
    <key>CFBundleVersion</key><string></string>
    <key>CFBundleName</key><string></string>
    <key>CFBundleLongVersionString</key><string></string>
    <key>CFBundleGetInfoString</key><string></string>
    <key>NSHumanReadableCopyright</key><string></string>

All bundle-identity fields are empty strings — the Info.plist template exists but the
CMake variables that fill it (`MACOSX_BUNDLE_BUNDLE_NAME`,
`MACOSX_BUNDLE_GUI_IDENTIFIER`, `MACOSX_BUNDLE_BUNDLE_VERSION`, etc.) aren't set on the
BALLView target.

Fix: set the `MACOSX_BUNDLE_*` properties on the BALLView CMake target.

**Per CONTEXT.md D-10:** Three candidate CFBundleIdentifier strings; this plan must
choose one and document the rationale. Recommended default:
`de.uni-tuebingen.ball.ballview` (institutional reverse-DNS).

Plan is non-autonomous because the canonical-identifier choice is a load-bearing
project-policy decision that the maintainer should confirm — once distributed, the
identifier is hard to change (macOS preferences, sandbox identity, launch-services entries
all key off it).

Not Codex cross-checked.

Purpose: BACKLOG.md task D5.
Output: `set_target_properties(BALLView PROPERTIES MACOSX_BUNDLE_* ...)` block in the
correct CMake file; the chosen CFBundleIdentifier embedded.
</objective>

  <context>
    Per CONTEXT.md D-10, this is a plan-time decision that must be made before the CMake
    edit lands. The identifier is load-bearing — distributed bundles key macOS preferences,
    sandbox identity, code-signing identity persistence, and LaunchServices "Open With"

    The recommended default is `de.uni-tuebingen.ball.ballview` (BALL originated at
    Universität Tübingen). The other candidates match the GitHub org (`BALL-Project`).

    Apple's reverse-DNS convention says the TLD-first portion should reflect the entity
    that owns the bundle. For an academic project hosted on GitHub but originated at a
    university, either institutional or org-based is defensible.
