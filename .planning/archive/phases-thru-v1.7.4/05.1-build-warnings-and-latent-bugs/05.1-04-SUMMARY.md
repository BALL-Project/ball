# Phase 05.1 Plan 04: -Wtautological-constant-out-of-range-compare in representation.C Summary

Drop the three tautological halves of the value-range check in `Representation::isValid()`
(`drawing_precision_ > BALL_VIEW_MAXIMAL_DRAWING_PRECISION`,
 `drawing_mode_ > BALL_VIEW_MAXIMAL_DRAWING_MODE`, and `drawing_mode_ < 0`) while preserving
the meaningful `drawing_precision_ < 0` sentinel check per CONTEXT.md D-09.

## What Changed

`source/VIEW/KERNEL/representation.C:269-271` — the original four-half value-range check inside
`Representation::isValid()`:

```cpp
if (drawing_precision_  < 0 || drawing_precision_ > BALL_VIEW_MAXIMAL_DRAWING_PRECISION ||
    drawing_mode_       < 0 || drawing_mode_      > BALL_VIEW_MAXIMAL_DRAWING_MODE ||
    transparency_       > 255)
```

is now:

```cpp
if (drawing_precision_ < 0 ||
    transparency_ > 255)
```

A 6-line comment block above the conditional records the rationale for each dropped half so
future readers don't reintroduce the warning.

## Enum-Asymmetry Confirmation

Per `include/BALL/VIEW/KERNEL/common.h`:

| Enum             | Enumerators       | INVALID sentinel              | `< 0` check meaning  | `> MAXIMAL` check meaning              |
| ---------------- | ----------------- | ----------------------------- | -------------------- | -------------------------------------- |
| DrawingPrecision | 0, 1, 2, 3 (+ -1) | `DRAWING_PRECISION_INVALID=-1`| **Meaningful**       | Tautological (max enum 3 < macro 4)    |
| DrawingMode      | 0, 1, 2, 3        | none                          | Tautological         | Tautological (max enum 3 < macro 4)    |

The CONTEXT.md D-09 reading was correct that DrawingPrecision's `< 0` half is the load-bearing
one. The plan's mechanical instruction — "drop only the `drawing_mode_ < 0 ||` portion" — did
NOT match the actual clang warnings, which were on the `> MAXIMAL` upper bounds, not the
`< 0` halves. The fix dropped all three tautological halves to satisfy
`must_haves.truths` line "clang emits zero `-Wtautological-constant-out-of-range-compare`
warnings on representation.C".

## Decisions Made

- **Option A (drop tautological halves) chosen over Option B (add DRAWING_MODE_INVALID = -1).**
  Option B would have required adding a new enumerator to a public-API enum in
  `include/BALL/VIEW/KERNEL/common.h`, triggering a header-recompile cascade across every
  callsite that includes it (the entire VIEW layer) and introducing risk of breaking any
  iteration that assumes `for (int i = 0; i < N; ++i)` covers all valid values. Option A is
  6 deleted tokens plus a comment block — strictly smaller blast radius and no API surface
  change. The "cleaner symmetric" framing of Option B in BACKLOG.md does not outweigh the
  cost when the asymmetric drop satisfies the same must_haves criteria.

- **DRAWING_PRECISION_INVALID = -1 sentinel check preserved.** This is the meaningful
  defensive check — without it, an explicitly-invalidated DrawingPrecision would silently
  read as valid. The comment block above the conditional now states this contract explicitly
  so future cleanup passes don't strip it as part of a broader warning sweep.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Plan misidentified the tautological halves**

- **Found during:** Task 1 (post-edit verification rebuild).
- **Issue:** The plan and BACKLOG.md Task A4 named the `< 0` halves as the tautological
  warnings clang was emitting on `representation.C:269-270`. A force-rebuild after the
  initial Option A edit (which dropped only `drawing_mode_ < 0`) showed that clang's
  `-Wtautological-constant-out-of-range-compare` warnings were actually on the `> 4`
  upper-bound halves of BOTH enums — because `BALL_VIEW_MAXIMAL_DRAWING_PRECISION` and
  `BALL_VIEW_MAXIMAL_DRAWING_MODE` are both `4`, while the largest enumerator in each enum
  is `3` (DRAWING_PRECISION_ULTRA / DRAWING_MODE_TOON). The `< 0` halves did not trip the
  warning because clang accepts the comparison `unsigned-ish enum < int literal 0` without
  flagging it. The plan's mechanical edit, executed verbatim, would have left both
  pre-existing clang warnings in place — violating the binding success criterion
  `must_haves.truths` line "clang emits zero `-Wtautological-constant-out-of-range-compare`
  warnings on representation.C".
- **Fix:** Extended Option A to drop the two tautological upper-bound halves as well as the
  tautological `drawing_mode_ < 0` half. Preserved the meaningful `drawing_precision_ < 0`
  sentinel check. The 6-line comment block above the conditional records all three reasons.
- **Files modified:** `source/VIEW/KERNEL/representation.C` (the same single-file edit, with
  scope extended from 1-token deletion to 3-half deletion).
- **Commit:** `932bd27`.
