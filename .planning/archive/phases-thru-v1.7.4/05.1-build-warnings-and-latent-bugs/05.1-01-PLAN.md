<objective>
Fix BACKLOG.md Task **A1** — C4717 `getline` infinite recursion in `string.iC`.

The two `getline(istream&, BALL::String&&, ...)` overloads call
`getline(is, move((string&)str), ...)`. No `std::getline(istream&, std::string&&, ...)`
exists in the standard, so overload resolution selects the being-defined `BALL::String&&`
overload (via the non-explicit `BALL::String(string&& s)` ctor at `string.h:161`) and
the function recurses on itself forever. MSVC catches this as C4717; gcc/clang produce
the same recursion silently.

The fix is to drop `move()` so the call falls into the existing `std::getline(istream&,
std::string&, ...)` standard overload — which fills `str_` in place via the
`(string&)str` cast invoking `String::operator string&()`. The matching lvalue overloads
at lines 1748-1757 already use exactly this pattern.

Purpose: BACKLOG.md task A1 (Codex-verified, severity: correctness — guaranteed stack
overflow if anyone calls `std::getline(stream, std::move(some_BALL_String), ...)`).

Output: 4 `move(` token removals across `include/BALL/DATATYPE/string.iC` lines 1761 and 1767.
</objective>
