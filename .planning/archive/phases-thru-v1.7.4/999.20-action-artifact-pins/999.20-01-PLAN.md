**Note re Phase 999.19:** If 999.19 ships its 3 new ninja-log upload-artifact steps BEFORE 999.20, this plan picks them up in the same v4→v6 sweep — 999.19 lands on v4 (current pin), 999.20 sweeps everything to v6 in one commit. If 999.20 lands FIRST, 999.19's new steps will be authored on v6 directly. Either order works; record actual order in SUMMARY.md.

**v4→v6 upload-artifact breaking changes (from [actions/upload-artifact CHANGELOG](https://github.com/actions/upload-artifact/blob/main/CHANGELOG.md)):**
- **v5 (intermediate):** removed `actions-runner-controller` self-hosted special-case; uses Node 20 runtime.
- **v6:** added **artifact immutability by default** (can't overwrite an artifact name with a second push in the same run — must use unique names or set `overwrite: true`). This is the BIG one. BALL uses `${{ github.sha }}` in artifact names (per existing pattern + 999.19's `ninja-log-{platform}-{sha}`), so name collisions are unlikely — but verify on the test CI run.
- Default retention is workflow-config-driven (was 90 days; honored from repo settings now).

**v4→v7 download-artifact breaking changes:**
- **v7:** requires upload-artifact ≥ v6 producer (compatibility matrix). Cross-workflow downloads via `github-token` parameter unchanged.
- The single `ci.yml:L734` and `release.yml:L353` download sites both pull from prior same-run uploads, so cross-workflow compatibility isn't tested here — straightforward bump.

**Per-bump CI validation:**
1. After upload@v6 commit, push + verify CI green AND verify uploaded artifacts are downloadable from the GH Actions UI on each platform (no silent corruption).
2. After download@v7 commit, push + verify CI green AND verify the `gh run download` flow still works.

**Rollback contract:** if either bump turns the CI red and the failure is action-version-related (not coincidental), revert that ONE commit with `git revert` (NOT `git reset --hard`), then file an investigation backlog stub for v1.6.3. Don't bundle both bumps into a single commit — the whole point of the two-commit shape is bisect-friendliness.
