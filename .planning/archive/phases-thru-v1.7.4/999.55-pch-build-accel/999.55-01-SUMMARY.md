# Phase 999.55 Plan 01: Test-suite PCH (REUSE_FROM) Summary

**The 298 `*_test.C` executables now reuse libBALL's / libVIEW's precompiled header via `target_precompile_headers(<test> REUSE_FROM BALL/VIEW)` — PIC-matched to the SHARED-lib PCH and AppleClang-guarded — closing the test-suite half of the v1.7.x-09 PCH scope that 999.16 left untouched.**

## Accomplishments

- Wired `TARGET_PRECOMPILE_HEADERS(${test} REUSE_FROM BALL)` inside the BALL class-test `FOREACH` and `REUSE_FROM VIEW` inside the VIEW-test `FOREACH`, each paired with `SET_TARGET_PROPERTIES(${test} PROPERTIES POSITION_INDEPENDENT_CODE ON)` and wrapped in `IF(NOT CMAKE_CXX_COMPILER_ID STREQUAL "AppleClang")` — mirroring the 999.16 library wiring exactly.

## Decisions Made

- **VIEW tests reuse the VIEW PCH** (not BALL's): VIEW tests link both BALL and VIEW, and the VIEW PCH is the larger superset for GUI TUs.
- **No new header audit:** REUSE_FROM inherits the 999.16 audited 21-header (BALL) / 23-header (VIEW) sets verbatim, per plan scope.
- **No CMakeLists.txt / ci.yml change:** the library PCH and the `CCACHE_SLOPPINESS` contract already shipped in 999.16; the contract already covers the REUSE_FROM-produced PCH objects.
- **Post-PCH measurement deferred to CI:** the local executor runs on macOS (AppleClang) where the guard skips PCH, so the test-build PCH path is not exercisable locally. Post-PCH cells in the measurement table are marked "pending CI run `<id>`" rather than fabricated.

## Issues Encountered

- The existing local `build/` tree uses `/usr/bin/c++` = Apple clang 21.0.0, so the AppleClang guard intentionally skips PCH on this Mac. This is the expected, documented behavior: local validation confirms the guard gates the REUSE_FROM block OFF correctly (no `cmake_pch` artifacts, clean configure, clean test builds). The actual PCH-on-tests REUSE_FROM build path (and its measurement) is exercised by the Linux / Windows CI runners — the cross-platform oracle — not local macOS.
