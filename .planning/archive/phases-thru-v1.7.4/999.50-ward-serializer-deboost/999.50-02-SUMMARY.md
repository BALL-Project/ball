# Phase 999.50 Plan 02: release.yml ccache reuse + MSVC /O1 fallback decision Summary

**Added per-OS ccache build-cache restore/save to `release.yml` with a key lineage shared with `ci.yml`, plus a new job-level `CCACHE_*` env block on the package job — so a release tag of an already-CI-built commit warms from CI's compiler cache instead of building cold; the optional MSVC `/O1` escape hatch (item ③) was intentionally skipped as moot since Plan 01's boost elimination already dropped the heavy TU to ~3.9s.**

## Accomplishments

### Task 1 — ccache reuse in release.yml (BUILD-ACCEL-07 / item ②)
- Created a NEW job-level `env:` block on the `package` job (it had none — verified) carrying `CCACHE_SLOPPINESS: "pch_defines,time_macros,include_file_mtime"` and `CCACHE_EXTRAFILES: "${{ github.workspace }}/include/BALL/CONFIG/config.h.in"`, copied verbatim from `ci.yml` so ccache hits actually land under PCH / `PROJECT VERSION` bumps instead of silently busting.
- Added a `Restore ccache` step (`actions/cache/restore@v5`, id'd) BEFORE the Configure step and a `Save ccache` step (`actions/cache/save@v5`) AFTER the Build step for each of macOS, Linux, Windows — gated on the same per-OS `if:` condition the surrounding steps use, and the save gated `if: always() && <os-cond> && steps.<id>.outputs.cache-hit != 'true'` (mirroring the file's vcpkg split-cache pattern).
- Cache `path` matches ci.yml's per-OS dirs exactly: macOS `~/Library/Caches/ccache`, Linux `~/.cache/ccache`, Windows `C:\Users\runneradmin\AppData\Local\ccache`.
- Cache key aligned with ci.yml's lineage: `key: ccache-${{ matrix.os }}-pch-v2-${{ github.sha }}` with `restore-keys: ccache-${{ matrix.os }}-pch-v2-` then `ccache-${{ matrix.os }}-`. release.yml's `matrix.os` strings (`macos-arm64` / `linux-x64` / `linux-arm64` / `windows-x64`) are identical to ci.yml's, so the keys line up directly and a same-SHA or most-recent CI cache is reusable.
- No `CMAKE_<LANG>_COMPILER_LAUNCHER` wiring added — the `ci-*` presets already set it. No other functional change to release.yml.
- Added Phase 999.50 / BUILD-ACCEL-07 (item ②) comments on the env block and each ccache step, matching the file's heavily-commented style.

### Task 2 — MSVC /O1 escape hatch (item ③): intentionally skipped as moot
- Consulted Plan 01's SUMMARY first (this plan is wave 2 / depends_on ["01"]): the boost::serialization elimination dropped `poseClusteringSerialization.C` from tens of minutes to **~3.9s**. No TU profiles pathologically on MSVC anymore.
- The maintainer spec (`v1.7.2-BUILD-ACCEL-PLAN.md` item ③) itself states the fallback is "largely moot once ① lands."
- Decision: SKIP item ③. `source/DOCKING/COMMON/sources.cmake` left **unchanged** — no `set_source_files_properties(... COMPILE_OPTIONS "/O1")` block was added. `/O1` is NOT active anywhere by default. This is the acceptable "OR" branch of Task 2's acceptance criteria (file unchanged + skip documented here).
