# Phase 999.50 Plan 01: Ward Serializer De-boost Summary

**Eliminated boost::serialization from the PoseClustering Ward cluster-tree serializer, replacing four boost archive flavors + adj_list serialization + ClusterProperties::serialize with a hand-rolled "BALLWARD" magic+version format — the single-TU compile drops from tens of minutes to ~4 seconds.**

- **Duration:** ~18 min
- **Completed:** 2026-05-21
- **Tasks:** 3 / 3
- **Files modified:** 4 (1 SUMMARY created)

## Accomplishments
- Rewrote `poseClusteringSerialization.C` as a boost-free, hand-rolled magic+version-headed reader/writer over the trivial Ward-tree payload (graph order, root bundle, per-vertex poses/size/merged_at, edge list). No `boost::archive`, `boost/serialization`, or adjacency-list serialization remains.
- Deleted the `ClusterProperties::serialize` template member from the header and the `.C` file. Public API and the `bool binary` flag are byte-identical.
- Old/wrong files now fail loudly via `Exception::InvalidFormat(__FILE__, __LINE__)` on a leading magic/version mismatch instead of silently mis-parsing.
- Regenerated `test/data/PoseClustering_wardtree.dat` in the new TEXT format (246 bytes, ASCII) by redirecting the existing test3:312 serialize call and then reverting — re-verified the fixture-read CHECK before commit.
- Documented the on-disk format break under a v1.7.2 "Breaking changes" heading in `RELEASE-NOTES-v1.7.md`.
- Both PoseClustering tests pass; both TOOLS callers compile/link unchanged; the graphviz sibling TU is untouched.

## Code Review Fixes

A standard-depth review (`999.50-REVIEW.md`) found 1 Critical + 5 Warnings + 3 Info. Applied in two follow-up commits (`f83d7b33c5` serializer/header, `23103d1039` fixture):

- **CR-01 (Critical) — read-path hardening (binary + text):** every read (counts, set elements, size, merged_at, edge endpoints, version token, binary width/byte-order header) is now followed by a stream-state check that throws `Exception::InvalidFormat(__FILE__, __LINE__, …)` on truncation/parse failure. Top-level counts (graph order, num_edges, per-vertex pose count) are bounded against a sanity ceiling (`1e8`, plus pose-count ≤ order) BEFORE any loop/allocation, so a corrupt/byte-swapped count word fails loudly instead of driving an unbounded allocation/hang. Every edge endpoint and the root index are validated `< order` before `boost::add_edge` / setting the graph_bundle root (out-of-range descriptors are UB for the vecS adjacency_list); empty trees (order 0) are rejected.
- **WR-03 (load-bearing) — exact text float round-trip:** the text writer now emits `merged_at` at `std::numeric_limits<float>::max_digits10` (9) precision, restoring the prior precision afterward. merged_at drives `extractClustersForThreshold`'s threshold comparisons and `getClusterScore`, so 6-digit precision could flip the partition.
- **WR-04 — text version-token stream check:** after `in >> magic >> version` the reader checks `!in` and throws a truncation/parse `InvalidFormat` before interpreting `version` (no more misleading "unsupported version 0").
- **WR-02 — binary width/endianness safety:** binary format bumped to **version 2**; the binary header records `sizeof(Size)/sizeof(Index)/sizeof(float)` plus a little-endian byte-order marker, and the reader throws `InvalidFormat` on any width or byte-order mismatch (detect-and-throw, no byte-swapping — no supported platform is big-endian). The committed fixture is TEXT, so the binary header change does not affect it. The inaccurate "fixed-width, host byte order" comment (WR-01) was replaced with an accurate non-portability note.
- **IN-01 — Doxygen:** `serializeWardClusterTree`/`deserializeWardClusterTree` docs now describe the BALLWARD magic+version format, the `binary` parameter, and the `@throw Exception::InvalidFormat` conditions (no longer "boost::serialize format").
- **IN-02 (trivial) — magic buffer:** read buffer sized exactly to `POSECLUSTERING_WARD_MAGIC_LEN` and zero-initialized (removes the uninitialized 16-byte tail).
- **IN-03 (trivial) — write-error check:** `serializeWardClusterTree` checks `!out` after emitting the payload and throws on a write failure.

**Intentionally skipped:**
- **WR-01 (byte-swap support):** out of scope — detect-and-throw is the proportionate fix per the brief; the inaccurate comment was corrected and the WR-02 marker covers the latent hazard.
- **WR-05 (`release.yml` cache-hit save gate):** the gate mirrors `ci.yml`/vcpkg intentionally; left as-is per the brief (not touched in this pass).
