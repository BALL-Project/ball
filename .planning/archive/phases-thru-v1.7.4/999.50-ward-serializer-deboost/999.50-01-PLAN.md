<objective>
Eliminate `boost::serialization` from the Ward cluster-tree serializer — the single
heaviest Boost component to compile and the bulk of the (already-quarantined)
`poseClusteringSerialization.C` cost. Replace the four boost archive flavors
(binary/text × in/out) + `adj_list_serialize.hpp` + `ClusterProperties::serialize`
with a hand-rolled, magic+version-headed reader/writer for the trivial payload the
tree actually holds. Keep the public API and the `bool binary` flag identical; only
the on-disk format changes.

This is maintainer plan item ① (the lead item / the real Windows-build-time killer)
plus its required format-break follow-through (fixture regen + RELEASE-NOTES).

Purpose: Drop that TU's compile from tens of minutes to ~seconds, removing the
boost::serialization template-instantiation cost from the build entirely.
Output: A boost-free serializer, a regenerated new-format fixture, callers still
building, tests green, and the format break documented.
</objective>

        (parent_index, child_index) pair of vertex indices.

    `order` times into a freshly-cleared cluster_tree_ (clear/assign an empty ClusterTree first so a reused
    object does not accumulate stale vertices), filling each vertex's ClusterProperties (poses/size/merged_at);
    read the edge count and for each call boost::add_edge(parent, child, cluster_tree_); finally set
    cluster_tree_[boost::graph_bundle] = root. Because ClusterTree uses vecS for vertices, add_vertex returns
    descriptors 0..order-1 in order, so stored integer indices map directly to descriptors — no remapping.

    Binary variant: write/read the fixed-width fields with stream write/read of the raw object bytes
    (ostream::write / istream::read over the integer/float values and each set element). Text variant:
    write whitespace-separated decimal tokens via operator<< / operator>>, one logical record per the layout
    above, so the output is plain ASCII (the committed fixture is ASCII text — keep it that way). Both variants
    MUST share the same logical header and the same field ordering so the only difference is the encoding of the
    scalars (and the header byte-vs-token form noted above). Match CLAUDE.md conventions: modeline header already
    present, 2-space indent, Allman braces, `namespace BALL`, BALL::Exception with __FILE__,__LINE__. Do not add
    center/eigen serialization (leave the existing TODO intent — center stays unserialized). Update the file's top
    comment to state the TU now uses a hand-rolled format and no longer instantiates boost archives.
