**Categorization rubric (each item → exactly one of 5):**
1. **close-as-fixed** — Resolved by a specific landed commit/PR in v1.6-modernization. MUST cross-reference the fix commit before closing.
2. **close-as-obsolete** — Targets abandoned subsystem or pre-Qt6 / pre-C++17 code path that no longer exists. Examples: SIP-bindings issues (Phase 6 will pick new generator), QGLWidget path issues, ball_contrib-tree refs.
3. **close-as-stale** — No activity ≥ 3 years AND not on v1.6/v2.0 critical path. Templated close invites reopening with current reproducer.
4. **keep** — Still actionable; label with target milestone (v1.6.x / v1.7 / v2.0).
5. **needs-investigation** — Can't confidently categorize; park for follow-up triage round.

**Templated close comments (from ROADMAP):**
- **fixed:** `"This was resolved by the v1.6 modernization work. Specifically: {commit-hash} ({short-message}) in Phase {N}. Closing as fixed — please reopen with a reproducer against v1.6-modernization if the issue persists."`
- **obsolete:** `"This targets {subsystem}, which was {removed | replaced} during Phase {N}. {subsystem} is no longer part of the build. Closing as obsolete. If similar functionality exists elsewhere in BALL today, please file a new issue against the current code."`
- **stale:** `"Closing as stale (no activity since {date}, more than 3 years). If this is still relevant against current v1.6-modernization, please reopen with a fresh reproducer and we'll triage promptly."`

**Out-of-triage-scope items (DO NOT touch in this phase):**
- Re-categorize already-closed issues — open items only.
- Items with active comments in last 90 days regardless of category (user is engaged; needs human judgment).
- Per-PR merge work in the "keep" category that isn't part of the named 5-PR bundle (subsystem owners handle those).
