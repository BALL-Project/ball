<interfaces>
**Today's trigger block (ci.yml lines ~1-22):**
- `on: push:` matches all branches with no path filter — every push starts the matrix.
- `concurrency: group: ci-${{ github.ref }} cancel-in-progress: true` (lines 19-21) — newer push cancels older same-branch runs.

**Target shape:** add `paths-ignore:` at the trigger level so the workflow doesn't run AT ALL for docs/planning-only pushes. The concurrency rule keeps its behavior (when the matrix DOES run, cancel obsolete).

**paths-ignore set (do NOT trigger CI):**
- `.planning/**` (all planning artifacts, audit docs, MILESTONE-CONTEXT, ROADMAP, REQUIREMENTS, PYBALLV2/KERNELV2)
- `**/*.md` (all markdown files — READMEs, doc updates) **EXCEPT** workflow-relevant ones; consider negation if needed
- `doc/**` (BALL doc tree — Doxygen sources, tutorials, LaTeX)
- `RELEASE-NOTES-*.md` (release notes drafts — not build-relevant)

**paths-ignore antipatterns (DO trigger CI):**
- `CMakeLists.txt`, `cmake/**`, `CMakePresets.json`, `vcpkg.json` — build system inputs
- `source/**`, `include/**` — code
- `.github/workflows/**` — workflow changes themselves must trigger CI (otherwise we can't validate workflow edits)

**Gotcha — paths-ignore semantics:** GitHub Actions only skips when ALL changed files match the ignore list. A mixed push (e.g., one .md change + one .C change) still triggers CI. This is the desired behavior — better to over-trigger than to miss code changes.
</interfaces>
</context>

    ```yaml
    on:
      push:
        branches:
          - v1.6-modernization
          - main
        # Phase 999.18 (BUILD-ACCEL-03): skip CI on docs/planning-only pushes.
        # Mixed pushes (any code file + any docs file) still trigger CI per
        # GitHub Actions paths-ignore semantics — only all-match-ignore skips.
        paths-ignore:
          - '.planning/**'
          - 'doc/**'
          - '**/*.md'
          - 'RELEASE-NOTES-*.md'

        paths-ignore:
          - '.planning/**'
          - 'doc/**'
          - '**/*.md'
          - 'RELEASE-NOTES-*.md'
    ```

    DO NOT touch `.github/workflows/release.yml` — release tags should always run, not be filtered.
