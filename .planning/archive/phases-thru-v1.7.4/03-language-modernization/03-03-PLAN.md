    1. Configure and build BALL/VIEW/BALLView from a clean build directory following
       `BUILD-macos.md` exactly.
    2. For EVERY compile error or hard failure, fix it IN-PHASE (D-07 explicitly scopes
       "fix whatever the C++17 build surfaces" into this phase — not just the 7 known
       files). Use the same idioms as Plan 01:
       - Removed STL adapters (`std::unary_function`/`binary_function`/`bind2nd`/
         `mem_fun`/`mem_fun_ref`) → drop the base class / rewrite as a lambda.
       - `std::not1`, `std::not2`, `std::ptr_fun` → fold into a lambda.
       - Removed dynamic exception specifications (`throw()` on a function) → replace
         with `noexcept` or remove.
       - `std::iterator` deprecation → spell out the member typedefs or restructure.
       - `std::result_of` → `std::invoke_result`.
       - `std::auto_ptr` → `std::unique_ptr` (grep says none exist, but if the build
         finds one, this is the fix).
       Match each fix to the construct; keep behaviour identical.
    3. **Deprecation-noise discretion (D-06 fallback):** Plan 02 removed the blanket
       `-Wno-deprecated-declarations`. If the build log is now flooded with Qt 5.15
       deprecation warnings (genuinely Phase 5's scope) to the point real C++17 errors
       are obscured, you are authorised to re-add a *narrowed* suppression to
       `cmake/BALLCompilerSpecific.cmake` — scoped to Qt headers only, or accept the
       noise. Record the decision and rationale in the SUMMARY. Default remains: leave
       it removed. C++17-relevant deprecations (e.g. anything in BALL's own code) must
       NOT be suppressed.
    4. Re-build until BALL, VIEW, and BALLView all compile and link with zero errors.
    5. Document in the SUMMARY: every file touched beyond the Plan 01 set, the construct
       it had, and the idiom applied. This is the LANG-01 evidence trail.
