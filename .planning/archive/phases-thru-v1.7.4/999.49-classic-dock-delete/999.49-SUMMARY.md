## Deviations from plan

### Task 3 — simplified the first-run prompt rather than relabel the second button (decision deviation, not Rule 1-3 auto-fix)

**Found during:** Task 3 — discovered the "Keep my layout (Classic)" button cannot be honored after deletion because `Mainframe::show()` calls `apply(Default, this)` BEFORE the prompt opens (per `mainframe.C:923-926`), so the legacy 5-dock layout has already been overwritten by the time the user sees the dialog. The PLAN.md proposed keeping a two-button prompt with the second button renamed to "Keep my legacy layout" and persisting `currentPreset=UserDefined`, but there is no actual legacy layout to preserve at that point — the docks are already in their Default positions.

**Resolution:** Collapsed the prompt to a single-button informational notice ("Got it") that announces the workspace refresh. Users who want a custom arrangement use the pre-existing `View → Workspace → Save current as…` flow afterwards. Honest UX over a half-truth button.

**Rule applied:** Not a Rule 1-3 auto-fix — this is a small UX design judgment. The PLAN.md acceptance criterion ("First-run prompt no longer references Classic by name") is still satisfied.

**Files modified:** `source/APPLICATIONS/BALLVIEW/main.C` (commit c35d34c9ff). Also dropped the now-unused `#include <QtWidgets/QPushButton>`.

### Rule 3 auto-fix — VIEW tests force offscreen QPA platform

**Found during:** CI run 26002675865 on `a32de26f3f`. linux-x64 build cell failed at the BALL test suite step, test #295 `tabOrder_test`:
```
qt.qpa.xcb: could not connect to display
qt.qpa.plugin: From 6.5.0, xcb-cursor0 or libxcb-cursor0 is needed to load the Qt xcb platform plugin.
```
Pre-existing infrastructure issue surfaced by Phase 999.48's tabOrder_test addition. GitHub-hosted ubuntu-24.04 runner has no X display + lacks `libxcb-cursor0` (a Qt 6.5+ runtime dep). linux-arm64 happened to ship `xcb-cursor0` in its base image so the same code green'd there.

**Resolution:** `SET_TESTS_PROPERTIES(${test} PROPERTIES ENVIRONMENT "QT_QPA_PLATFORM=offscreen")` for every test in `VIEW_TESTS` (`test/CMakeLists.txt`). The offscreen plugin has no X / wayland / xcb-cursor dep tree and ships with every Qt 6 distribution in our matrix. The 999.48 SUMMARY noted "tabOrder_test smoke (6 checks, QT_QPA_PLATFORM=offscreen PASSED)" — this fix makes the design intent enforced by the build system rather than implicit-on-developer-shells.

**Rule applied:** Rule 3 (blocking-issue auto-fix). Out of strict scope for 999.49 (Classic deletion), but blocked CI green on the same push that deletes Classic.

**Files modified:** `test/CMakeLists.txt`.

**Commit:** `7f965a0cf3`.

**Concurrent maintainer fix:** Commit `8485636bc7` landed on the branch ~1 minute before my fix and applied the same idea at the `qputenv("QT_QPA_PLATFORM", "offscreen")` call site inside `test/tabOrder_test.C`. Both fixes are independent and mutually compatible — belt-and-suspenders: maintainer's fix covers tabOrder_test specifically (in-test); mine covers ALL VIEW tests (CMake-level, applies to menuMapping_test + any future VIEW test added to `VIEWTestExecutables.cmake`). Kept both per "OOS executor commits — surface, don't revert" memory directive.
