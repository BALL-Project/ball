## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Windows runner not provisioned (windows-2022-xlarge)**
- **Found during:** Task 2 / CI trigger phase
- **Issue:** The `windows-2022-xlarge` runner label is not provisioned in the org. Run 25959228804 queued indefinitely.
- **Fix:** Reverted Windows runner to `windows-2022` in ci.yml and release.yml (commit `7b1ba7d`)
- **Files modified:** `.github/workflows/ci.yml`, `.github/workflows/release.yml`

**2. [Rule 3 - Blocking] macOS Apple Clang PCH + ccache incompatibility**
- **Found during:** Task 3 — first measurement run
- **Issue:** Apple Clang embeds non-deterministic metadata in PCH files that ccache cannot normalize even with `pch_defines,time_macros,include_file_mtime`. macOS ccache hit rate dropped to 0.81% (5/618), causing a 10x build regression: 307-308s vs 39s baseline.
- **Root cause:** Apple's Clang fork adds non-deterministic data at PCH creation time (runner-specific timestamps, build environment fingerprints) not covered by any current ccache sloppiness option. This affects Apple Clang specifically; GCC (Linux) and MSVC (Windows) are not affected.
- **Fix:** Wrapped all `target_precompile_headers` calls in `IF(NOT CMAKE_CXX_COMPILER_ID STREQUAL "AppleClang")` (commit `5e04578`)
- **Validation:** Run 25961540880 shows macOS Build 34s, ccache 99.84% hits — regression resolved
- **Files modified:** `CMakeLists.txt`, `cmake/PCH.md`

- `d33e24e` — `ci(coverage): switch Qt 6 source from apt to jurplel/install-qt-action` — user OOS fix for coverage job Qt 6 install; cancelled run 25960028976's Windows Build mid-flight
