# Phase 999.41 Plan 01: SVG icons + HiDPI fixup Summary

**One-liner:** Build-flag-gated SVG-preferred branch in `IconLoader::loadIcon_`,
14 vendored Lucide v0.460.0 SVGs aliased to BALLView's icon keys via `theme.qrc`,
toolbar size 22→20 logical px under `BALL_UI_V2`. Zero behaviour change with the
flag OFF (the v1.7 default).

## What landed (each commit, briefly)

1. **Lucide subset.** 14 SVGs (folder-open, save, maximize, minimize-2, octagon-x,
   ruler, plus, trash-2, copy, atom, shrink, link-2, settings, help-circle) vendored
   verbatim from lucide-static@0.460.0 into `source/VIEW/KERNEL/theme/icons/lucide/`
   with a per-file one-line provenance comment + `LICENSE-lucide.txt`. Each SVG is
   <2 KB, uses `stroke="currentColor"` so it inherits the QSS text color naturally.
2. **theme.qrc extension.** Single new `<qresource prefix="/icons">` block aliases
   BALLView's icon keys (`actions/quicksave`, `categories/preferences`, etc.) onto
   the Lucide files. `quicksave` + `document-save` both map to `save.svg` by
   design. XML validates.
3. **CMake/Qt6Svg link.** `Svg` added to `BALL_HAS_VIEW`'s `FIND_PACKAGE(Qt6 ...)`
   list at `CMakeLists.txt:370`; `Qt6::Svg` appended to `VIEW_DEP_LIBRARIES` at
   `:388`. Unconditional (not BALL_UI_V2-gated) so libVIEW links uniformly across
   flag states.
4. **Loader wedge.** `IconLoader::loadIcon_(name)` gains a `#ifdef BALL_UI_V2`
   block that first tries `:/icons/<name>.svg` from the QRC; on hit it constructs
   a `QIcon` and caches under `name`; on miss it falls through to the existing
   PNG-from-disk walk. Header signature unchanged — zero call-site churn across
   the 28 `IconLoader::instance().getIcon(...)` use sites.
5. **Toolbar size.** `mainframe.C:295` `setIconSize(22,22)` wrapped in
   `#ifdef BALL_UI_V2`/`#else` so the ON path picks `Theme::kIconToolbar` (=20)
   from 999.40's `tokens.h`. OFF path unchanged.
6. **999.42 + v1.8 breadcrumbs.** Three `TODO(...)` comments at the obvious
   future entry points (`icons.h` XPM bucky → 999.42 + Phase 8; `iconLoader.h`
   class top → v1.8 ThemedIconEngine; `iconLoader.C` inside the wedge → v1.8
   tint cache).

`6ca8506d23 docs(999.25b): complete tutorial/sample-tree sweep — PLAN + SUMMARY`.

git history).

**Action taken:** per user feedback memo `feedback_oos_executor_commits.md`
(_"surface, don't revert; OK to keep well-formed opportunistic commits"_), both
combined commits are left in place. This deviation entry is being amended into
the SUMMARY in a separate dedicated commit (using path-spec terminator to bound
the index against future sweeps).

**Future avoidance:** when parallel executors are active, always commit with
explicit path-spec terminator (`git commit -m ... -- <explicit paths>`) so the
commit operation is bounded against other agents' index mutations. The
orchestrator should add a "scope your `git add` to your task tree" rule to the
parallel-agent contract — a wide-net `git add` is a footgun in multi-agent mode.

v0.460.0 ships under ISC. `LICENSE-lucide.txt` records the actual upstream
license. Both are permissive — no project-level impact, but the docstring would
have been wrong if I'd copied the spec verbatim.
