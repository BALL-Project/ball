# `999.62` — Opaque-paint contract · codification

**v1.7.x-35 (new)** · Wave A · ~2 days

> **Ingest note (2026-05-22).** The handover PLAN.md minted this as `v1.7.x-30 (new)`, but `v1.7.x-30` is already used in this repo for the #527 Material-transparency item (Phase 999.52). Re-minted to the next free patch-queue ID **v1.7.x-35** during ingest. The handover phase id `999.61` was renumbered to **999.62** (+1) to clear the collision with the in-flight `999.58` set.

> **Codex reconciliation (2026-05-22, LOW #12).** The lint is **warn-only
> first**, and must ship with (a) a whitelist file for legitimate
> exceptions (`QPropertyAnimation`s on non-visible properties) and (b)
> synthetic positive + negative self-tests proving the grep actually
> catches a missing-opaque-parent case and actually passes a correct
> fix. It flips to BLOCKING only after one clean STATUS week. A grep
> that can't be demonstrated to catch the bug — and can't be quieted on
> a real exception — does not gate merges on day one.

## Goal

Convert the UFG-05 / 09 / 10 lessons from per-site fixes into a
structural contract: every container that hosts an animated child is
opaque, and CI enforces it (warn-only first, then blocking).

## Why now

The fixes shipped in rc2/rc3 are in 5 specific files. A future
contributor adding a new collapsible section will reproduce the
defect unless the rule is structural. Dark mode (v1.8) raises the
visual cost — the failure mode is even louder at higher contrast.

## Scope

**In:**

1. **`InspectorSection` base** — set `WA_OpaquePaintEvent` +
   `setAutoFillBackground(true)` + paintEvent fillRect, ONCE at the
   base. Every subclass inherits.
2. **`InspectorView`, `InspectorBody`, `InspectorTabs`, the inner
   `QScrollArea` + viewport + contents widget** — opaque, codified in
   the constructors (currently set ad-hoc per-site).
3. **`WelcomeScreen`** — same pattern, already shipped at rc3; the
   `999.62` work is to factor it into a shared mixin (`OpaqueMixin`).
4. **Theme token** — `data/BALLView/theme/theme-neutral.qss` gains a
   centralized rule: `[opaqueContainer="true"] { background: palette(Window); }` — toggled by a dynamic property.
5. **`THEME.md`** — new design-system reference doc (~80 LOC)
   documenting the opaque-paint rule, the dynamic-property toggle,
   and the relationship to dark mode.
6. **CI lint script** `cmake/scripts/check-opaque-paint.sh` —
   1) greps for `QPropertyAnimation` in `source/VIEW/`,
   2) for each hit not in the whitelist, walks up to 3 ancestors in the constructor,
   3) requires `WA_OpaquePaintEvent` OR `setAutoFillBackground(true)`
      OR an `opaqueContainer` dynamic-property set within those
      ancestors.
   **Ships as STATUS (warn-only)**; flips to BLOCKING after one week of
   clean runs.
7. **Whitelist** `cmake/scripts/opaque-paint-whitelist.txt` — full
   `file:line` entries for `QPropertyAnimation`s that animate non-visible
   properties (counters, scroll offsets with no transparency risk). Each
   entry requires a justifying comment.
8. **Synthetic self-tests** `test/contract/opaque-paint-lint-selftest.sh`
   — (a) a NEGATIVE fixture: a synthetic `QPropertyAnimation` with no
   opaque parent → the lint reports exactly 1 hit; (b) a POSITIVE
   fixture: the same with an opaque parent → the lint reports 0 hits;
   (c) a whitelist fixture: a whitelisted line → 0 hits. The self-test
   runs in CI so the lint can't silently rot into a no-op.

**Out:**
- Refactoring already-correct sites — drive-by edits not allowed.
- Dark-mode visual tokens — v1.8 builds on this, not the other way.
- Removing per-site fillRect calls — the contract is "redundant is OK", strip them in v1.7.5+.

## Rollout (warn-only → blocking)

| Step | State | Gate |
|------|-------|------|
| 1 | Lint + whitelist + self-tests land | self-tests green; lint runs as STATUS (non-blocking) |
| 2 | One week of clean STATUS CI | no new hits surface in PRs that week |
| 3 | Flip `STATUS` → `BLOCKING` in `ci.yml` | a one-line CI change after the clean week |

The flip is a deliberate, separately-committed step — not part of the
initial landing.

## Acceptance criteria

- [ ] `check-opaque-paint.sh` reports 0 hits on current tree (STATUS pass).
- [ ] Self-test NEGATIVE fixture → script reports exactly 1 hit; POSITIVE fixture → 0 hits; whitelist fixture → 0 hits. Self-test runs in CI.
- [ ] Whitelist file exists; every entry has a justifying comment.
- [ ] Lint ships as STATUS (warn-only); the BLOCKING flip is a separate later commit gated on one clean week.
- [ ] `THEME.md` exists and is readable; references back to `ARCHITECTURE-CONTRACT.md §10`.
- [ ] Existing UFG-05/09/10 fixes still in place (now redundant with the base-class pattern; redundancy acceptable in v1.7.4).
- [ ] Manual smoke: open Inspector → expand each section → collapse → screenshot every transient frame; no text ghosting.
- [ ] Smoke also passes on Linux + Windows (the v1.7.0 fixes were macOS-discovered; ensure they hold cross-platform).

## Risks

- **False positives in the lint.** Some `QPropertyAnimation`s animate non-visible properties (a counter, a scroll offset). Mitigated by the whitelist (full `file:line`, justifying comment) AND proven by the self-test's whitelist fixture. This is exactly why the lint is warn-only first.

## Out of scope

- Dark mode → v1.8. The opaque-paint contract is a *prerequisite* for dark mode landing safely.
- Custom clang-tidy check for the same rule → v1.7.5 stretch.
