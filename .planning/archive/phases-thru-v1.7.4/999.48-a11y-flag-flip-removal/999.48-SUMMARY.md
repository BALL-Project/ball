## What landed

### Accessibility (Tasks 1-5)

- **QAccessible names** on the 4 named custom widgets per Handover §8.2.
  Qt's default factory already supplies the right roles for
  `QAbstractButton` (Button), `QSlider` (Slider), `QWidget` (Pane); we
  added `setAccessibleName` / `setAccessibleDescription` calls + kept
  them in sync with property changes (e.g. `SwatchButton::setColor`
  refreshes the "Color: #ff0000" name).
- **SectionHeader chevron** bumped from `Qt::NoFocus` to
  `Qt::StrongFocus` so keyboard users can tab to it and use Space to
  collapse/expand.
- **`tabOrder_test.C`** 6-check smoke test locks in the a11y invariants
  against regression: PASSED locally with `QT_QPA_PLATFORM=offscreen`.
  Deep per-dialog tab-chain walk defers to RC patch (needs full
  Mainframe + display).
- **`ThemeManager::TextScale`** API (ScaleNormal=100, ScaleLarge=115,
  ScaleExtraLarge=130). `init()` loads from `QSettings`
  `[Appearance]/textScale`, applies via `qApp->setFont()` with cached
  base point-size. UI radio group defers to RC patch (the Preferences >
  Appearance dialog is `displayProperties.ui` which is itself a deferred
  legacy file).
- **`contrast-check.py`** stdlib-only Python validator. Computes WCAG 2.1
  §1.4.3 relative luminance (sRGB-linearization with 0.03928 threshold
  and 2.4 gamma), reports PASS/FAIL/EXEMPT per rule pair. First run on
  `theme-neutral.qss`: 16/16 non-exempt PASS, 2 `:disabled` pairs exempt
  per WCAG §1.4.3 explicit exemption.
- **`tooltip-lint.py`** addAction-without-setToolTip gate. Tightened
  heuristic only flags inline-birth sites (`addAction(tr(...)`,
  `addAction("...")`, `addAction(new QAction(...))`) — variants that
  pass pre-built `*_action_` members are exempt because the QAction is
  responsible for its own tooltip. 2 pre-existing baseline gaps
  (standardDatasets.C, propertyEditor.C) allow-listed with breadcrumb.
  Wired into ci.yml's `lint` job.

### Flag flip + removal (Tasks 6-9)

- **Task 6 (the flip):** `OPTION(BALL_UI_V2 ... OFF)` → `ON` at
  `CMakeLists.txt:289`. CI still validates both cells until Task 9.
- **Task 7 (the source removal):** Python script
  `/tmp/remove_ball_ui_v2.py` walked the preprocessor stack-depth
  correctly for nested `#if`/`#endif` inside the BALL_UI_V2 outer
  blocks. Removed **110 `#ifdef BALL_UI_V2` blocks** across **76 files**;
  dropped **12 `#else` branches** in the 4 complex files (mainframe.C,
  mainControl.C, iconRegistry.C, main.C). 265 net lines deleted.
- **Task 8 (CMake plumbing):** `OPTION(BALL_UI_V2 ...)` block and
  `IF(BALL_HAS_VIEW AND BALL_UI_V2) ... TARGET_COMPILE_DEFINITIONS`
  block deleted. The Phase 999.46 lesson about TARGET_COMPILE_DEFINITIONS
  PRIVATE vs SET_TARGET_PROPERTIES COMPILE_DEFINITIONS preserved in
  shortened form so future maintainers don't reintroduce the
  anti-pattern.
- **Task 9 (CI matrix):** `ui_v2_matrix` output, `ui_v2_paths_match`
  block (~80 lines), `MAC/LINUX/WINDOWS_ENTRY` `ui_v2` JSON fields,
  jq doubling step, `name: build (... ui_v2=…)` suffix,
  `ccache key -ui_v2_` suffix, Windows CMake-tree cache `-ui_v2_`
  suffix, every artifact name's `-ui_v2_` suffix, every JUnit
  filename's `-ui_v2_` suffix, every macOS/Linux/Windows Configure
  step's `-DBALL_UI_V2=` flag, and the Windows vcpkg upload-artifact
  `matrix.ui_v2 == 'OFF'` condition — all removed. ~160-line net
  reduction in ci.yml. 20 stale comment-only `ui_v2` / `BALL_UI_V2`
  mentions remain (documentary; pure-comment scrub defers).
