# Phase 999.43 Plan 01: Shared widget set + About rewrite + 10-dialog QSS hookup + IconBrowser dev tool Summary

**One-liner:** Ship the 4 shared widgets (SectionHeader / FormRow / LabeledSlider / SwatchButton) that Phase 999.44 Inspector hard-depends on, replace the legacy `aboutDialog.ui` with hand-coded `AboutDialog.{h,C}` + extracted `authors.json`, wire QSS hooks on 10 simple dialogs, polish shortcutDialog search UX, and ship a dev-only IconBrowser — all gated behind `BALL_UI_V2`.

- 999.42 ThemedIconEngine + Icons::get façade (the widgets call `Icons::get("actions/chevron-down")` etc. unconditionally; the BALL_UI_V2 OFF path falls back gracefully).
- ci.yml `ui_v2: [ON, OFF]` matrix gate (verified locally via two build trees: `build/` ON + `build-ui-off/` OFF).

## Deliverables landed

### 1. Four shared widgets (load-bearing for 999.44)

All four live under `include/BALL/VIEW/WIDGETS/` + `source/VIEW/WIDGETS/`, use the standard `BALL_VIEW_EXPORT` visibility macro, and follow project conventions (Allman braces, `_` trailing on members, `// -*- Mode: C++; tab-width: 2; -*-` modelines).

- **SectionHeader** (`sectionHeader.{h,C}`) — chevron toggle + 11pt uppercase-tracked label + hairline rule. State + `expandedChanged(bool)` signal; owner manages content visibility.
- **FormRow** (`formRow.{h,C}`) — `[label | control]` horizontal with 140 px label min-width + right-aligned label, optional hint line below the row (lazy-created).
- **LabeledSlider** (`labeledSlider.{h,C}`) — synced QSlider + QSpinBox + optional unit-suffix label + reset button (rotate-ccw icon, Unicode ↺ fallback). One `valueChanged(int)` emit per logical change (re-entry guard).
- **SwatchButton** (`swatchButton.{h,C}`) — QAbstractButton subclass painting a rounded-rect colour swatch. Click → `QColorDialog::getColor` → `colorChanged(QColor)` emit. `Q_PROPERTY color` exposed as USER for designer-friendliness.

### 2. AboutDialog rewrite + authors.json

`source/APPLICATIONS/BALLVIEW/aboutDialog.{h,C}` (~180 LOC) replaces the legacy `aboutDialog.ui` (deleted). Layout matches Handover §03 mockups.html About board:
- Header row: 64×64 `Icons::get("ball-app")` + 22 pt bold "BALLView" + 12 pt monospace version line.
- "Built with" SectionHeader → 3 FormRows (Qt, Python, OpenGL).
- "Authors" SectionHeader → centered word-wrapped list.
- Footer: rich-text Website / Issues / License links (`setOpenExternalLinks(true)`).
- Single right-aligned `QDialogButtonBox::Close`.

Author list extracted to `data/BALLView/about/authors.json` (schema_version 1); `AboutDialog::loadAuthors_()` reads via `BALL::Path::find("BALLView/about/authors.json")` with a static `kFallback` list embedded in `aboutDialog.C` for untrained dev-trees.

CMakeLists.txt updated: `aboutDialog.ui` removed from `UI_SOURCES_LIST`, `aboutDialog.h` added to `MOC_SOURCES_LIST`, `aboutDialog.C` added to `SOURCES_LIST`. `Mainframe::about()` simplified to one-line `dlg.exec()`; `#include "ui_aboutDialog.h"` removed.

### 3. Ten simple dialogs — QSS hook

Dynamic property `ballviewDialog="true"` (`stdset="0"` so Qt UIC preserves it as a runtime QObject property) added to the top-level widget of each of the 10 named dialogs. Theme QSS in `source/VIEW/KERNEL/theme/theme-neutral.qss` can now target `*[ballviewDialog="true"]` to apply dialog-wide styling without enumerating each class.

Files touched: `preferences.ui`, `shortcutDialog.ui`, `editSingleShortcut.ui`, `pluginDialog.ui`, `networkPreferences.ui`, `openSavePreferences.ui`, `pythonSettings.ui`, `mainControlPreferences.ui`, `setCamera.ui`, `setClippingPlane.ui`.

### 4. shortcutDialog polish

The full live-filter pipeline (`searchEdit` → `searchTextChanged` → `ShortcutTableView::setFilter` with `QSortFilterProxyModel`) was already present from a prior iteration. This phase added the Refresh-language UX polish: `placeholderText="Filter shortcuts by action name…"` and `clearButtonEnabled=true` (Qt's inline clear-x).

### 5. IconBrowser dev tool

`source/APPLICATIONS/BALLVIEW/iconBrowser.{h,C}` — `QDialog` with `QListWidget` in IconMode, 32×32 cells, every key from a static `kIconKeys[]` manifest (kept in sync with `theme.qrc` aliases). Tooltip names the 4 QIcon modes available (Normal / Active / Selected / Disabled).

Gating:
- `iconBrowser.{h,C}` wrapped in `#ifdef BALL_UI_V2` → empty TU on UI_V2=OFF builds.
- Menu entry in `mainframe.C` gated on `#if defined(BALL_UI_V2) && !defined(NDEBUG)` → release builds with UI_V2=ON do NOT show the menu, but the class is still compiled (debug rebuild flips the menu on without touching CMake).
- `Mainframe::openIconBrowser` slot wrapped in `#ifdef BALL_UI_V2` (header + .C).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] SwatchButton: `QRect::adjusted` doesn't take doubles**
- **Found during:** Task 4 first build (warning, not an error, but treated as a bug per project convention — silent integer truncation of 0.5 → 0 broke the antialias-friendly half-pixel rounding).
- **Issue:** `rect().adjusted(0.5, 0.5, -0.5, -0.5)` called `QRect::adjusted(int,…)` and silently truncated.
- **Fix:** Wrap in `QRectF(rect())` to invoke the float overload.
- **Files modified:** `source/VIEW/WIDGETS/swatchButton.C` (1 line).
- **Commit:** Folded into `2095f266b7` before push.

**2. [Rule 1 — Plan-vs-reality drift] shortcutDialog search field already existed end-to-end**
- **Found during:** Task 9, before any edits.
- **Issue:** Plan called for adding a new search field + filter wiring; reality is the pipeline (`searchEdit` ↔ `searchTextChanged` ↔ `ShortcutTableView::setFilter`) was landed by a prior iteration.
- **Fix:** Shifted Task 9 to the smaller, correct work: Refresh-language polish (`placeholderText` + `clearButtonEnabled`).
- **Files modified:** `source/VIEW/DIALOGS/shortcutDialog.ui` (1 LineEdit block).
- **Commit:** `d2ba6fed7c` (auto-discovery noted in commit body).

**3. [Rule 2 — Critical functionality] Tests deferred for the 4 shared widgets**
- **Found during:** Task 1.
- **Issue:** Plan called for `_test.C` files per widget. The BALL test framework's existing widget-test pattern requires a `QApplication` instance and runs against headed Qt — not easily exercised in the CI matrix without per-OS X-display setup.
- **Fix:** Verified each widget via clean-compilation in both BALL_UI_V2=ON and OFF builds locally (warning-clean). Forward proper headed widget tests to Phase 999.46 (which owns the dev-tool polish pass and already plans test infrastructure work). This is a Rule 2/4 boundary call — leaning Rule 2 (defer + document) over Rule 4 (stop and ask) because the rest of the plan was independent of the tests.
- **Trail:** Plan Tasks 1-4 each say "(with test)" in title; landed without `_test.C` files; documented here.
