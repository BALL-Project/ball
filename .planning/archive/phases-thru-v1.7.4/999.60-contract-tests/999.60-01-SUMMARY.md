# Phase 999.60 Plan 01: Contract Tests — Cross-Surface Parity Summary

Stood up the cross-surface contract-test **harness + compile-fail infra
FIRST** (the Codex MEDIUM #7 sequencing fix): a headless `ContractTestHarness`
exercising the 9 controllers, 9 per-controller parity fixtures shipped
disabled/expected-fail, a selection-consumer and a bool-apply re-entrancy
fixture, owner-narrowing compile-fail checks, a ctest `contract` label, and a
blocking Linux CI gate — all compiling green today and engineered to flip
green per-controller as 999.59 cuts each over.

## What shipped

- **`ContractTestHarness` (`contractTestHarness.{h,C}`)** — boots offscreen-QPA
  Qt (matching `tabOrder_test`), constructs the `Stage` + `Representation`
  owners the controllers mutate, best-effort loads `1BNA.pdb` for the selection
  surface, and produces a diff-friendly `OwnerSnapshot` POD over Stage /
  Representation / selection state. `SurfaceKind` + `surfaceAvailable()` report
  surface readiness honestly: Inspector live; Toolbar/Menu unavailable until the
  §8 command-body migration (999.59-03); Python gated on `BALL_HAS_PYBALL`.
- **`harness_selftest.C`** — the plan's "harness self-test" acceptance criterion:
  asserts the toolbar/menu surfaces are NOT faked via `action->trigger()` (they
  report unavailable until the registered command body exists).
- **9 per-controller parity fixtures** — one per state domain (Model / Coloring /
  Material / Clipping / Label / Stage / Camera / Light / Stereo). Each carries an
  ENABLED Inspector→owner postcondition check (the safety net the cut-over must
  not break) plus a `DISABLED_*_parity_across_surfaces` check encoding the
  bit-equal cross-surface contract, gated on `CONTRACT_FIXTURE_DISABLED`.
- **`selection_consumer_test.C` (§7)** — ENABLED source-of-truth check via
  `Composite::isSelected()`; DISABLED four-consumer agreement pending 999.59.
- **`reentrancy_test.C` (§2/§11b)** — ENABLED guard-shields-nested-apply check
  (holds today via the void path); DISABLED bool-drop assertion pending 999.59-01.
- **Owner-narrowing compile-fail infra (§3/§11c)** — two negative TUs that mutate
  the owner directly (EXPECT pass today, flip to EXPECT fail after 999.59-04
  privatises the setters) + a positive TU through `RepresentationBuilder` (must
  compile every phase), driven by `run_compile_check.cmake` as `contract`-labeled
  ctests.
- **CMake + CI wiring** — `test/CMakeLists.txt` registers the 12 executables with
  the ctest `contract` label and the 3 compile checks + a `contract_tests`
  aggregate target; `.github/workflows/ci.yml` adds a blocking, Linux-only
  contract gate running `ctest -L contract`.

(`BALL_UI_V2` was removed), so per the reconciled plan the bool-apply parity /
re-entrancy assertions and the cross-surface parity bodies ship **disabled** and

  (v1.7.1 release notes), not its tip — the plan, the architecture contract, the

  branch (`git merge --ff-only`) — non-destructive, no commits lost, branch
  identity preserved.
- **Files modified:** none (history advance only)

**2. [Rule 1 - Bug] Harness `.C` missing `BALLTestConfig.h` include**
- **Found during:** Task 6 build validation
- **Issue:** `contractTestHarness.C` used `BALL_TEST_DATA_PATH(1BNA.pdb)` without
  including `<BALLTestConfig.h>`, so the macro was undefined and `1BNA.pdb`
  tokenised as an invalid numeric literal.
- **Fix:** Added `#include <BALLTestConfig.h>`.
- **Commit:** 46dfc89be2

**3. [Rule 1 - Bug] Ambiguous `PDBFile::isValid()`**
- **Found during:** Task 6 build validation
- **Issue:** `pdb.isValid()` is ambiguous — `PDBFile` inherits `isValid()` from
  both `File` and `PropertyManager`.
- **Fix:** Qualified as `pdb.File::isValid()`.
- **Commit:** 46dfc89be2

**4. [Rule 1 - Bug] `harness_selftest.C` used incomplete `Stage` type**
- **Found during:** Task 6 build validation
- **Issue:** the self-test called `h.stage()->setFogIntensity()` with only the
  forward declaration from the harness header.
- **Fix:** Added `#include <BALL/VIEW/KERNEL/stage.h>`.
- **Commit:** 46dfc89be2

**5. [Rule 2 - Missing functionality] macOS framework search path in the compile-check driver**
- **Found during:** Task 6 driver validation
- **Issue:** the driver passed only `-I` dirs; on macOS Homebrew Qt is a
  framework build so `QtCore/QEvent` did not resolve. (Linux CI — the actual gate
  target — uses plain `-I` and was unaffected, but local validation and any
  future macOS coverage needed it.)
- **Fix:** Added `FRAMEWORK_DIRS` support to `run_compile_check.cmake` and
  forwarded Qt framework dirs from `test/CMakeLists.txt` on APPLE.
- **Commits:** e3ef4d927a (driver), 937ff38f04 (CMake)
