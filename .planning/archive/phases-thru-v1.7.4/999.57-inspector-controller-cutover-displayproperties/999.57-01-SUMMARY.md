# Phase 999.57 Plan 01: ModelProcessorFactory headless relocation Summary

**Relocated `createModelProcessor` + `applySettingsTo` out of the legacy ModelSettingsDialog into a headless `ModelProcessorFactory` (pure function of a `ModelProcessorParams` struct, zero QWidget dependency); the dialog now packs its ~22 getters and delegates — behavior byte-identical, render path untouched.**

## Performance

- **Duration:** ~10 min
- **Started:** 2026-05-21T19:31Z
- **Completed:** 2026-05-21T19:41:28Z
- **Tasks:** 3
- **Files modified:** 4 (2 created, 2 modified)

## Accomplishments
- New `ModelProcessorFactory` lives in the MODELS layer with no dependency on any dialog widget — `create(ModelType, const ModelProcessorParams&)` reproduces the exact 11-case switch + per-type RTTI settings dispatch.
- `ModelProcessorParams` carries every numeric/bool knob the dialog previously read from sliders/checkboxes, each defaulted to the dialog's out-of-box value so a default-constructed params reproduces the dialog's initial state.
- `ModelSettingsDialog::createModelProcessor` thinned from a 67-line switch to a 25-line pack-params-then-delegate body; the dialog no longer constructs any per-type ModelProcessor itself (`new Add*Model` count in the method = 0).
- libVIEW builds clean on macOS-arm64 (BALL_UI_V2=ON) after each task.

## Decisions Made
- **ModelType include path:** included `<BALL/VIEW/KERNEL/common.h>` (the canonical home of `enum ModelType`) exactly as the sibling MODELS-layer header `colorProcessor.h` does. The factory header writes no literal `QtWidgets`/`QSlider`/`QCheckBox` includes, so it passes the headless-invariant verify and is consistent with the existing MODELS layer. The factory depends only on a plain enum + a value object — never on a widget.
- **applySettingsTo kept, not deleted:** grep found an external caller (`displayProperties.C:471`) outside `createModelProcessor`. Per the plan ("preserve any non-factory caller"), the dialog method stays intact; Plan 03 will repoint it.
- **Defaults source:** the dialog never held `BALL_..._DEFAULT_*` constants; it derives defaults from default-constructed model processors via `setDefaultValues_`. The params struct therefore mirrors those processor-constructor defaults.
