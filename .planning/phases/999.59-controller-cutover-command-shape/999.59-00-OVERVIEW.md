**Codename:** *the contract*
**Wave:** A · gating
**Effort:** ~2.5–3 weeks (revised up — owner-narrowing fallout + Python binding step; see ARCHITECTURE-CONTRACT.md §15)
**Risk:** medium-high (touches every Controller TU + ~13 non-controller files + the SIP surface)

## Goal

Land the command-shaped `Controller::apply()` contract on **all 9**
mutating Controllers in the VIEW layer. Harmonize the 7 that already
mutate onto one shape, finish the 2 stubs (Clipping/Label), make `apply()`
return `bool`, and narrow owner-side mutation so external mutation does
not compile — bringing the full owner-narrowing fallout (and the PyBALL
binding refresh it forces) into v1.7.4.

This is the **gating phase** for v1.7.4 — `999.63`/`999.64` depend on the
contract being in place, and `999.60`'s per-controller fixtures flip
green as this phase cuts each controller over.

## Ground truth (2026-05-22 audit — read before estimating)

- There is **no base `Controller` class today** — the 9 controllers are
  independent `QObject`s. `999.59-01` creates the base.
- **7 of 9 controllers already mutate** (Camera/Stereo/Light/Model/
  Coloring/Material + Stage). Only **Clipping** and **Label** are
  `Log.info` stubs. So this phase is mostly **harmonization**, not nine
  extractions.
- `ClippingController::apply()` **explicitly omits the re-entrancy
  guard** today (clippingController.C ~line 88 comment). The contract now
  requires it everywhere.
- The in-tree `controllerApplyGuard.h` is a plain RAII `bool&` flag — not
  nest-aware. `999.59-01` upgrades it.
- **~47 owner-setter call sites across 13 non-controller files** (the
  full inventory is ARCHITECTURE-CONTRACT.md §3a). Not "≤8 file-IO".
- `representation.sip` exposes exactly the setters being narrowed
  (`setTransparency`/`setDrawingMode`/`setColoringMethod`/`setModelType`/…)
  — privatizing them breaks PyBALL unless the binding moves in v1.7.4.

## Why now

`v1.7.x-ARCHITECTURE-REVIEW.md` identified the dual-path mutation defect
behind ~30 UFG bug reports. The mutating Controllers diverge in their
guard / event / invalidation handling; that drift is what keeps re-entry,
mid-state observation, and notification-ordering issues biting.

The contract makes mutation a **transaction**, not a sequence of public
calls.

## Scope

**In:**
- Base `Controller` class (NEW) + nest-aware `ControllerApplyGuard` (upgrade) + `ApplyPayload` types. `bool apply()` + `virtual void reset()` (the latter consumed by 999.64) + `invalidateDeclared_()` §2a hook.
- Harmonization of the 7 already-mutating Controllers (Model, Coloring, Material, Stage, Camera, Light, Stereo) onto the §2 `bool` shape with declared §2a invalidation.
- Finishing the 2 stubs (Clipping, Label) into real command-shaped `apply()` bodies — Clipping gains the guard it omits today.
- Migration of all interactive non-controller owner-setter sites (§3a) onto Controller calls.
- Owner-side narrowing via `StageMutation` facade (Stage) + `RepresentationBuilder` friend (Representation); builder/render-side friends for the legitimate construction sites.
- CommandRegistry command-body migration for dual-surface mutating ops (§8).
- Reversible-payload capture (storage only; no UI consumer in v1.7.4).
- PyBALL binding shim/regen (`999.59-06`) — IN v1.7.4.
- Minimal `ControllerJob` base (async scaffold the §4 thread-safety model references; no concrete job).

**Out:**
- Undo stack — `999.59-05` captures the payload; v2.0 consumes.
- `ConnectionObject` replacement — v2.0.
- Deep PyBALL test coverage — v2.1 (v1.7.4 ships the binding + a build-check, not exhaustive parity tests).
- New owner-side state.
- New Inspector controls — `999.63` and `999.64` do that, *consuming* this contract.
- A concrete async job (minimization Controller) — v2.0; v1.7.4 ships only the `ControllerJob` base.

## Sequencing (Codex MEDIUM #7 — the circular-dependency fix)

The first draft had `999.60` depend on `999.59` AND `999.59` acceptance
depend on `999.60` tests. Broken as follows:

1. **`999.60` lands the harness + compile-fail infra FIRST**, with each
   per-controller parity fixture **disabled / expected-fail** (the
   controller doesn't conform yet).
2. **`999.59` then cuts controllers over one-by-one.** As each controller
   reaches the §2 `bool` shape (recipe in ARCHITECTURE-CONTRACT.md §13),
   its `999.60` fixture is flipped from expected-fail to enabled and goes
   green.
3. Owner-narrowing compile-fail fixtures (`999.60` §11c) start as
   expected-PASS-once-narrowed; they flip when `999.59-04` privatizes the
   setters.

So `depends_on: [999.57, 999.60]` here means *the 999.60 harness
skeleton*, and `999.60`'s per-controller fixtures depend back on the
incremental `999.59` cut-overs. No deadlock.

**Harness mechanism (confirmed in-tree at base `899e98e30a`):**
`test/contract/contractTestHarness.h` flips every per-controller fixture
from `STATUS`-skip to live the moment the feature macro
`BALL_VIEW_CONTROLLER_APPLY_RETURNS_BOOL` is defined. `999.59-01` defines
that macro (in `controller.h`); from that commit every cut-over controller's
fixture is live and asserts `mutated == true` and snapshot parity. The
owner-narrowing compile-fail driver `test/contract/compilefail/run_compile_check.cmake`
reads an `EXPECT` value (`pass`/`fail`) set per-phase in `test/CMakeLists.txt`;
`999.59-04` flips the Stage/Representation negatives from `EXPECT=pass` to
`EXPECT=fail` with a `DIAG_MATCH` of `is private` / `no matching`.

## Cross-platform notes

The contract is platform-agnostic. Platform-specific touches:

- **macOS:** `ControllerJob`'s worker thread must NOT touch the GL context. `Renderer::query…()` methods on the GUI thread are the only legal accessors. UFG-26 was a `QPainter` on `QOpenGLWidget` off the paint cycle — the same shape.
- **Windows:** MSVC's strict `friend` lookup needs `friend class StageMutation;` / `friend class RepresentationBuilder;` *inside* the owner definition (not a forward decl in a header outside). One pass in `999.59-04` covers it. The `virtual` setters on `Stage` (`setCamera`/`setBackgroundColor`) stay virtual on the private surface.
- **SIP:** the binding regen in `999.59-06` must run on the CI runner that has SIP available; the build-check compiles the regenerated bindings but does not require a full PyBALL runtime.

| Risk | Severity | Mitigation |
|------|----------|------------|
| Owner-narrowing fallout larger than the ~47 sites grepped | med | The grep in acceptance is the gate; any site found mid-phase is added to the §3a inventory and migrated. |
| Narrowing breaks the Python binding | med→**closed** | `999.59-06` brings the binding regen + deprecation shim into v1.7.4; CI SIP-refresh build-check catches future drift. |
| `friend`-grant explosion on Stage (5 domains) | med→**closed** | `StageMutation` facade = one friend, not five (§3b). |
| Contract-test harness not ready | low→**closed** | Sequencing fix: `999.60` harness lands first with expected-fail fixtures (above). |
| Nest-aware guard semantics surprise a future implementer | low | The header carries doc-comments + examples; `999.60` re-entrancy test asserts the `bool` drop behavior. |
| MSVC strict-friend lookup for the facade | low | Dedicated pass in `999.59-04`. |

**Rollback:** the contract lands behind no flag — once committed, it's
the only shape. Revert path is per-Controller `git revert` if a specific
Controller's cut-over regresses; the base types stay. The Python shim is
revertible independently (`999.59-06` is the last plan).
