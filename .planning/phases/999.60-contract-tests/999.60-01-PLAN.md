# `999.60` — Contract tests · cross-surface parity

**v1.7.x-25** · Wave A · ~3–4 days (harness-first; fixtures flip green during 999.59)

## Goal

Stand up the **contract tests** that enforce the `apply()` contract by
behavior. Grep gates miss too much (aliases / helpers / lambdas /
indirection / Python / generated MOC); contract tests catch what grep
can't.

## Why now

Without these, the `999.59` contract is folklore. With them, every PR
that re-introduces a dual-path bypass fails CI immediately. They are the
structural enforcement layer the architecture review demanded.

## Sequencing — harness FIRST, fixtures flip green (Codex MEDIUM #7)

The first draft created a circular dependency: `999.60` depended on
`999.59`, but `999.59` acceptance depended on `999.60` tests. Resolution:

1. **This plan's harness + compile-fail infra (60.1 / 60.5 / 60.6) land
   FIRST.** They only need the *existing* controller surface to compile.
2. **Per-controller parity fixtures (60.2) ship `DISABLED_` / expected-
   fail.** They encode the target contract behavior the controller does
   not satisfy yet.
3. As `999.59` cuts each controller over to the §2 `bool` shape, that
   controller's fixture is **flipped from `DISABLED_` to enabled and goes
   green** (the flip is part of the `999.59-NN` plan that cuts it over).
4. The owner-narrowing compile-fail fixtures (60.5) flip from
   "expected-still-compiles" to "expected-fails-to-compile" when
   `999.59-04` privatizes the setters.

So `depends_on: [999.57]` (not `999.59`): the harness depends only on the
pre-existing controller scaffold. The green state of the per-controller
fixtures depends back on the incremental `999.59` cut-overs.

## Scope

**In:**

1. **`ContractTestHarness`** — fixture base that boots BALLView
   headlessly (matching `tabOrder_test`), loads `bpti.pdb` (CI-stable
   sample), exposes 4 helper methods per Controller for the 4 surfaces,
   and a `snapshotOwner()` that produces a POD diff-friendly view.
   **The toolbar/menu helpers invoke the registered `CommandRegistry`
   command body** (the §8 migrated `std::function`), not
   `action->trigger()` — so menu/toolbar parity is genuinely tested.
2. **Per-Controller parity tests** (**9 files**, one per Controller:
   Model / Coloring / Material / Clipping / Label / Stage / Camera /
   Light / Stereo). Each runs 3–5 representative operations through all 4
   surfaces and asserts bit-equal postconditions. Ship `DISABLED_` and
   flip green per the sequencing above.
3. **Selection-consumer agreement test** — four-way `EXPECT_EQ` across
   tree / scene picker / mainControl / action enable-gate.
4. **Re-entrancy test** — Controller apply triggers a notification that
   re-enters the same Controller; assert the second `apply()` returns
   `false` (dropped). This is exactly why `apply()` returns `bool`.
5. **Owner-narrowing compile tests** — negative tests that fail to
   compile on direct `stage_->setX()` / `rep_->setX()` from outside, plus
   a **positive** test that mutation through `StageMutation` /
   `RepresentationBuilder` DOES compile. Run as compile-fail/compile-pass
   tests under CTest.
6. **CI job `contract-tests`** — Linux-only (matches `tabOrder_test`
   discipline), blocking, ~90s wall-clock.

**Out:**
- Per-frame visual diff (v1.7.5 — pixel-diff is a separate concern).
- Performance contract (e.g. "no apply takes > 50 ms"). v1.7.5.
- Deep Python binding coverage — v1.7.4 Python harness uses the existing
  PyBALL test stub + the new `controllers.sip` surface; exhaustive
  parity is v2.1. When `BALL_HAS_PYBALL=OFF` the python-surface tests
  `GTEST_SKIP()` and parity drops to the 3 native surfaces.

## Detailed steps

### 60.1 — Harness skeleton (lands first)

- New `test/contract/` directory + `contractTestHarness.{h,C}` (~150 LOC).
- The harness:
  - `setUp()` → constructs `MainControl` + `Mainframe` offscreen, loads sample.
  - `surface_inspector(controller, op)` → instantiates the section, calls its public binding methods, then `controller->apply()` (returns `bool`).
  - `surface_toolbar(controller, op)` → invokes the registered `CommandRegistry` command body the toolbar action resolves to (the §8 migrated `std::function`).
  - `surface_menu(controller, op)` → same registered body, reached via the menu entry.
  - `surface_python(controller, op)` → calls the SIP-exposed Controller method from `controllers.sip` (or `GTEST_SKIP()`s cleanly if PyBALL is disabled in the CI build).
  - `snapshotOwner()` → POD `{Stage::serialize() + Rep::serialize() + Composite::selectionSet()}` blob.
- Uses GoogleTest matchers (BALL's `ClassTest.h` macro layer).

### 60.2 — Per-Controller parity tests (ship disabled, flip green)

For each of **9** Controllers, one test file with ~3–5 `TEST_F`s. Each
test follows the shape from `ARCHITECTURE-CONTRACT.md §11a`. ~80 LOC each.
Ship `DISABLED_`-prefixed; the `999.59-NN` plan that cuts the controller
over removes the prefix and confirms green.

Skeleton:

```cpp
TEST_F(ColoringContractTest, set_method_parity_across_surfaces)
{
  bool ia = via(SurfaceKind::Inspector).setMethod("Element").apply();
  bool tb = via(SurfaceKind::Toolbar  ).setMethod("Element").apply();
  bool mn = via(SurfaceKind::Menu     ).setMethod("Element").apply();
  bool py = via(SurfaceKind::Python   ).setMethod("Element").apply();
  EXPECT_TRUE(ia); EXPECT_TRUE(tb); EXPECT_TRUE(mn);   // all mutated
  EXPECT_EQ(snapshots[0], snapshots[1]);
  EXPECT_EQ(snapshots[1], snapshots[2]);
  if (py) EXPECT_EQ(snapshots[2], snapshots[3]);       // python optional
}
```

### 60.3 — Selection-consumer agreement

Single file, four `EXPECT_EQ`. Verbatim per `ARCHITECTURE-CONTRACT.md §7`.

### 60.4 — Re-entrancy test

Force a Controller to apply while its own emitted message is in flight;
assert the second `apply()` returns `false`:

```cpp
TEST_F(MaterialReentrancyTest, second_apply_dropped_during_emission)
{
  controller_.setTransparency(50);
  bool drop_observed = false;
  controller_.installNotifyHook([&](){
    // Re-enter while we're emitting the FIRST applyChanged
    drop_observed = !controller_.apply();   // expect false (early-return)
  });
  EXPECT_TRUE(controller_.apply());          // first apply mutated → true
  EXPECT_TRUE(drop_observed);                // re-entrant apply dropped → false
}
```

`apply()` returns a `bool` (true = mutated, false = dropped) — added in
`999.59-01`. This test is the reason the whole contract is `bool`.

### 60.5 — Owner-narrowing compile tests

CTest-driven compile-fail tests. Each negative `.C` file tries to mutate
the owner from outside a Controller TU; CTest asserts non-zero exit and
matches an expected diagnostic substring (`no matching public member
function` / `is private`). A companion **positive** `.C` mutates through
`StageMutation` / `RepresentationBuilder` and MUST compile. Ship the
negative tests as expected-pass-compile (setters still public) until
`999.59-04` privatizes them, then flip to expected-fail-compile.

### 60.6 — CI wiring

```yaml
contract-tests:
  needs: [build]
  runs-on: ubuntu-24.04
  steps:
    - uses: actions/checkout@v5
    - run: cmake --preset ci-linux -DBALL_BUILD_TESTS=ON
    - run: cmake --build build/ci-linux --target contract_tests -j 4
    - run: ctest --test-dir build/ci-linux -L contract --output-on-failure
```

Blocking. Same ccache lineage as the existing test job.

## Acceptance criteria

- [ ] `ctest -L contract` runs ~25+ tests, all enabled ones green, ~90s on Linux CI runner.
- [ ] Each of the **9** Controllers has its parity test file (Model / Coloring / Material / Clipping / Label / Stage / Camera / Light / Stereo).
- [ ] The toolbar/menu helpers invoke the registered command body, not `action->trigger()` — verified by a harness self-test.
- [ ] Owner-narrowing negative tests fail to compile with diagnostic matching `no matching public member function` / `is private`; the positive `StageMutation`/`RepresentationBuilder` test compiles.
- [ ] Re-entrancy test asserts `apply()==false` on re-entry; fails BEFORE `999.59-01` lands (sanity check), passes after.
- [ ] Harness + compile-fail infra land before `999.59` cut-overs; per-controller fixtures ship `DISABLED_` and are flipped green by the corresponding `999.59-NN` plan.
- [ ] CI `contract-tests` job appears in the matrix; blocking.
- [ ] Documented in a new `test/contract/README.md`.

## Risks

- **Headless BALLView is fragile.** `tabOrder_test` already does this on Linux/Windows but is brittle on macOS — mitigate by running contract-tests Linux-only at v1.7.4; macOS coverage in v1.7.5.
- **PyBALL is optional.** When `BALL_HAS_PYBALL=OFF` the python-surface tests skip via `GTEST_SKIP()` with a clear message; coverage drops to 3-surface parity (Inspector + Toolbar + Menu) which is still meaningful. The new `controllers.sip` surface (999.59-06) is what the python helper binds to when PyBALL is on.
