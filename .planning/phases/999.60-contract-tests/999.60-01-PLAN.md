# `999.60` — Contract tests · cross-surface parity

**v1.7.x-25** · Wave A · ~3 days

## Goal

Stand up the **contract tests** that enforce the apply() contract by
behavior. Grep gates miss too much (aliases / helpers / lambdas /
indirection / Python / generated MOC); contract tests catch what grep
can't.

## Why now

Without these, the `999.59` contract is folklore. With them, every PR
that re-introduces a dual-path bypass fails CI immediately. They are
the structural enforcement layer the architecture review demanded.

## Scope

**In:**

1. **`ContractTestHarness`** — fixture base that boots BALLView
   headlessly (matching `tabOrder_test`), loads `bpti.pdb` (CI-stable
   sample), exposes 4 helper methods per Controller for the 4 surfaces,
   and a `snapshotOwner()` that produces a POD diff-friendly view.
2. **Per-Controller parity tests** (8 files, one per Controller). Each
   runs 3–5 representative operations through all 4 surfaces and
   asserts bit-equal postconditions.
3. **Selection-consumer agreement test** — four-way `EXPECT_EQ` across
   tree / scene picker / mainControl / action enable-gate.
4. **Re-entrancy test** — Controller apply triggers a notification that
   re-enters the same Controller; assert second apply is dropped.
5. **Owner-narrowing compile tests** — negative tests that
   `static_assert` / `#error` on direct `stage_->setX()` from outside.
   These run as compile-fail tests under CTest.
6. **CI job `contract-tests`** — Linux-only (matches `tabOrder_test`
   discipline), blocking, ~90s wall-clock.

**Out:**
- Per-frame visual diff (v1.7.5 — pixel-diff is a separate concern).
- Performance contract (e.g. "no apply takes > 50 ms"). v1.7.5.
- Python binding coverage — v1.7.4 Python harness uses the existing
  PyBALL test stub; deep coverage is v2.1.

## Detailed steps

### 59.1 — Harness skeleton

- New `test/contract/` directory + `contractTestHarness.{h,C}` (~150 LOC).
- The harness:
  - `setUp()` → constructs `MainControl` + `Mainframe` offscreen, loads sample.
  - `surface_inspector(controller, op)` → instantiates the section, calls its public binding methods, then `controller->apply()`.
  - `surface_toolbar(controller, op)` → calls the registered `CommandRegistry` entry that the toolbar action resolves to.
  - `surface_menu(controller, op)` → same as toolbar, different entry.
  - `surface_python(controller, op)` → calls the SIP-exposed Controller method (or stubs cleanly if PyBALL is disabled in CI build).
  - `snapshotOwner()` → POD `{Stage::serialize() + Rep::serialize() + Composite::selectionSet()}` blob.
- Uses GoogleTest matchers (BALL's `ClassTest.h` macro layer).

### 59.2 — Per-Controller parity tests

For each of 8 Controllers, one test file with ~3–5 `TEST_F`s. Each test
follows the shape from `ARCHITECTURE-CONTRACT.md §11a`. ~80 LOC each.

Skeleton:

```cpp
TEST_F(ColoringContractTest, set_method_parity_across_surfaces)
{
  auto a = via(SurfaceKind::Inspector).setMethod("Element").apply();
  auto b = via(SurfaceKind::Toolbar  ).setMethod("Element").apply();
  auto c = via(SurfaceKind::Menu     ).setMethod("Element").apply();
  auto d = via(SurfaceKind::Python   ).setMethod("Element").apply();
  EXPECT_EQ(a.ownerSnapshot, b.ownerSnapshot);
  EXPECT_EQ(b.ownerSnapshot, c.ownerSnapshot);
  EXPECT_EQ(c.ownerSnapshot, d.ownerSnapshot);
}
```

### 59.3 — Selection-consumer agreement

Single file, four `EXPECT_EQ`. Verbatim per `ARCHITECTURE-CONTRACT.md §7`.

### 59.4 — Re-entrancy test

Force a Controller to apply while its own emitted message is in flight:

```cpp
TEST_F(MaterialReentrancyTest, second_apply_dropped_during_emission)
{
  controller_.setTransparency(50);
  bool drop_observed = false;
  controller_.installNotifyHook([&](){
    // Re-enter while we're emitting the FIRST applyChanged
    drop_observed = !controller_.apply();   // expect early-return
  });
  controller_.apply();
  EXPECT_TRUE(drop_observed);
}
```

`apply()` returns a `bool` (true = mutated, false = dropped) for this
diagnostic purpose — added in `999.59-01`.

### 59.5 — Owner-narrowing compile tests

CTest-driven compile-fail tests. Each is a tiny `.C` file that tries to
mutate the owner from outside a Controller TU; CMake's
`CMAKE_BUILD_TYPE=Debug` + `target_link_libraries(... VIEW)` runs the
compiler. CTest fixture asserts non-zero exit and matches an expected
diagnostic substring.

### 59.6 — CI wiring

```yaml
contract-tests:
  needs: [build]
  runs-on: ubuntu-24.04
  steps:
    - uses: actions/checkout@v5
    - run: cmake --preset ci-linux -DBALL_BUILD_TESTS=ON
    - run: cmake --build build/ci-linux --target contract_tests -j 4
    - run: ctest --test-dir build/ci-linux -L contract --output-on-failure
```

Blocking. Same ccache lineage as the existing test job.

## Acceptance criteria

- [ ] `ctest -L contract` runs ~25 tests, all green, ~90s on Linux CI runner.
- [ ] Each of the 8 Controllers has its parity test file.
- [ ] Owner-narrowing compile tests fail with diagnostic matching `no matching public member function` (or platform-equivalent).
- [ ] Re-entrancy test fails BEFORE `999.59-01` lands (sanity check), passes after.
- [ ] CI `contract-tests` job appears in the matrix; blocking.
- [ ] Documented in `cmake/PCH.md` or a new `test/contract/README.md`.

## Risks

- **Headless BALLView is fragile.** `tabOrder_test` already does this on Linux/Windows but is brittle on macOS — mitigate by running contract-tests Linux-only at v1.7.4; macOS coverage in v1.7.5.
- **PyBALL is optional.** When `BALL_HAS_PYBALL=OFF` the python-surface tests skip via `GTEST_SKIP()` with a clear message; coverage drops to 3-surface parity (Inspector + Toolbar + Menu) which is still meaningful.

## Out of scope

- Per-frame visual diff — v1.7.5
- Performance contract — v1.7.5
- Python binding coverage depth — v2.1
