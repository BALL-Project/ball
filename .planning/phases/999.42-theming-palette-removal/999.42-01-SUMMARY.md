# Phase 999.42 Plan 01: Palette removal + QSS objectName sweep + 999.41 icon carry-overs Summary

**One-liner:** Strip 7 dialogs' `<palette>` XML, ship ThemedIconEngine
(per-DPR state-tinted SVG renderer) + Icons::get façade, migrate 22
call sites off IconLoader, delete 3 XPM arrays + icons.{h,C} — all
gated behind BALL_UI_V2 (default OFF in v1.7).

## Context

Phase 999.42 = Handover Phase 1 (palette removal,
`Claude Design Handover/revitalization/01-phase-theming.md`) + Handover
Phase 2 tail (`02-phase-icons.md` §2.2 ThemedIconEngine + §2.3 call-site
rewrites + §2.4 XPM removal + §2.6 packaging icon regen).

Per the 2026-05-17 ROADMAP audit pull-in, Wave-4 was re-pinned for v1.7
RC stages and Phase 999.42 absorbed the 999.41 forwarded carry-overs.
The phase ships unconditionally per maintainer-Q3 resolution (single
neutral theme — palette removal is hygiene + OS palette inheritance,
not theme-picker breadth).

Built on:
- 999.40 ThemeManager + `tokens.h` (kInkSoft/kInk/kAccent/kInkMuted
  used as tint colors by the new engine).
- 999.41 SVG-preferred IconLoader wedge + theme.qrc `/icons` prefix
  (engine pulls SVGs from the same QRC).
- 999.41 Qt6::Svg link surface (engine uses QSvgRenderer).
- ci.yml `ui_v2: [ON, OFF]` axis added 2026-05-17 (Handover §10
  CI gate 6).

## What landed (each commit, briefly)

1. **Inventories + strip script.** Generated three inventory files
   under `revitalization/inventory/` and committed
   `revitalization/scripts/strip-palettes.py` (re-port of Handover §1.1
   spec). Actual counts: **61 .ui files in tree, 7 with `<palette>`**
   (Handover claimed 52 / 38 — the bulk of palette removal happened
   organically since the doc was authored).

2. **Palette strip.** -3,612 lines of legacy beige `<palette>` XML
   removed from 7 dialogs. Script regex updated to handle both
   modern `name="palette">` and Qt-Designer-3-era
   `name="palette" >` (with trailing space). All 7 still compile
   through `uic` (Qt 6.10 + 6.11 verified locally).

3. **Semantic-color audit.** Verified that all semantic colors (residue
   swatches, status badges, RGB-slider previews) flow through C++
   helpers (`ColorButton::setColor`, `QTableWidgetItem::setBackground`,
   `VIEW::setColor`) regardless of `<palette>` presence. Zero code
   restore needed.

4. **objectName sweep audit.** Verified all 61 .ui files set a root
   `objectName`. Qt-Designer-default `Ui_<Name>Data` convention is
   universal — QSS rules like `QDialog#AboutDialog` work today.

5. **lupdate deferred.** Running Qt 6.11 lupdate would produce 10,646
   lines of churn (TS schema 2.0→2.1, source-text drift across the
   tree). Palette strip itself contributes zero translatable-string
   changes. Forwarded as dedicated `chore(i18n)`.

6. **ThemedIconEngine.** `QIconEngine` subclass under BALL_UI_V2 that
   loads `:/icons/<name>.svg`, tints by `QIcon::Mode`
   (Normal/Active/Selected/Disabled → kInkSoft/kInk/kAccent/kInkMuted),
   composites via `QPainter::CompositionMode_SourceIn`, caches per
   `(size, mode, dpr)`. State tints, not theme tints (Q3 doesn't
   block).

7. **IconRegistry + Icons::get façade.** Single API for all icon
   lookups. Under BALL_UI_V2 → `QIcon(new ThemedIconEngine)`; under
   OFF → delegates to `IconLoader::instance().getIcon` (legacy PNG
   walk). API contract is identical either way.

8a-h. **22 call-site migrations.** Per-file atomic commits across
   8 files: mainframe.C (6), pluginDialog.C (2), editMode.C (3),
   mainControl.C (1), modularWidget.C (1), SDWidget.C (1),
   propertyEditor.C (3), scene.C (5). All use
   `VIEW::Icons::get("foo")`; `loader` cache locals dropped where
   unused.

10. **3 new Lucide SVGs.** `activity.svg`, `zap.svg` vendored as new
    Lucide v0.460.0 ISC; `ball-app.svg` shipped as Lucide-atom-derived
    placeholder (bespoke artwork to Phase 8 per its header). theme.qrc
    extended with the 3 matching aliases under `/icons/`.

9a/b/c. **XPM array removal.** All 3 production XPM arrays gone:
    `bucky_64x64_xpm` (mainframe.C window icon → `Icons::get("ball-app")`,
    icons.{h,C} deleted, CMake SOURCES_LIST updated),
    `simulation_running_xpm_` (mainControl status indicator →
    `Icons::get("actions/simulation-running").pixmap(14,14)`),
    `mini_ray_xpm_` (serverWidget status indicator →
    `Icons::get("actions/raytracing").pixmap(14,14)`). Header
    declarations also dropped (including orphan `simulation_stoped_xpm_`).

11. **.icns/.ico regen deferred.** Three structural reasons (wrong
    hook, missing toolchain on CI runners, placeholder artwork) push
    this to Phase 8 packaging where both the bespoke artwork AND
    pipeline land together. Full rationale in
    `ICNS-ICO-REGEN-DEFERRED.md`.

12. **iconLoader breadcrumbs updated.** v1.8-deferred `TODO` blocks
    replaced with "Phase 999.42: LANDED — see themedIconEngine.h"
    pointers. `[[deprecated]]` marker added to
    `IconLoader::getIcon` (target v2.0); diagnostic suppression at
    `iconRegistry.C` OFF-flag delegation (the legitimate fallback).
