## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 — Missing critical functionality] Python 2 print statements in `amberparser.py`**
- **Found during:** Task 5 verification (`python3 -c "import ast; ast.parse(...)"` failed).
- **Issue:** `amberparser.py` had 3 unmigrated Python 2 `print "..."` statements
  (lines 179, 199, 213). The file would not even parse on any Python ≥ 3.0
  (Python 2 EOL 2020). The plan only flagged this for the sibling
  `parmConverter.py`.
- **Fix:** Convert all 3 to `print(...)` calls. Verified with `ast.parse()`.
- **Files modified:** `data/Amber/converter/amberparser.py`
- **Commit:** `ea503f0af2`

**2. [Rule 2 — Missing critical functionality] `pyWidget.C` live reference to deleted `pywidget_init.py`**
- **Found during:** Task 9 pre-delete grep (`grep -rl pywidget_init source/`).
- **Issue:** `source/VIEW/WIDGETS/pyWidget.C` at lines 651 and 934 hard-coded
  `pywidget_init.py` as the BALLView PyBALL startup script filename. This
  branch is currently dormant (PyWidget is gated behind
  `BALL_PYTHON_SUPPORT=ON` in `source/VIEW/WIDGETS/sources.cmake`; v1.7 builds
  with PYTHON_SUPPORT=OFF), so the immediate v1.7 build is unaffected.
  However, when Phase 999.15 (v2.1 PyBALL v2) flips PYTHON_SUPPORT back on,
  the deleted file would cause runtime errors with no obvious cause.
- **Fix:** Update both call sites to reference `view_utils.py` (the
  replacement explicitly named in `pywidget_init.py`'s own deprecation
  notice). Added inline comments documenting the rationale.
- **Files modified:** `source/VIEW/WIDGETS/pyWidget.C`
- **Commit:** `c19d38a69e` (bundled with the file deletion in task 9)

No other deviations. No authentication gates encountered.

`source/VIEW/WIDGETS/pyWidget.C`, but that file is gated behind

NOT compiled in v1.7 (`BALL_PYTHON_SUPPORT=OFF` in every preset). So the
comment-only-plus-string-literal-rename change cannot affect the v1.7 CI
build. (When 999.15 flips the flag, the file will then need to compile;
the change is a single string-literal rename plus comments — trivially
safe.)
