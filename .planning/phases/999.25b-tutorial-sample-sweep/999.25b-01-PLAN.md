# Phase 999.25b Plan 01: Tutorial / Sample-tree Sweep for v1.7

## Objective

Audit every tutorial source, example program, and sample data file shipped under the repo
and classify each as **KEEP**, **UPDATE**, or **REMOVE** against the v1.7-modernized
codebase. Apply the resulting changes as atomic commits.

This is a documentation / sample-tree pass, **not** a renderer or library change. No
public API surface is touched.

### C. `doc/examples/PYTHON/` — Python example scripts (46 files across BALLView/, UTILITIES/, howtos/)

Every Python example here imports the **SIP-based BALL/VIEW Python bindings** (e.g.
`from BALL import ...`, `MainControl.getInstance(0)`, `Path().find(...)`). The
SIP bindings are **DISABLED** in the v1.7 build (`BALL_PYTHON_SUPPORT=OFF` in
every `ci-*` preset; CLAUDE.md "Removed/disabled" line explicitly lists
"SIP Python bindings"). They will not be re-enabled in v1.7. Phase 999.15 PyBALL
v2 is the rewrite path and is **deferred to v2.1** per the v2.0 substrate plan.

These scripts are therefore **stranded** under v1.7: they reference an API surface
that the v1.7 build does not expose. Two options were considered:

- **REMOVE all** → loses the design corpus that 999.15 will need as a reference.
- **KEEP + add a README** → preserves the corpus, makes the situation explicit.

We pick **KEEP + add a stub README** because: (a) the scripts are valuable as a
spec for what the PyBALL v2 surface needs to support; (b) they cost nothing
(46 small text files, ~few KB total) to keep in tree; (c) deleting them now means
re-archaeology when 999.15 starts. The README makes the "won't run in v1.7" reality
unambiguous so users don't try and hit confusing import errors.

| Path                                              | Class | Notes                                                                                                             |
| ------------------------------------------------- | ----- | ----------------------------------------------------------------------------------------------------------------- |
| `doc/examples/PYTHON/BALLView/*.py` (28 files)    | KEEP  | All require SIP bindings + live BALLView session. Stranded until Phase 999.15. New `README.md` documents this.    |
| `doc/examples/PYTHON/UTILITIES/*.py` (16 files)   | KEEP  | All `import BALL`. Stranded until Phase 999.15. Covered by the same README.                                       |
| `doc/examples/PYTHON/howtos/*.py` (2 files)       | KEEP  | Same.                                                                                                              |

**New file:** `doc/examples/PYTHON/README.md` — single page stating the
