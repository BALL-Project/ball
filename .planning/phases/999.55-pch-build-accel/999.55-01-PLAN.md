TEST target definitions — test/CMakeLists.txt (the files to modify):
- BALL class tests, lines 44-59: `FOREACH(group ${BALL_TESTS})` / `FOREACH(test ${${group}})` → `ADD_EXECUTABLE(${test} ${test}.C)`; `TARGET_LINK_LIBRARIES(${test} BALL ${BALLTEST_SUPPORT_LIBRARIES})`; `SET_TARGET_PROPERTIES(${test} PROPERTIES COMPILE_FLAGS "${Qt5Core_EXECUTABLE_COMPILE_FLAGS}")`.
- VIEW tests, lines 142-173: `IF (BALL_HAS_VIEW)` / `FOREACH(test ${VIEW_TESTS})` → `ADD_EXECUTABLE(${test} ${test}.C)`; `TARGET_LINK_LIBRARIES(${test} BALL VIEW ${BALLTEST_SUPPORT_LIBRARIES})`; same `COMPILE_FLAGS`; plus `ENVIRONMENT "QT_QPA_PLATFORM=offscreen"`.
- 298 total `*_test*.C` TUs. CMAKE_MINIMUM_REQUIRED is 3.21 (REUSE_FROM needs ≥3.16 — satisfied).

REUSE_FROM flag-compatibility constraint:
- `libBALL`/`libVIEW` are `ADD_LIBRARY(... SHARED ...)` → compiled with position-independent code (-fPIC on GCC/Clang). A target reusing their PCH must compile with compatible flags or the build fails with "PCH file was compiled with different flags". The standard fix is to set `POSITION_INDEPENDENT_CODE ON` on each PCH-reusing test executable so its flags match the SHARED-library PCH. (No effect / harmless on MSVC, which has no -fPIC concept.)
