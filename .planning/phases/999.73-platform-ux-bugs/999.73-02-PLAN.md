ROOT CAUSE (confirmed at HEAD 1db62125cf) in source/SYSTEM/directory.C:
- countItems() returns (size - 2) on BOTH the Windows (l.305) and POSIX (l.319)
  branches, subtracting "." and ".." (comment l.321).
- getFirstEntry() (l.110) and getNextEntry() (l.180) return the RAW entries from
  FindFirstFileA/FindNextFileA (Windows) and readdir (POSIX), which INCLUDE "."
  and "..". So a getFirst/getNext loop visits countItems()+2 entries.
- Reporter (#627) hit this on Windows/VS15. The same leak exists on POSIX; the
  existing Directory_test masks it by skipping "."/".." in the test body
  (Directory_test.C:231-247) — exactly the class-level inconsistency #627 wants fixed.
- The canonical skip pattern already exists: countFiles()/countSubdirectories()
  compare against FileSystem::CURRENT_DIRECTORY and FileSystem::PARENT_DIRECTORY
  (directory.C:517-518, 551-552). Reuse it.

SECONDARY INCONSISTENCY (fix while here): getFirstEntry() is guarded by
#ifdef BALL_OS_WINDOWS (l.112) but getNextEntry()/countItems() use
#ifdef BALL_COMPILER_MSVC (l.182, l.264). On MinGW these diverge, mixing the
Win32 first-entry path with the POSIX next-entry path. Unify all three to
#ifdef BALL_OS_WINDOWS (the OS-level macro, correct for the Win32 path).
</context>
