# Phase 999.73 Plan 02: Directory consistency on Windows Summary

Fixed BUG-627 (#627): `Directory::getFirstEntry`/`getNextEntry` now skip the synthetic `.` and `..` entries on both the Win32 and POSIX paths, so a getFirst/getNext loop visits exactly `countItems()` entries on every platform, and the enumeration guards are unified on `BALL_OS_WINDOWS`.

## What Was Built

### Task 1 — directory.C fix (commit 8f8125e820)

Root cause confirmed at HEAD: `countItems()` returns `size - 2` (dropping `.`/`..`) on both the Windows (`FindFirstFileA`/`FindNextFileA`) and POSIX (`readdir`) branches, but `getFirstEntry`/`getNextEntry` returned the raw API entries **including** `.`/`..`. A getNext loop therefore over-iterated by 2 versus `countItems()` — the inconsistency the reporter hit on Windows/VS15. The same leak existed latently on POSIX, masked only by the old test skipping `.`/`..` in its body.

Exact change (both platform paths):
- **getFirstEntry()** — after the first `FindFirstFileA` (Windows) / `readdir` (POSIX) result, advance while the name equals `FileSystem::CURRENT_DIRECTORY` or `PARENT_DIRECTORY`; on stream end, close handles and `desynchronize_(false)`; otherwise return the first real entry.
- **getNextEntry()** — wrap the `FindNextFileA` / `readdir` advance in a loop that keeps advancing while the name is `.`/`..`; also skip `.`/`..` in the forgot-to-call-FirstEntry recovery branch.
- **Guard unification** — changed `getNextEntry()` and `countItems()` from `#ifdef BALL_COMPILER_MSVC` to `#ifdef BALL_OS_WINDOWS`, matching `getFirstEntry()`, so all three take the Win32 path on Windows regardless of compiler (fixes the latent MinGW path-mixing bug where the Win32 first-entry path was paired with the POSIX next-entry path).
- `countItems()`'s `(size - 2)` arithmetic left unchanged. Reused the existing `FileSystem::CURRENT_DIRECTORY`/`PARENT_DIRECTORY` skip pattern (already used by `countFiles`/`countDirectories`/`find`); `fileSystem.h` and `<cstring>` were already included.

### Task 2 — test strengthening + verification (commit f47ac19e80)

- Added `[EXTRA] enumeration count equals countItems() (BUG-627, #627)`: creates a directory with 4 known real entries, iterates it with `getFirstEntry`/`getNextEntry`, and `TEST_EQUAL`s the loop count to `countItems()` (4); asserts no returned entry is `.` or `..`.
- Strengthened the existing `getNextEntry` CHECK: removed the skip-`.`/`..`-and-continue workaround and now directly `TEST_NOT_EQUAL`s every returned entry against `.` and `..`, since the class filters them.
- Kept all `cleanup()` calls.
