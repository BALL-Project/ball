<objective>
Stop supplied project files from overriding user settings (BUG-621, #621).
Project files embed a full copy of the BALLView INI; loading one calls
fetchPreferences()+applyPreferences(), clobbering the user's current preferences
with the (often stale) copy baked into the project. Separate project-STATE load
(representations, scene, systems) from user-SETTINGS restore so opening a project
— including PresentaBALL's per-click project loads — leaves user settings intact.
</objective>

ROOT CAUSE (confirmed at HEAD 1db62125cf) in source/VIEW/KERNEL/mainControl.C:
- saveBALLViewProjectFile (l.1989) builds an INIFile with a BALLVIEW_PROJECT
  section (representations via storeRepresentations l.2004, TurnPoint l.2011) and
  then calls writePreferences(out) (l.2014) — embedding the ENTIRE user
  preference set (all ModularWidget prefs + the preferences dialog) into the
  project file.
- loadBALLViewProjectFile (l.2065) reads that INIFile back and calls
  fetchPreferences(in) (l.2113) + applyPreferences() (l.2114). fetchPreferences
  (l.1120) restores working dir, font, the preferences dialog, and every
  ModularWidget's prefs from the project's stale copy — overwriting the user's
  live settings. This is exactly #621.
- Project STATE (what the project legitimately owns) is restored separately AFTER
  this, from the BALLVIEW_PROJECT section (representations / turn point / the
  System composites that follow the INI lines in the file). That part must stay.

FIX (separate state from settings): on load, restore ONLY the BALLVIEW_PROJECT
section and the systems, NOT the user preferences. Two coordinated changes in
mainControl.C:
  (a) loadBALLViewProjectFile: remove (or guard out) the fetchPreferences(in) +
      applyPreferences() calls (l.2113-2114). Replace with restoring just the
      project-owned state already handled below (representations, turn point,
      systems). Keep applyPreferences() ONLY if it is needed to re-render with the
      user's EXISTING (unchanged) preferences — if so, call it without first
      fetching from the project INI.
  (b) saveBALLViewProjectFile: stop embedding user preferences — remove the
      writePreferences(out) call (l.2014) so newly-written project files carry
      project state only. (Old project files that still contain a [preferences]
      copy are now harmless because load no longer reads them.)
Net effect: project files become pure project state; user settings live solely in
the user's INI (preferences_file_, fetched at startup l.626 and written at exit
l.691) and are never touched by project load.

QT_NO_KEYWORDS is in effect: use Q_EMIT/Q_SIGNALS/Q_SLOTS.
</context>
