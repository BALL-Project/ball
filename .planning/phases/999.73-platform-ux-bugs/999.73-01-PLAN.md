ROOT CAUSE (confirmed at HEAD 1db62125cf) — degenerate-solution ordering
non-determinism, NOT an algorithmic bug:

- apply(n) enumerates optimal bond-order assignments out of a
  std::priority_queue PartialBondOrderAssignment (AStarBondOrderStrategy.C:30).
  AMPTRB10_kek_sol0.mol2 has 7 distinct OPTIMAL solutions (test2.C:784).
- The ordering is PartialBondOrderAssignment::operator<
  (partialBondOrderAssignment.C:36). For two entries with EQUAL coarsePenalty():
  when use_fine_penalty_ is true it tie-breaks on finePenalty() (so the FINE
  subtest test2.C:990-1002 passes everywhere); when use_fine_penalty_ is false it
  returns false for BOTH orderings — the entries are equivalent. Equivalent
  entries pop in an order set by heap array positions (push order + push_heap /
  pop_heap), which differs between libc++ (macOS), libstdc++ (Linux), MSVC STL.
- Result: apply(5) with USE_FINE_PENALTY=false (test2.C:1005-1010) returns a
  different 5th optimal solution per platform. Matches report #576 exactly and
  the CMake quarantine note (test/CMakeLists.txt:84-104, fails only Apple Silicon).

Current conditional quarantine (test/CMakeLists.txt:99-104):
  IF (APPLE AND CMAKE_SYSTEM_PROCESSOR MATCHES "arm64|aarch64")
    SET_TESTS_PROPERTIES(AssignBondOrderProcessor_test2 PROPERTIES WILL_FAIL TRUE)
  ENDIF()

Members for tie-break (partialBondOrderAssignment.h): finePenalty() ==
estimated_bond_length_penalty (l.100), vector<short> bond_orders (l.105),
Position last_bond (l.108).

Current operator< is a MAX-priority-queue comparator (returns true when *this is
worse / lower priority than b, so the queue pops the LOWEST penalty first —
preserve this). It compares coarsePenalty(); on coarse-tie it only tie-breaks on
finePenalty() when abop->use_fine_penalty_ is set, otherwise returns false for
both orderings (the determinism hole).
</context>
