<objective>
Scope BALLView keyboard shortcuts appropriately (BUG-622, #622). High-impact
shortcuts (Del, Space, Ctrl+C/V/X) are global to the main window, so they fire
regardless of focus — deleting structures from the wrong context and stealing
keystrokes from text fields and the embedded web view. Constrain those shortcuts
to the widget context that should own them.
</objective>

ROOT CAUSE (confirmed at HEAD 1db62125cf):
- Menu actions are created in MainControl::insertMenuEntry (mainControl.C:938)
  via popup->addAction(...) (l.960) / addAction + setShortcut (l.964-965). The
  shortcut context is NEVER set, so it defaults to Qt::WindowShortcut and fires
  whenever the main window is active, regardless of which child widget has focus.
- High-impact actions: Delete = MainControl::delete_action_ (mainControl.C:1751,
  slot deleteClicked_); Cut/Copy/Paste = molecularControl.C cut_id_/copy_id_/
  paste_id_ (l.983-993), owned by MolecularControl.
- Qt fix: set the high-impact QAction shortcutContext to
  Qt::WidgetWithChildrenShortcut and make the action reachable from the widget
  that should own it, so the shortcut only resolves when that subtree has focus.
  Leave genuinely application-wide safe accelerators (Quit, Preferences) as
  WindowShortcut. Do NOT blanket-change insertMenuEntry. The embedded
  QtWebEngineView keeps Space/Del/Ctrl+C/V/X for its own input once the BALLView
  actions are scoped off WindowShortcut.

QT_NO_KEYWORDS is in effect: use Q_EMIT/Q_SIGNALS/Q_SLOTS.
