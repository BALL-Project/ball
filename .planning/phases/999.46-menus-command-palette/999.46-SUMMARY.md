# Phase 999.46 Plan 01: Menus + command palette Summary

**One-liner:** 8-task-coded top-level menubar + Cmd/Ctrl+K
CommandPalette with fuzzy match and ?/>/: prefix modes, behind
`BALL_UI_V2`, plus macOS per-action standard-role plumbing for the
3 system items (About / Preferences / Quit).

## What Was Built

### CommandRegistry (Task 1)

`BALL::VIEW::CommandRegistry` — process-singleton owning the
canonical Command list. Each `Command` is a POD with `id` (stable),
`title`, `category`, `description`, `shortcut`, `icon`, plus
`std::function<void()>` triggers and a non-owning `QPointer<QAction>`
back-pointer. Public API: `registerCommand` (idempotent on id),
`registerFromAction(QAction*, category)` (the convenience the
insertMenuEntry hook calls), `overrideCategory(QAction*, category)`
(plugin late-binding), `all()` / `search(query)` / `recent()` /
`noteTriggered(id)` / `clearForTest()`.

Fuzzy `search` scores results: exact prefix > word boundary >
subsequence; sorted highest-first.

### Auto-register hook (Task 2)

`MainControl::insertMenuEntry` gained a 12-line block (BALL_UI_V2-gated)
that calls `CommandRegistry::instance().registerFromAction(action, category)`
after a successful action creation. Category = parent-menu title
with the Qt mnemonic ampersand stripped. Every existing
`insertMenuEntry` call-site in `MainControl` + `Mainframe` +
widgets/dialogs/datasets — across both `source/VIEW/*` and
`source/APPLICATIONS/BALLVIEW/*` — now lands in the registry
without per-callsite edits.

### Menu remap to 8 top-level menus (Task 3)

Under `BALL_UI_V2` the menubar reorganizes to **File · Edit · Select ·
View · Compute · Scripts · Window · Help** per the Handover §06
18-row mapping table. Strategy: re-route at the
`initPopupMenu` switch (re-title `DISPLAY` to View, `MOLECULARMECHANICS`
to Compute, `TOOLS` to Scripts, `WINDOWS` to Window, route `BUILD` as
`Edit › Structure` submenu, route `MACRO` as `Scripts › Macros`
submenu). Existing callers don't need updating. The new top-level
`SELECT` menu (10900) is the only structural addition that required
per-callsite changes — Invert Selection + Clear Selection in
mainframe.C now route conditionally to `SELECT` under v2, `EDIT`
under OFF.

Window menu (v2) lists workspace presets (Default / Classic /
Focused) populated from `WorkspaceManager` (999.45 API).

### macOS standard-role plumbing (Task 4)

Quit (`QuitRole`), Preferences (`PreferencesRole`), About (`AboutRole`)
all get `setMenuRole(...)` applied unconditionally. On macOS Qt
auto-relocates the actions into the BALLView application menu in
the system menubar (BALLView ▸ Quit BALLView / Settings… / About
BALLView). On Linux/Windows Qt is a no-op — pure-win application.
Maintainer Q1 keep-inline-menubar constraint respected: this is
per-action standard-role plumbing, NOT full `QMenuBar`
global-menubar mode.

### CommandPalette widget (Task 5)

`BALL::VIEW::CommandPalette` — 560 px floating `Qt::Popup` sheet
centered on parent. Top: `QLineEdit` with "Type a command, or ?"
placeholder. Below: `QListView` over `CommandPaletteModel` (which
adapts `CommandRegistry::search()` to `QAbstractListModel`).
`CommandPaletteDelegate` renders each row with title (bold, left) +
category chip + shortcut (monospace, right) + icon. Help mode (`?`
prefix) grows rows to 56 px and renders description text below the
title.

Wiring in `Mainframe::Mainframe` (BALL_UI_V2-gated): construct one
palette parented to the main window after all menu entries are
registered, then bind a global `QShortcut` on
`QKeySequence(Qt::CTRL | Qt::Key_K)` (Qt translates CTRL → ⌘ on
macOS) with `Qt::ApplicationShortcut` context so the palette opens
regardless of focus.

### Command palette `?`/`>`/`:` prefix modes (Task 6)

Implemented in `CommandPaletteModel::setQuery`:
- `?` → help mode (delegate switches to 2-line rendering with
  prominent description).
- `>` → file mode (results restricted to category == "File").
- `:` → navigation (results restricted to commands whose id
  starts with `view.workspace.`, `window.`, `view.inspector.`, or
  `file.recent.`).
- (plain) → fuzzy search all.

Mode-aware tooltip on the line edit hints at the active mode
without leaving the input.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Qt6 QRegExp removal in CommandRegistry::score_**
- **Found during:** Task 1 first build.
- **Issue:** `QRegExp` is removed in Qt 6; `title.split(QRegExp(...))`
  fails to compile.
- **Fix:** Switched to `QRegularExpression` + static-const cache.
- **Files modified:** `source/VIEW/KERNEL/commandRegistry.C`.
- **Commit:** Rolled into the Task 1 commit (`2e0fc371d4`) — fixed
  before the first commit landed.

**2. [Rule 1 - Bug] AUTOMOC dangling-link in OFF cell**
- **Found during:** Task 1 first OFF-cell build.
- **Issue:** Original design gated `commandRegistry.C` impl behind
  `#ifdef BALL_UI_V2` but kept the `Q_OBJECT` class declaration in
  the header unconditional. AUTOMOC scanned the header, generated
  moc_commandRegistry.cpp referencing `CommandRegistry::~CommandRegistry()`,
  which was missing because the impl TU was empty in OFF.
- **Fix:** Wrapped the whole class declaration (including
  `#include <QtCore/QObject>` etc.) in `#ifdef BALL_UI_V2` at the
  header level. OFF cell now sees no class at all. No call-site
  edits needed because every CommandRegistry call-site is itself
  BALL_UI_V2-gated.
- **Files modified:** `include/BALL/VIEW/KERNEL/commandRegistry.h`.
- **Commit:** Rolled into the Task 1 commit (`2e0fc371d4`).
- **Carry-over:** Applied the same idiom to `CommandPalette` +
  supporting model/delegate (Task 5) preemptively.
