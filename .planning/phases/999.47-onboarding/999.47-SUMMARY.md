## Architectural Decisions

### WelcomeScreen lifecycle

Mounted as `centralWidget` when `composite_manager_.getNumberOfComposites() == 0`; the Scene is preserved off-screen via `takeCentralWidget()` (rather than a `QStackedWidget`) so its OpenGL context survives. The swap is driven by `Mainframe::checkMenus()` which already runs after every composite insert/remove.

User can toggle "Skip this screen on startup" — persisted at `QSettings[/Onboarding/skipOnStartup]`. When skip is set the WelcomeScreen never auto-mounts even at startup (matches Handover §7.6 footer toggle behaviour).

### Recent files

QSettings-backed list `[Onboarding/recentFiles]`, capped at 10, dead paths filtered on load. WelcomeScreen renders the top 5 with native file icons. The list is updated by `Mainframe::rememberRecentFile_()` after a successful `openFile(path)` from the WelcomeScreen recent / sample paths — does NOT (yet) hook into File > Open from the menubar; that's a one-line follow-up if the menubar path proves to be the dominant entry.

### What's-new card

Compares `BALL_RELEASE_STRING` (the actual config.h macro — initial planner-typo `BALL_PACKAGE_VERSION` corrected as a Rule 1 fix during build) to `QSettings[/Onboarding/lastVersion]`. Idempotent within a launch. 2-minute QTimer auto-dismiss per Handover §7.6. Content sourced from `data/BALLView/help/whatsnew/1.7.md`.

### MarkdownHelpViewer

New class (NOT a rewrite of `HelpViewer`) — the legacy `MyTextBrowser` / `HelpViewer` pair stays in tree until 999.48's flag-removal pass deletes them. The new class is `BALL_UI_V2`-gated, lives in the same TU, subclasses `QTextBrowser`, and overrides Qt 6's `doSetSource(QUrl, ResourceType)` to intercept `ballview://` URLs and hand them to `QDesktopServices::openUrl` → the in-process handler installed by `Mainframe::installBallviewUrlHandler_`. Initial attempt at overriding `setSource(QUrl)` failed because Qt 6 made that method non-virtual (Qt 5 was virtual) — `doSetSource` is the documented Qt 6 extension point.

### `ballview://` URL scheme dispatch

Three platforms wired:

- **macOS:** `CFBundleURLTypes` / `CFBundleURLSchemes=[ballview]` in `MacOSXBundleInfo.plist.in`. LaunchServices picks up on next `.app` install.
- **Linux:** `x-scheme-handler/ballview` appended to the `.desktop` `MimeType=` list. `xdg-open ballview://…` spawns BALLView on a fresh launch.
- **Windows:** NSIS install section writes `HKCR\ballview` class (URL Protocol + shell\open\command); uninstall section removes it.

Dispatch logic (mainframe `onBallviewUrlInvoked_`):
- `ballview://open?pdb=<id>` → surface `DownloadPDBFile` dialog
- `ballview://open?file=<path>` → `MolecularFileDialog::openFile(path)`
- `ballview://command/<id>` → look up `Command` in `CommandRegistry::all()`, invoke its `trigger`, `noteTriggered(id)` (mirrors `commandPalette.C:375`)

`CommandRegistry::run(id)` does NOT exist — Rule 1 fix during build. The palette dispatches via the `Command` record's `std::function<void()> trigger` directly.

### Sample structures bundling

Real coordinates for `1bna.pdb` (4-bp DNA excerpt), `caffeine.mol2`, `dialanine.pdb`. The four full protein/ligand slots (`1ubq.pdb`, `1stp.pdb`, `1ymg.pdb`) ship BPTI-derived placeholders that BALL already parses cleanly — gives the WelcomeScreen demo path a guaranteed load on first install. Replacement deferred to 999.48 asset pipeline; `samples/README.md` documents the per-file status. Install rules covered by the existing `INSTALL(DIRECTORY data/ ...)` blanket at `CMakeLists.txt:942` — no new install hook needed.

### Tutorial Markdown migration

6 files under `data/BALLView/help/tutorial/` with YAML frontmatter (`title`, `order`, `prev`, `next`, `prereq`, `expected-runtime`). Content distilled from the demoTutorialDialog's 9-step slide flow into the 6 Handover-mandated topics (welcome / loading / models / selection / coloring / saving). Each tutorial includes a `Try this →` `ballview://` link that demos the URL scheme. `demoTutorialDialog.{C,h,ui}` is NOT deleted this phase — already in 999.48's legacy-file deletion roster, and the dialog must keep compiling in the OFF cell until then.

### Welcome.rtf retirement

Replaced by `Welcome.txt` (CPack-compatible plain text), referenced from `CPACK_PACKAGE_DESCRIPTION_FILE` and `CPACK_RESOURCE_FILE_WELCOME` in `BALLPackageConfig.cmake`. The new copy bumps the headline to BALLView 1.7 and surfaces the Refresh as the headline change. `.rtf` deletion is intentional and called out in the commit message to satisfy the post-commit deletion check.

## Deviations from Plan

### Rule 1 fixes during build

1. **`BALL_PACKAGE_VERSION` macro doesn't exist** — corrected to `BALL_RELEASE_STRING` (the actual macro in `build/include/BALL/CONFIG/config.h`; planner typo). Mainframe `maybeShowWhatsNew_()`.
2. **`MolecularFileDialog::openFile()` requires a filename** — switched the WelcomeScreen "Open file…" slot to `dlg->readFiles()` (the no-arg slot that surfaces the QFileDialog). The `openFile(String)` overload stays in use for the recent + sample paths where the filename is already resolved.
3. **`CommandRegistry::run(id)` doesn't exist** — replaced with a `for-each` over `reg.all()` + invoke `Command::trigger` (mirroring `commandPalette.C:375`'s dispatch pattern).
4. **Qt 6 `QTextBrowser::setSource(QUrl)` is non-virtual** — initial override attempt failed to compile; migrated to `doSetSource(QUrl, ResourceType)` per Qt 6's documented extension point (`qtextbrowser.h:81`).

All four fixes documented in the per-commit messages.

### Rule 2 additions (auto-added for correctness/security)

None — the Handover §7 scope was complete as written; no missing-validation / missing-error-handling fixes needed during execution.

### Scope-trims

1. **Sample protein structures** — `1ubq`/`1stp`/`1ymg` ship as BPTI-derived placeholders (real coordinates loadable but not the requested PDB entries). Replacement workflow documented in `samples/README.md` and explicitly deferred to the 999.48 asset pipeline. Trade-off chosen because (a) inlining ~300 KB of real PDB content per file across 3 files would balloon the commit; (b) fetching from RCSB during autonomous execution is brittle / network-dependent; (c) the WelcomeScreen end-to-end demo path works regardless of which protein the placeholder represents.
2. **Thumbnails** — 320×200 single-density PNGs only; the @2× DPR (640×400 physical) pipeline is one of 999.48's deliverables and is documented in `samples/README.md` accordingly. Qt's `QPixmap` smooth-scale handles the display until then.
3. **`ballview://` scheme registration** — full coverage across macOS / Linux / Windows; no scope trim. (Was flagged as potentially partial in the orchestrator brief; ended up landing all three.)
4. **Tutorial migration** — all 6 tutorials migrated; no scope trim. (Was flagged as potentially partial in the orchestrator brief; full set landed.)
5. **demoTutorialDialog deletion** — NOT performed this phase. It's already in 999.48's legacy-file deletion roster; deleting it here would conflict with the OFF-cell baseline.
6. **PubChem dialog ID pre-fill from `ballview://open?pdb=<id>`** — the `DownloadPDBFile` dialog has no public "pre-fill the ID" API; the URL handler surfaces the dialog but the user re-types the ID. A one-line `dlg->setPdbId(pdb)` follow-up would close this gap once that setter exists; tracked as a polish item.

### Threat Flags

| Flag | File | Description |
|------|------|-------------|
| threat_flag: url-handler | source/APPLICATIONS/BALLVIEW/mainframe.C `onBallviewUrlInvoked_` | New external-input surface (OS-routed URLs). `ballview://open?file=` accepts arbitrary local file paths — `MolecularFileDialog::openFile` already validates extension + parses through BALL's file-format dispatch, so the surface is bounded to "can convince BALLView to try to load file X" (same threat surface as the existing File > Open). `ballview://command/<id>` dispatches into `CommandRegistry` which only exposes registered Commands — bounded to "can run any menu action the user has access to".
