## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] upload-artifact@v4 skips dotfiles by default**
- **Found during:** Task 2 (CI verification of run 25966184504/25967169707)
- **Issue:** `upload-artifact@v4` has `include-hidden-files: false` by default. `.ninja_log` starts with a dot and was not uploaded despite the file existing (Top-20 print step ran successfully, confirming the file was present).
- **Fix:** Added `include-hidden-files: true` to all 3 (later 4) upload-artifact steps.
- **Files modified:** `.github/workflows/ci.yml`
- **Commit:** 061a823

**2. [Rule 1 - Bug] Wrong ninja_log field index: $5 is cmd_hash, not output_path**
- **Found during:** Task 2 (artifact analysis after downloading from run 25968675219)
- **Issue:** ninja log v7 format is `start TAB end TAB mtime TAB output_path TAB cmd_hash`. The plan's PLAN.md interface doc and the original awk one-liner used `$5` (cmd_hash = 16-char hex) instead of `$4` (output_path = `CMakeFiles/.../*.C.o`). This caused the in-log Top-20 print to show hex hashes, not readable file paths.
- **Fix:** Changed awk to use `$4` with a `CMakeFiles/` filter to exclude autogen entries. Windows pwsh updated to use `$f[3]` (0-indexed) with `CMakeFiles\` filter.
- **Files modified:** `.github/workflows/ci.yml`
- **Commit:** c0d439c

**3. [Out of scope] Parallel session interference — multiple CI runs cancelled**
- **Found during:** Task 2 (CI triggering)
- **Issue:** A parallel agent session pushed 5+ commits while this plan executed, triggering the `cancel-in-progress: true` concurrency group and cancelling 3 of my CI runs. The parallel session also pre-emptively added `set +o pipefail` to the macOS/Linux top-20 steps (in commit "build: silence Apple-GL deprecations + fix ninja-log pipefail"), which was a correct fix for a real issue (GH Actions bash default `pipefail` + `sort | head` = SIGPIPE = step failure on ARM blocking jobs).
- **Outcome:** The parallel session's `set +o pipefail` fix is kept (it's correct). Total 4 CI runs triggered; 2 successful (25967169707 for baseline data, 25968675219 for artifact verification).

**4. [Out of scope] 4th matrix entry: linux-arm64**
- **Found during:** Task 1 (reading ci.yml matrix)
- **Issue:** The plan mentions 3 platforms (macOS, Linux, Windows) but the CI matrix has 4 entries (macos-arm64, linux-x64, linux-arm64, windows-x64). Both Linux entries share the `ci-linux` preset and `build/ci-linux/` directory, so the `startsWith(matrix.os, 'linux-')` condition was used for Linux steps. This correctly produces separate ninja-log artifacts per matrix entry (linux-x64 and linux-arm64) since `${matrix.os}` differs.
- **Outcome:** 4 artifacts produced instead of 3. Documented as expected behaviour for the expanded matrix.
