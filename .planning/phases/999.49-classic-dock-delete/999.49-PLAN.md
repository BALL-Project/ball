# Phase 999.49: Delete Classic 5-dock workspace preset

## Objective

Honor the maintainer-Q2 commitment ("v1.X deletes Classic" — one release
after Default ships) by deleting the **Classic** workspace preset
end-to-end. After this phase, the workspace picker offers Default +
Focused (+ any UserDefined presets). Users currently on Classic
auto-migrate to Default on first launch.

This is the **LAST UI phase of v1.7** — closes Wave 4 and unblocks the
v1.7-RC1 tag.

## Tasks

### Task 1 — Auto-migration for users currently on Classic
**type:** auto

Before deletion, add migration logic so users with
`[Workspace]/currentPreset=Classic` in their BALLView.ini are silently
remapped to Default on first launch with v1.7. The remap must happen
**before** any code path tries to call `apply(Classic, ...)` (so it
doesn't fall through to the about-to-be-deleted enum value via a
QString round-trip).

Implementation site: `source/APPLICATIONS/BALLVIEW/main.C`, in the
existing Phase 999.45 first-run block. Read the
`[Workspace]/currentPreset` key — if it equals `"Classic"`, overwrite
it with `"Default"` and apply Default. Log an info message:
`"v1.7 migration: legacy Classic workspace preset retired — falling
back to Default. (User-defined presets are unaffected.)"`

This is a one-time read+rewrite — no user prompt; v1.7 RELEASE-NOTES
explains the change.

**Verification:**
- Read `source/APPLICATIONS/BALLVIEW/main.C` migration block to
  confirm the read-classic → write-default branch fires before any
  subsequent `apply()`.
- `grep -n "v1.7 migration" source/APPLICATIONS/BALLVIEW/main.C`
  returns the log message.

**Files:** `source/APPLICATIONS/BALLVIEW/main.C`
