**Pre-fix state at [`include/BALL/KERNEL/atom.h:1033-1044`](../../../include/BALL/KERNEL/atom.h#L1033):**
```cpp
#ifdef BALL_COMPILER_MSVC
#include <vector>
// Phase 999.26 (v1.6.2): the next declaration produces the literal C4910
// pattern when compiling libBALL itself (BALL_EXPORT → __declspec(dllexport)
// + extern). MSVC's complaint is cosmetic — it still honors the dllexport
// and the symbol exports correctly; the warning is the only cost. Narrow
// `suppress` (next-statement-only) silences the 307 instances on this site
// without affecting other potential C4910 sites elsewhere in the tree.
// The architectural alternative (move the extern decl to a client-only
// header) is a v2.0 candidate documented in 999.26's "out of scope."
#pragma warning(suppress: 4910)
extern template class BALL_EXPORT std::vector<Atom*>;
```

**Path-aware Windows trigger:** commit 7b07936 (CI-HARDEN-W1) added a path-aware trigger that
fires the Windows CI job WITHOUT manual Stage 2 promotion when any file in the high-risk path

**Idiom precedent:** [`include/BALL/COMMON/exception.h:16-19`](../../../include/BALL/COMMON/exception.h#L16)
uses the `push`/`disable`/`pop` triplet for C4251 (the dll-interface-string warning). The
`suppress:` directive is the narrower sibling — equivalent semantics for a single declaration,
no risk of forgetting the `pop`, and matches the "one warning, one declaration" shape of this
site exactly. Either spelling is correct BALL style; `suppress:` is preferred when the scope is
one declaration.

**Root cause one-liner (see ROADMAP.md:1366-1371 for the full chain):**
`extern template class BALL_EXPORT std::vector<Atom*>;` is the correct pattern for libVIEW's
sake (gives client TUs the dllimport hint so they don't implicit-instantiate and trip LNK2005),
but trips C4910 in libBALL's own TUs (where BALL_EXPORT → dllexport, contradicting `extern`).
MSVC still honors the dllexport — the warning is purely cosmetic. The narrow `suppress:` makes
the cosmetic noise go away without changing the working build.
