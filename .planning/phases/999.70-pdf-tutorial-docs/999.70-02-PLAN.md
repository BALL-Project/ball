<objective>
Document the scope of the Preferences "Restore Defaults" button (TUT-02 / #523): it resets the registered
preference values of the currently-selected preferences page, but deliberately does NOT reset the General
tab's font, language, or interface style. Per the issue, this is an intentional design decision (confirmed by
A. Hildebrandt) and the gap is purely documentation — users click Restore Defaults expecting font/language/style
to revert and are surprised when nothing visibly changes.

Deliver the documentation on two surfaces:
1. A user-facing in-app help page under `data/BALLView/help/` (the markdown help system already used for the
   BALLView tutorial pages and whatsnew notes).
2. A tooltip on the actual Restore Defaults button, so the explanation is present at the exact moment of confusion.

Purpose: Close a long-standing usability complaint (#523, open since the BALL 2.0 milestone) with accurate,
in-context documentation instead of changing the deliberate behavior.
Output: One help markdown page + a tooltip string; both autonomously verifiable.
</objective>

<facts>
Authoritative behavior, confirmed at HEAD:
- preferences.C: clicking Restore Defaults hits `dialogButtonsClicked_` -> `ResetRole` -> `setDefaultValues()`.
- `setDefaultValues()` calls `restoreDefaultValues()` on the *currently selected* PreferencesEntry page only
  (the selected tree item), via its registered objects — it does NOT reset all pages, only the open one.
- mainControlPreferences.C (the "General" tab) DELIBERATELY unregisters the style and language widgets from the
  reset path:
      unregisterObject_(style_box_);
      unregisterObject_(languageComboBox_);
  and the font is held in a separate `font_` member chosen via QFontDialog, also outside the registered-object
  reset path. THIS is the concrete technical reason font/language/style are not restored — it is intentional,
  not a bug. (Issue #523: Hildebrandt confirms "this is a design decision ... should be documented anyway.")
- The help system (helpViewer.C) renders markdown pages with YAML frontmatter (title/order/prev/next/prereq).
  Existing pages live in data/BALLView/help/tutorial/ and data/BALLView/help/whatsnew/.
- The Restore Defaults button is the standard `QDialogButtonBox::RestoreDefaults` button on `buttonBox`
  (declared in preferences.ui). It is reachable in the Preferences constructor as
  `buttonBox->button(QDialogButtonBox::RestoreDefaults)`. There is no .ui tooltip slot for it; set it in code.
</facts>
