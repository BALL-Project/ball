The material-transparency backend (the SAME path the legacy dialog uses).
From source/VIEW/DIALOGS/materialSettings.C (READ ONLY — reference, do not edit):
  - The legacy slider `transparency_factor_slider` has range 0–100 (materialSettings.ui).
  - apply() does: `material.transparency = transparency_factor_label->text().toFloat();`
    then `Scene::getInstance(0)->updateMaterialForRepresentation(current_representation_, material);`
  - So the property to reuse is `Stage::Material::transparency` (a float), pushed
    through `Scene::updateMaterialForRepresentation(rep, material)`.

From include/BALL/VIEW/KERNEL/stage.h (the material struct):
  struct Material { ...; float shininess; float transparency; };
  // transparency is a plain float field, range used by the legacy UI is 0–100.

From include/BALL/VIEW/WIDGETS/scene.h:
  void updateMaterialForRepresentation(Representation* rep, const Stage::Material& new_material);

MaterialController already routes through exactly this backend in apply()
(source/VIEW/KERNEL/controllers/materialController.C):
  - apply() seeds a `Stage::Material material;` from the rep's existing
    "Rendering::Material" property (or the Stage default), overwrites
    ambient_intensity / reflective_intensity / specular_intensity / shininess,
    then calls `scene->updateMaterialForRepresentation(rep_, material);`.
  - It currently LEAVES `material.transparency` untouched (an explicit comment
    at the "transparency stays as-is" line) — THIS is what the plan changes.
  - revert() reads the same material back and emits *Changed signals; apply()
    has a re-entrancy guard (ControllerApplyGuard apply_guard(applying_)).

The existing slider pattern in MaterialSection
(source/VIEW/WIDGETS/inspector/sections/materialSection.C):
  - `makePercentSlider_(content, init)` builds a 0–100 `LabeledSlider` with a
    "%" suffix; ambient/diffuse/specular use it. init is
    `static_cast<int>(controller_->XxxFactor() * 100.0f)`.
  - Each slider: connect(slider_, &LabeledSlider::valueChanged, this, &MaterialSection::onXxxChanged_);
  - onXxxChanged_(int v) does: `controller_->setXxxFactor(v / 100.0f); debounce_.start();`
  - Controller→UI sync: connect(controller_, &MaterialController::xxxFactorChanged,
    this, &MaterialSection::onControllerXxxChanged_); the slot guards
    `if (slider_->value() != iv) slider_->setValue(iv);`.
  - debounce_ is a single-shot QTimer(100ms) whose timeout calls
    onDebounceFire_() → controller_->apply().
  - Per-section reset is already wired: setResettable(true, ...) +
    connect(resetRequested, [this]{ controller_->revert(); controller_->apply(); }).
    revert() re-emits *Changed → sliders resync automatically. NO extra reset
    wiring is needed for the new slider — it inherits this for free as long as
    revert() handles transparency and the controllerTransparencyChanged sync
    slot is connected.
  - The destructor flushes a pending debounce: if active, stop() + onDebounceFire_().
