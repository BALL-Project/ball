<objective>
Resolve issue #636 (BUG-636): a memory leak in DisplayProperties, where
`DisplayProperties::rep_` was used as a temporary for both an owning (createRepresentation,
displayProperties.C:526) and a non-owning (displayProperties.C:190) raw pointer,
leaking the Representation when the owning path ran.

Important context: DisplayProperties was DELETED entirely in Phase 999.67
(legacy-dialog deletion — `git ls-files` shows no source/VIEW/DIALOGS/displayProperties.C;
only PLAN/SUMMARY archives remain), and the offending `rep_` member no longer
exists anywhere in the tree. The owning logic migrated into
`RepresentationBuilder::createRepresentation` (source/VIEW/MODELS/representationBuilder.C),
which `new`s a Representation, inserts it into the RepresentationManager (which
owns and deletes it via remove()/willBeUpdated()), and returns it — i.e. the
dual-use temporary that caused the leak is gone.

Purpose: confirm the leak is resolved-by-deletion with concrete evidence, and
fix any residual leak in the migrated path if one exists.
Output: a verified leak-free representation-creation path; an edit only if a
residual leak is found.
</objective>
