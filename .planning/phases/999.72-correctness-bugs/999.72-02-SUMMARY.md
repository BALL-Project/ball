# Phase 999.72 Plan 02: AromaticityProcessor fused-ring fix Summary

Fixed `AromaticityProcessor::aromatize` so a peri-/ortho-fused polycyclic aromatic system (pyrene) has every ring bond assigned the aromatic order, not just two of four rings (#539).

## What was built

- **Fixture** (`test/data/AromaticityProcessor_test_BUG539.sdf`): the kekulized COD molecule 73045 — the exact #539 reproducer — recovered from the issue's pastebin (`pastebin.com/raw/CNLs2PQ3`, still live). It is a Br-substituted pyrene plus an sp3 -C(H3) substituent: 16 ring carbons, 19 ring bonds, SSSR = 4 fused 6-rings.
- **Regression CHECK** (`test/AromaticityProcessor_test.C`, `[BUG-539]`): loads the fixture, applies `AromaticityProcessor`, counts bonds with `ORDER__AROMATIC`, and asserts `== 19` (all ring bonds of the fully-aromatized pyrene core).
- **Fix** (`source/QSAR/aromaticityProcessor.C`, `aromatize`): after the existing per-ring while-loop, added a fixed-point **system-level propagation pass**. Any original SSSR ring whose atoms are all aromatic-capable carbons (each has exactly one double bond or ≥1 aromatic bond) and which **shares a complete aromatic edge** (a ring bond whose two endpoints are both already `IsAromatic`) with the established system gets its ring bonds set aromatic (`Bond::IS_AROMATIC` + `setOrder(ORDER__AROMATIC)` under `overwrite_bond_orders_`). Iterated to a fixed point so chains of fused rings are all reached. The existing `IsAromatic`-property pass is preserved.

## Root-cause confirmation (red → green)

Instrumented the loop and traced the BUG539 molecule:
- The per-ring `extendAromaticSystem_` correctly merges the first rings (merge size 10, pi=10, Hückel ok). But the merged 16-atom system fails the strict single-ring Hückel test (`(16-2)%4 = 2 ≠ 0`), and the final fused benzene wing (atoms 6,7,8,9,10,11) is evaluated with `pi=0` (its fusion carbons' bonds were already turned aromatic, breaking `countPiElectrons_`'s per-carbon `d_count==1 || a_count==2` test) and **dropped entirely**.
- **RED:** the unfixed processor assigns 11 aromatic bonds (`got 11, expected 19`) — matching the buggy "aromatized" reference in the pastebin (only the anthracene-ish core).
- **GREEN:** with the propagation pass, all 19 ring bonds are aromatic; `[BUG-539]` passes AND the pre-existing 9-molecule CHECK still passes (`results[] = {0,6,0,6,6,6,0,6,0}` unchanged).

## Verification

## Deviations from Plan

None affecting scope. The plan's primary suggestion was to fix the per-ring branch/`extendAromaticSystem_` bookkeeping in place; I instead added a conservative additive propagation pass (Rule-3-adjacent design choice) because surgically altering the heavily-coupled while-loop heuristic carried a high risk of regressing the 9-molecule baseline. The propagation only ever ADDS aromaticity to all-sp2-carbon rings already fused (sharing a full aromatic edge) into the system, so non-aromatic rings are never touched — confirmed by the unchanged baseline.
