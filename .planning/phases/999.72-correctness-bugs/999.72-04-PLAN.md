<objective>
Fix issue #497 (BUG-497): creating a ribbon representation on selected atoms
yields the model for a DIFFERENT selection. Reproduction (from the issue, BALL
1.5 era): load 1igt, create a ribbon (by individual color) for chain A residues
27-32, 50-52, 89-97 and chain B residues 26-33, 51-57, 93-102 — the created
ribbon covers the wrong residues.

The DisplayProperties dialog that historically drove this was deleted in 999.67;
the model-build path now runs through RepresentationBuilder::createRepresentation
→ AddCartoonModel / AddBackboneModel. The defect is in how the selected
composites are expanded into model parts: the backbone/cartoon model groups
residues by chain / secondary structure and the selection filtering does not
preserve non-contiguous residue ranges (it renders a contiguous span or the
whole chain instead of the exact selected residues).

This is the GUI-visible, UAT-gated fix in the phase. The exact root-cause line
requires reproducing against a running GUI, so Task 1 is investigation; the fix
and a human verification follow.

Purpose: ribbon-on-selection must honor the user's exact (possibly
non-contiguous) residue selection.
Output: a selection-correct backbone/cartoon model path, confirmed by UAT.
</objective>
