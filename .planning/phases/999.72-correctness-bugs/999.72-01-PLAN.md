<objective>
Fix the SDGenerator infinite loop reported in issue #540 (BUG-540).

The hang is NOT in sdGenerator.C — the reporter (dstoeckel) traced it to
`BALL::RingAnalyser::sequenceRing` and supplied the fix in the issue. The
`while(!ring_atoms.empty())` loop spins forever when no remaining ring atom is
bound to `last_atom` (the inner `for` finds nothing to erase, the `while`
condition never changes), which then also leads to a downstream segfault in
`peelNextRing_`.

Purpose: SDGenerator must terminate on the #540 SMILES so Build-from-SMILES and
structure-diagram generation cannot hang the application.
Output: A bounded `sequenceRing` loop plus a regression test that locks termination.
</objective>

<!-- The exact loop to fix. From source/STRUCTURE/ringAnalyser.C, function
     void RingAnalyser::sequenceRing(std::vector<Atom*>& ring) (lines ~182-212). -->

Current (buggy) loop body — note the while condition never advances when the
inner for matches nothing:

  Size  last_index = 0;
  Atom* last_atom = start_atom;
  while(!ring_atoms.empty())
  {
    for (std::list<Atom*>::iterator ring_it = ring_atoms.begin();
                                    ring_it != ring_atoms.end(); ++ring_it)
    {
      if (last_atom->isBoundTo(**ring_it))
      {
        ring[++last_index] = *ring_it;
        last_atom = *ring_it;
        ring_atoms.erase(ring_it);
        break;
      }
    }
  }

The reporter-supplied fix adds a `found` flag and breaks the while when no atom
could be threaded in a full pass.
