# Phase 999.72 Plan 01: RingAnalyser::sequenceRing infinite-loop guard Summary

Bounded `RingAnalyser::sequenceRing` so a ring whose atoms cannot all be threaded into a single cycle terminates instead of spinning forever (and segfaulting downstream in `peelNextRing_`), the root cause of the #540 SDGenerator hang.

## What was built

- **Fix** (`source/STRUCTURE/ringAnalyser.C`, `sequenceRing`, ~line 196): added a `bool found` flag reset at the top of each `while(!ring_atoms.empty())` iteration, set true alongside the existing erase/break in the matching branch, and an `if (!found) break;` after the inner `for`. When a full pass over the remaining atoms threads none onto `last_atom`, the loop now exits. This is exactly the reporter (dstoeckel) fix from the issue.
- **Regression test** (`test/RingAnalyser_test.C`): a new CHECK builds a Molecule with four carbons where a0-a1-a2 form a chain and a3 is bonded only to a0, then passes the vector `{a0,a1,a2,a3}` to `sequenceRing`. The running chain a0→a1→a2 cannot reach a3, so the unfixed loop never empties the list. The assertion is "control returns" (plus size/first-atom sanity); the real signal is that the test no longer hangs.

## Root-cause confirmation (red → green)

- **RED:** built the test against the unfixed source and ran it; the process was still alive after 12 s and had to be killed (`STILL RUNNING after 12s -> HANG CONFIRMED`). The unfixed `while` condition never changes once the inner `for` matches nothing.
- **GREEN:** after the fix, the test exits 0 and prints `PASSED` in well under a second. `SDGenerator_test` also still PASSES (exit 0).

## Verification

- `RingAnalyser_test` — PASSED (terminates).
