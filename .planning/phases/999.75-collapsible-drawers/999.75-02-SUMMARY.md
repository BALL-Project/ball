# Phase 999.75 Plan 02: PyBALL-ready Bottom Drawer (DRAWER-02) Summary

Generalized `BottomDrawer`'s tab set into a single `addDrawerTab_` registration path and added a Python/PyBALL tab slot that is entirely compile-time guarded by `#ifdef BALL_PYTHON_SUPPORT`. Logs + FileObserver remain the live tabs; the PyBALL slot is inert (zero Python compiled/linked) in the normal Python-OFF build.

## What Was Built

- **Generalized tab registration** (Task 1): a private `addDrawerTab_(label, content, outerToHide)` helper replaces the two duplicated LogView/FileObserver blocks in `buildBody()`. Behavior is byte-for-byte equivalent for the live tabs — the UFG-17 double-attach fix is preserved exactly: the inner `widget()` is reparented into the `QStackedWidget`, and the outer dock is hidden **only when the inner widget was actually added** (null content installs an `(unavailable)` placeholder and leaves the outer dock visible). Title bar, animation, `setExpanded`/`toggle`, and objectName are unchanged.
- **PyBALL tab slot** (Task 2): a guarded `#include <BALL/VIEW/WIDGETS/pyWidget.h>` (with `config.h` reached transitively via `bottomDrawer.h → BALL/COMMON/global.h`) and a third "Python" tab registered through `addDrawerTab_`, all inside `#ifdef BALL_PYTHON_SUPPORT`. `PyWidget` (a `DockWidget` like LogView/FileObserver) is constructed as a child of the drawer; its inner `widget()` is hosted and the outer dock hidden via the same helper. Every `PyWidget` / `pyWidget.h` token is inside the guard. `sources.cmake` untouched (`pyWidget.C` is already CMake-gated).
