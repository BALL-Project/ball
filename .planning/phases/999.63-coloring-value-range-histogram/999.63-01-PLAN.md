# `999.63` — Coloring · value-range histogram

**v1.7.x-17b** · Wave B · ~3–4 days

## Goal

Replace the basic `min` / `max` text inputs that shipped in
v1.7.x-17 with a histogram of the actual values across the active
selection, plus two draggable handles, plus four smart presets. The
first visible **Inspector depth** win on the v1.7.4 contract.

Visual target: `revitalization/mockups.html#v172-forward` board 05.

## Why now

The shipped basic version is functional but information-blind — the
user has to *know* what range to pick. The histogram makes the data's
shape legible and lets the user clamp to it in one drag. Small UI
investment; large user-experience leverage on value-based colorings
(B-factor / Occupancy / Distance from ligand).

The contract from `999.59` is the prerequisite: the widget binds
through `ColoringController::setRange(min, max)` which goes through
the new command-shaped `apply()`. No new mutation paths.

## Scope

**In:**

1. **`ValueRangeWidget`** — new widget (~300 LOC):
   - Renders a 27-bin histogram (or N-bin if injected).
   - Draws the colormap behind the bars; in-range bins paint with the colormap, out-of-range bins are de-emphasized.
   - Two draggable handles (`min` / `max`) emit `rangeChanged(min, max)` while dragging, `rangeCommitted(min, max)` on release.
   - Two text readouts below the handles.
   - Footer row with 4 preset buttons (Auto-fit / Full range / Robust 5–95% / Reset).
   - Lives in `source/VIEW/WIDGETS/`, not `inspector/sections/` (it's reusable).
2. **`ColoringController::distribution()`** — new method:
   - Returns `BinSummary { min, max, bin_edges, bin_counts }` for the current selection + coloring method.
   - Caches against `(selection_id, method)` — invalidates on selection-change or method-change notification.
   - The Controller computes once via `BALL::Statistics::Histogram`; widget reads it.
3. **`ColoringSection` integration** — replaces the v1.7.x-17 stacked-widget min/max page with the `ValueRangeWidget` for value-based methods.
4. **Presets** wire to controller methods:
   - Auto-fit → `distribution().min` / `.max`.
   - Full range → method-defined limits (e.g. B-factor: 0–100; Charge: -5–+5).
   - Robust 5–95% → percentile bin edges.
   - Reset → revert to method-defined defaults.

**Out:**
- Non-coloring uses of the widget (other Sections do not consume it in v1.7.4).
- Custom colormap editor — v1.7.5+.
- Persisted user-preferred ranges per method — v1.7.5.
- Time-series histograms (trajectories) — v2.0.

## Detailed steps

### 62.1 — `ValueRangeWidget` skeleton

- `QWidget` subclass. `paintEvent` draws the histogram (per
  `mockups.html` board 05 visual).
- Mouse events on the handles — pointer-precise drag.
- Emits `rangeChanged` (during drag) + `rangeCommitted` (on release).
- Accepts `setDistribution(BinSummary)` from the section.
- No business logic; no statistics.

### 62.2 — `ColoringController::distribution()`

- New read-model on the Controller. Computes the bin summary in
  `Controller`-land, caches it.
- Cache key: `(selection_hash, method, custom_field_if_any)`.
- Cache invalidates on `CompositeMessage::selectionChanged` or
  `applyEvent(coloring.setMethod)`.
- Returns a value type, not a pointer — widget can't accidentally
  mutate it.

### 62.3 — `ColoringSection` wiring

- Remove the current min/max stacked-widget page.
- Insert `ValueRangeWidget`.
- On `rangeCommitted(min, max)`:
  - `controller_->setRange(min, max);`
  - `controller_->apply();`
- On `rangeChanged(min, max)` (drag-time):
  - Call a Controller method `previewRange(min, max)` that updates a
    visual hint WITHOUT going through `apply()` — the contract is
    strict here: dragging does not commit a payload.
  - The hint path is a separate Controller method that paints a
    semi-transparent overlay on the scene; landing the overlay is a
    `999.63`-stretch (or v1.7.5).
- Preset buttons call `controller_->setRange(...).apply()` directly.

### 62.4 — Tests

- Unit test for `distribution()` against known values.
- Smoke test in `999.60`'s contract harness: widget → controller →
  scene roundtrip equals `setRange(min, max)` from menu/Python.

## Risks

- **`previewRange` hint path is fiddly.** If the live preview during drag turns out to need a render-side overlay, scope it down to "no preview during drag; commit-on-release only" — still a strict win over text inputs. Land the hint as a follow-up.
- **Histogram resolution.** Default 27 bins is `mockups.html` board 05. For very small selections (≤27 atoms) the bins look sparse; provide a `setBinCount(N)` escape hatch on the widget.
