<objective>
Relocate the `createColorProcessor` color-processor factory (and its `applySettingsTo` override-application helper) out of the legacy `ColoringSettingsDialog` into a free-standing `ColorProcessorFactory` in the MODELS layer that constructs the per-method processor (which already carries compiled-default colors) and then applies an explicit `ColoringOverrides` struct — no QWidget / QTableWidget dependency.

Purpose: The factory at `coloringSettingsDialog.C:669` (`createColorProcessor`) is the second of the two render-path factories pinning `displayProperties.C` to the legacy dialogs (the VIEW-CLEAN-02 lynchpin). KEY INSIGHT confirmed in the code: each color processor's constructor already loads its compiled default color map (that is exactly how `setDefaultValues_` at coloringSettingsDialog.C:64-121 populates the tables — by constructing a dummy processor). So `applySettingsTo` only layers the USER'S table/button customizations on top. The relocated factory therefore takes a `ColoringOverrides` whose EMPTY state means "use compiled defaults" — which is precisely the molecule-load default-rep render behavior (consistent with CONFIG-01's compiled-defaults-show-through principle). This plan ONLY relocates + delegates; it does NOT yet repoint the render path (Plan 03), so the build + render stay unchanged.

Output: A new `ColorProcessorFactory::create(ColoringMethod, const ColoringOverrides&)` reproducing `createColorProcessor` + `applySettingsTo`; `ColoringSettingsDialog::createColorProcessor` rewritten to pack its tables/buttons into a `ColoringOverrides` and delegate.
</objective>
