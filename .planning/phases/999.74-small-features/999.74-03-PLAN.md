<task type="checkpoint:human-verify" gate="blocking">
  <what-built>
    A status-bar progress bar shown during the continuous simulation loop, and an
    auto-stop that ends the loop when a quality criterion (RMS gradient / convergence
    for minimization; the criterion documented in 999.74-02-SUMMARY for MD) is met.
  </what-built>
  <how-to-verify>
    1. Build BALLView with the ci preset for your platform
       (ci-macos / ci-linux / ci-windows), -DBALL_LICENSE=GPL, and launch it
       (ensure BALL_DATA_PATH points at data/).
    2. Open a structure (e.g. File → Open a bundled PDB/HIN), and select it so the
       molecular-mechanics menu entries are enabled.
    3. Run MolecularMechanics → Energy Minimization. Confirm:
       a. A progress bar appears in the status bar while the run proceeds.
       b. The bar advances toward 100% as iterations accumulate (it should not sit at
          0 or jump straight to full).
       c. When the minimizer converges early (criterion met) the run stops on its own
          and the status text reports the criterion was met — you should NOT have to
          press Stop.
       d. After the run ends, the progress bar disappears / resets.
    4. Run MolecularMechanics → Molecular Dynamics (Ctrl+M) on the same structure with
       a large step count. Confirm the progress bar advances, then verify the auto-stop
       ends the run before the full step count when the MD quality criterion is reached.
    5. Start a run and press Stop mid-way — confirm the bar clears and no crash/leak
       (the app stays responsive and a second run can be started).
    6. Sanity: confirm the build had QT_NO_KEYWORDS defined (no Q_EMIT/keyword
       regressions) — it did if BALLView built under the ci preset.
  </how-to-verify>
  <resume-signal>
    Type "approved" if all of 3a–3d, 4, and 5 hold. Otherwise describe what failed
    (e.g. "bar never appears", "auto-stop never fires", "crash on Stop") so a
    gap-closure plan can be created.
  </resume-signal>
</task>

</tasks>
