<objective>
Add user-controllable axis/value limits to the PropertyPlotter command-line tool
(GitHub #524, FEATPLOT-01). Today the plot is always auto-ranged, so a property
with a few extreme outliers (e.g. `<score>` of -25 mixed with 3.8e+11) produces a
useless plot. Let the user clamp the plotted range via new `-p1_min`, `-p1_max`,
`-p2_min`, `-p2_max` flags, matching the wording of the original report.

Purpose: makes distribution/scatter plots usable on ill-distributed data without
pre-filtering the input SDF.
Output: an updated, backward-compatible PropertyPlotter tool.
</objective>

<task type="auto" tdd="true">
  <name>Task 1: Register limit flags and apply them to data + gnuplot range</name>
  <files>source/APPLICATIONS/TOOLS/PropertyPlotter.C</files>
  <behavior>
    - With no `-p*_min`/`-p*_max` flags: output data file and gnuplot script are
      identical to current behavior (no `set xrange`/`set yrange` lines emitted).
    - With `-p1_min X`: prop1 values below X are dropped before binning/scatter,
      and the gnuplot script emits `set xrange [X:*]`.
    - With `-p1_max Y`: prop1 values above Y are dropped; gnuplot `set xrange [*:Y]`
      (or `[X:Y]` when both given).
    - With `-p2_min`/`-p2_max` (scatter mode, p2 present): prop2 values outside the
      range are dropped and gnuplot emits a matching `set yrange`.
    - For the distribution (single-property) mode, `-p2_*` flags are ignored (no p2
      axis); only `-p1_*` clamps the histogram domain so the 100 buckets span the
      requested range rather than the data extremes.
  </behavior>
  <action>
    Per FEATPLOT-01 / #524, add four optional double parameters after the existing
    `p2` registration (line ~19): `p1_min`, `p1_max`, `p2_min`, `p2_max`, each with a
    description like "lower/upper limit for property 1/2 axis". Use
    registerOptionalDoubleParameter. After parse, read each with parpars.get() and
    compare against CommandlineParser::NOT_FOUND to detect whether the user supplied
    it (do NOT rely on the 0.0 default — 0.0 is a legal limit); convert supplied
    values with String::toDouble(). Store as `has_p1_min` + `p1_min_val` pairs etc.

    In the read loop (lines ~46-82), before inserting a pair into `properties`, skip
    the molecule when its prop1 is below p1_min or above p1_max (when those are set),
    and — in scatter mode only — when prop2 is outside [p2_min, p2_max]. Filtering
    here keeps both the distribution histogram and the scatter output consistent.

    For the distribution branch (lines ~84-108): when p1_min/p1_max are set, use the
    user limits as `min_p1`/`max_p1` instead of (or clamped to) the scanned data
    extremes so the 100 buckets span exactly the requested domain.

    In the gnuplot script section (lines ~138-171): when a p1 limit is set emit
    `set xrange [lo:hi]` using `*` for any unset side (gnuplot autorange token);
    likewise emit `set yrange` for p2 limits in scatter mode. Emit these lines after
    the existing `set xlabel`/`set ylabel` lines and before the `plot` line. Emit
    NOTHING when no limit is set so default output is unchanged.

    Keep 2-space indent, Allman braces, `using namespace BALL`. This tool does not use
    Qt keywords so QT_NO_KEYWORDS is not a concern here.
  </action>
