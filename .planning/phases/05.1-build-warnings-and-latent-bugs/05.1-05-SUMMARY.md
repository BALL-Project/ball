# Phase 05.1 Plan 05: -Wformat-overflow in CIFParserParser.y Summary

**Replaced all 20 sprintf calls in the CIF parser's Bison grammar with bounded snprintf using sizeof(\$\$) — eliminates 19 gcc -Wformat-overflow warnings and removes a memory-corruption risk on malformed CIF input.**

## Accomplishments

- All 20 `sprintf($$, ...)` calls in `source/FORMAT/CIFParserParser.y` converted to `snprintf($$, sizeof($$), ...)` — every grammar action that composes a value/tag/quoted-string is now bounded.
- The generated `CIFParserParser.C` compiles cleanly under gcc/clang with **zero `-Wformat-overflow`** on the CIF parser (verified by local rebuild after deleting the cached generated files to force a fresh Bison regeneration).
- BACKLOG Task **A5** closed — the security-adjacent buffer-overflow class on malformed CIF input is fixed (the `%s` directive can no longer write past the 2550-byte `char[CIFPARSER_LINE_LENGTH]` destination, terminating nul included).
- `libBALL.dylib` re-links green on macos-arm64 / Qt 6.11.0.

## Decisions Made

- **`sizeof($$)` over `CIFPARSER_LINE_LENGTH`:** Bison's `$$` macro expands to a `yyval.text`-style reference to a `char[CIFPARSER_LINE_LENGTH]` field of the `%union`. `sizeof($$)` therefore resolves to 2550 at compile time. Using `sizeof` instead of the bare macro is refactor-safe — if the union bound ever changes (e.g., bumped to handle longer CIF tokens), the snprintf calls update automatically.
- **No edits to the generated `.C`:** The plan and CMake setup both treat `CIFParserParser.C` as a build artifact. The Bison toolchain regenerates it from the `.y` source on every build; editing the `.C` would be lost on the next rebuild.
- **Scope discipline:** The `.l` lexer file (`CIFParserLexer.l`) has 18 `strncpy` calls that are a separate `-Wstringop-truncation` issue (Task A6, plan 05.1-06). Left untouched.

## Deviations from Plan

**None substantive.** One minor count-correction:

- The plan and BACKLOG documented "19 instances" (the gcc warning count); the actual `sprintf(` call count in `CIFParserParser.y` is **20**. All 20 were swapped — this just means gcc was emitting one warning per *line* of the generated `.C`, and at least one source line emits two warnings to gcc or one source action contributed two `__builtin___sprintf_chk` invocations. Either way, the swap is exhaustive: post-fix `grep -cE "(^|[^a-zA-Z_])sprintf\(" source/FORMAT/CIFParserParser.y` returns `0`, and `grep -cE "snprintf\(" source/FORMAT/CIFParserParser.y` returns `20`. Not a rule-driven deviation — the plan's "swap every sprintf" instruction was followed verbatim; only the BACKLOG's expected count was off by one.
