# Phase 05.1 Learnings: build-warnings-and-latent-bugs

## Decisions

### `BALL::PointerSizeUInt` over `std::uintptr_t` for pointer-identity storage
For the C4311 LLP64 pointer-truncation fix, the canonical cast target across all 9 modified sites is `BALL::PointerSizeUInt` (typedef at [`include/BALL/COMMON/global.h:207`](include/BALL/COMMON/global.h#L207)) rather than the C++11 `std::uintptr_t`.

**Rationale:** Width-equivalent on all BALL-supported platforms; codebase idiom is overwhelmingly `PointerSizeUInt` (~30+ existing sites: `hash.h:49`, `persistenceManager.h` ×6, `timer.h/C`, `molecularSurfaceGrid.C`); zero `std::uintptr_t` sites. No new `<cstdint>` include needed — `PointerSizeUInt` reaches via `<BALL/common.h>`.
**Source:** [05.1-02-SUMMARY.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-02-SUMMARY.md)

### Option A (drop tautological halves) over Option B (add `DRAWING_MODE_INVALID = -1`) for A4
Plan 14 listed two paths; Option A is the surgical 3-half-removal in `representation.C`; Option B adds an enum sentinel matching `DrawingPrecision`'s `DRAWING_PRECISION_INVALID`.

**Rationale:** Option A is the smaller blast radius — Option B mutates `include/BALL/VIEW/KERNEL/common.h` enum, forcing a public-API recompile cascade for every TU that includes the header. The warning is fixable without that cost.
**Source:** [05.1-04-SUMMARY.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-04-SUMMARY.md)

### Un-deprecate `GeneticIndividual` (Remediation A) over `#pragma warning(suppress: 4996)` (C) for B4
Three remediations were available for the 5 C4996 instances surfaced by MSVC STL templates invoking `GeneticIndividual`'s deprecated methods.

**Rationale:** Remediation A (remove the class-level `BALL_DEPRECATED` marker) is a 1-token edit that fixes all five sites at the root cause. Remediation C (pragma) was rejected because the suppression wouldn't reach downstream consumers of `libBALL.dll` that include `geneticAlgorithm.h` — the warning would propagate through the STL template chain on their builds. Remediation B (refactor BALL to hold `unique_ptr<GeneticIndividual>`) was rejected as disproportionate (~10 source files, public API change) for a cosmetic Tier-B fix.
**Source:** [05.1-09-SUMMARY.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-09-SUMMARY.md)

### `memcpy` + explicit nul-termination (Remediation B) over `std::string` (A) and `#pragma suppress` (C) for A6
All 10 flagged `-Wstringop-truncation` sites use Remediation B.

**Rationale:** Each destination is a fixed-width PDB record field or Bison `%union char[N]` consumed by C-string APIs (`printf`, `String()` ctors). Remediation A would force boundary churn across many call sites. Remediation C was rejected because the warnings flag a real nul-termination concern, not a false positive.
**Source:** [05.1-06-SUMMARY.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-06-SUMMARY.md)

### Combined options (a) + (b) for D1 (Qt6LinguistTools)
The plan presented (a) `vcpkg.json` port-add and (b) CMakeLists `QUIET` + STATUS as alternatives. The executor landed both.

**Rationale:** Discovery surfaced that option (a) was already complete on this branch (`qttools` already in `vcpkg.json:8`, landed as the D6 root-cause fix). Doing only option (a) would have left the bare `find_package(...)` call emitting the built-in CMake warning on any non-vcpkg build path where LinguistTools is absent (local dev, future Qt install variants). Defence-in-depth.
**Source:** [05.1-10-SUMMARY.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-10-SUMMARY.md)

### `narrow-cached-path` for D3 (apt-cache tar failure)
None of the four plan-listed options (`split-cache-key` / `pre-save-cleanup` / `permissions-fix` / `no-fix-transient`) matched the real root cause. Executor invented a fifth.

**Rationale:** 7/7 recurrence rate on runs that reached the cache phase is chronic, not transient — `no-fix` rejected. The real cause is "cached path contains root-owned runtime-state files" (apt's `lock` and `partial/`). Narrowing `path:` to `/var/cache/apt/archives/*.deb` excludes the offending files at source; the only content `apt-get install` downloads is `.deb` archives anyway.
**Source:** [05.1-12-SUMMARY.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-12-SUMMARY.md)

### `${CMAKE_PROJECT_VERSION}` over `${PROJECT_VERSION}` for Info.plist (UAT-found gap fix)
Plan 14 used `${PROJECT_VERSION}` in 4 substitutions inside `source/APPLICATIONS/BALLVIEW/CMakeLists.txt`. UAT discovered the resulting Info.plist had empty version fields.

**Rationale:** [`source/APPLICATIONS/BALLVIEW/CMakeLists.txt:1`](source/APPLICATIONS/BALLVIEW/CMakeLists.txt#L1) calls `PROJECT(BALLView)` without `VERSION`. Under `CMP0048 NEW` (active at the root), this resets `PROJECT_VERSION` to empty for BALLView's scope. `${CMAKE_PROJECT_VERSION}` always refers to the top-level project's version (`1.6.0`), bypassing the shadow.
**Source:** [05.1-UAT.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-UAT.md) Gap 1; commit [`61aff67`](https://github.com/BALL-Project/ball/commit/61aff67)

### B3 default (full project-wide pragma) applied without measurement
CONTEXT.md D-06 specified a decision tree based on the post-B1+B2 C4251 count from CI. CI was repeatedly cancelled by concurrent pushes; no measured count was available at plan-execute time.

**Rationale:** Plan 08 explicitly allowed default-application when measurement could not complete ("If Build never started, apply the default — the pragma is safe-by-default and the measurement can be retroactively validated when CI stabilizes"). The pragma is a 3-line addition gated by `BALL_COMPILER_MSVC`; the downside of being wrong is zero (cosmetic on all three OSes); the upside of being right is silencing 3495 warnings.
**Source:** [05.1-08-SUMMARY.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-08-SUMMARY.md)

### CFBundleIdentifier = `de.uni-tuebingen.ball.ballview` (institutional reverse-DNS)
Three candidates were available: `de.uni-tuebingen.ball.ballview` / `org.ball-project.ballview` / `de.ball-project.ballview`.

**Rationale:** Institutional reverse-DNS is the strongest provenance for Phase 8 notarization — it will match a Developer ID Application certificate registered to the institution. The other two options would force a certificate-vs-bundle-ID mismatch resolution at Phase 8 time.
**Source:** [05.1-CONTEXT.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-CONTEXT.md) D-10, [05.1-14-SUMMARY.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-14-SUMMARY.md)

## Lessons

### BACKLOG.md fix-proposals can misidentify the failing component
Three plans found their BACKLOG description was wrong about *what* was broken, not just *how* to fix it:
- **D3** named ccache; the failing step was actually apt-archives cache.
- **D4** claimed both `ci.yml` and `release.yml` had the latent gap; `git blame` showed `ci.yml` had `--config Release` from its initial wiring commit (`e63f061`).
- **A4** said the `< 0` halves were tautological; clang was actually warning on the `> MAXIMAL_*` upper bounds.

**Context:** BACKLOG.md was authored from a single CI log read; subsequent intervening commits and closer inspection during execution surfaced corrections. Executors should treat BACKLOG fix proposals as a hypothesis to verify, not a directive to apply blindly.
**Source:** [05.1-12-SUMMARY.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-12-SUMMARY.md), [05.1-13-SUMMARY.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-13-SUMMARY.md), [05.1-04-SUMMARY.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-04-SUMMARY.md)

### Codex CLI cross-checks catch incomplete fixes that look complete
The Codex flag on A2 ("incomplete-as-spec'd — widening cast site alone leaves storage truncation downstream") drove CONTEXT.md D-08, which elevated end-to-end audit to a hard requirement. Without that cross-check, Plan 02 would have shipped a fix that left `HashMap<long, …>` storage on Windows still truncating.

**Context:** The audit ultimately turned out narrower than Codex feared (function-local rather than header-declared), but the discipline of *running* the audit caught the case where it would have mattered.
**Source:** [05.1-02-SUMMARY.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-02-SUMMARY.md), [05.1-CONTEXT.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-CONTEXT.md) D-08

### Nested `PROJECT()` calls without `VERSION` silently shadow `${PROJECT_VERSION}`
[`source/APPLICATIONS/BALLVIEW/CMakeLists.txt:1`](source/APPLICATIONS/BALLVIEW/CMakeLists.txt#L1) calls `PROJECT(BALLView)`. Under `CMP0048 NEW`, this resets `PROJECT_VERSION` to empty for that scope. CMake's `MACOSX_BUNDLE_*` properties are evaluated at target-property-set time, not at top-level-PROJECT time, so the bundle shipped with empty version strings without a single warning.

**Context:** The phase's local-macOS build succeeded; the gap only surfaced when UAT inspected the produced `Info.plist`. Subtle scoping bugs in build systems can pass every quality gate that doesn't *read the artifact*.
**Source:** [05.1-UAT.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-UAT.md) Gap 1

### vcpkg `builtin-baseline` must match the runner's pre-installed vcpkg checkout
Commit `cd912fc` (Phase 5 work) re-introduced a `builtin-baseline` pin that commit `8bd5294` had previously removed for this exact reason. The pinned commit doesn't exist in the GitHub runner's vcpkg checkout → manifest install fails for every port.

**Context:** This is a *non-obvious* recurrence — the failure manifests not as a vcpkg.json schema error but as a fatal `git show versions/baseline.json failed` deep inside the vcpkg toolchain run. Without `git log -p vcpkg.json` history reading, it looks like a vcpkg infrastructure problem rather than a self-inflicted pin mismatch. Lesson is the same fix repeated: when consuming the runner-provided vcpkg toolchain, **omit** `builtin-baseline`.
**Source:** Commit [`08ec9c5`](https://github.com/BALL-Project/ball/commit/08ec9c5) (re-applies [`8bd5294`](https://github.com/BALL-Project/ball/commit/8bd5294))

### `ci.yml` concurrency-groups cancel in-flight runs on every push
The phase's 14 push-per-plan cadence caused each CI run to be cancelled by the next push within ~5 minutes. Tri-OS verification became impossible until pushes paused. The concurrency-group is correct for normal development (one PR run per HEAD) but adversarial for janitorial sweep phases that depend on per-commit CI feedback.

**Context:** Phase 5.1 worked around this by relying on local macOS build verification per plan plus a final stand-alone CI run at phase end. Future phases that need per-commit CI verification should batch commits or pause between pushes.
**Source:** Multiple cancelled runs in [`gh run list`](https://github.com/BALL-Project/ball/actions); [05.1-08-SUMMARY.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-08-SUMMARY.md) ("CI run 25931203110 was cancelled mid-Windows-build … by the unrelated Linux aqtinstall Qt 6.5.3 failure cascading concurrency-cancel")

### `aqtinstall` v3.3.0 rejects `qtbase qtopengl` as modules on Qt 6.5+
Out-of-scope discovery in Phase 5.1, but worth recording: jurplel/install-qt-action's `modules:` field accepts only *additional* modules in Qt 6.5+. `qtbase` ships by default; `qtopengl` was a Qt 5 module name and is part of `qtbase` in Qt 6 (as `Qt6::OpenGLWidgets`). Listing them as modules makes aqt error: `The packages [...] were not found while parsing XML of package information!`.

**Context:** Surfaced by Linux CI on every Phase 5.1 run; Phase 5 / commit `a26cafa` introduced the misconfiguration. Fix is a one-line change: `modules: 'qtbase qttools qtopengl'` → `modules: 'qttools'`.
**Source:** [`gh run view 25925481471 --log-failed`](https://github.com/BALL-Project/ball/actions/runs/25925481471)

### A phase with no user-facing features needs a CI-grep UAT, not a conversational one
Phase 5.1 had no UI changes and no user workflows changed — UAT.md is structured as a 12-test smoke matrix (cold-start build, bundle identity, warning-census CI greps, runtime smoke) rather than a click-through walkthrough.

**Context:** The default UAT shape (presented-expected, user-confirms) doesn't fit code-quality phases. Future warning-cleanup or refactor phases should explicitly framed the UAT this way at extraction time, not after starting tests.
**Source:** [05.1-UAT.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-UAT.md) header note

## Patterns

### `find_package(... QUIET)` + `IF(NOT FOUND) MESSAGE(STATUS ...)` for optional deps
Canonical CMake pattern for optional dependencies whose absence is non-fatal: pass `QUIET` to suppress the built-in not-found warning, then explicitly print `STATUS` (not `WARNING`) describing what's disabled.

**When to use:** Any optional dependency where build proceeds without it. Qt LinguistTools (translations), SpaceNavigator (input plugin), VRPN (haptic plugin), Python (Jupyter plugin) all fit this shape in BALL.
**Source:** [05.1-10-SUMMARY.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-10-SUMMARY.md), [CMakeLists.txt:351](CMakeLists.txt#L351)

### `memcpy(dst, src, N); dst[N-1] = '\0';` for safe fixed-width string copy
The drop-in replacement for `strncpy(dst, src, N)` when the destination is a fixed-width record field and you need both truncation AND guaranteed nul-termination. Avoids `-Wstringop-truncation` warning class entirely; the explicit nul-write documents the intent.

**When to use:** Any fixed-width buffer that needs both bounded write and guaranteed termination. PDB record fields, fortran-format columns, Bison `%union char[N]`.
**Source:** [05.1-06-SUMMARY.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-06-SUMMARY.md), [source/FORMAT/PDBFileDetails.C](source/FORMAT/PDBFileDetails.C)

### Helper-routed refactor for repeated bug-class patterns
When a bug-class pattern appears N times in one file (10 `strncpy` sites in CIFParserLexer.l), introduce a `static inline` helper in the file's prelude and route all sites through it. Avoids 10× the repetition; ensures any future fix lands at one site.

**When to use:** Any time you find yourself making the same surgical change >3 times in one file.
**Source:** [05.1-06-SUMMARY.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-06-SUMMARY.md) (`CIF_copy_text(dst, src)` helper)

### `extern template class T;` (header) + `template class BALL_EXPORT T;` (.C) for MSVC DLL exports
The C4910 fix pattern: declaration site (`.h`) gets the `extern template class` *without* `BALL_EXPORT`; definition site (`.C`) gets the bare `template class` *with* `BALL_EXPORT`. Honest export under MSVC; valid C++ under gcc/clang.

**When to use:** Every explicit template instantiation that needs to be DLL-exported. `std::vector<T>`, `TVector3<float>`, similar instantiations.
**Source:** [05.1-07-SUMMARY.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-07-SUMMARY.md), [05.1-BACKLOG.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-BACKLOG.md) §B1+B2

### BACKLOG.md as research-equivalent for follow-up phases
Phase 5.1 was scoped end-to-end via [`05.1-BACKLOG.md`](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-BACKLOG.md) — Codex-cross-checked per-task fix proposals — and the `/gsd-plan-phase` skipped its researcher dispatch because the BACKLOG already served as RESEARCH.md.

**When to use:** Any janitorial / follow-up phase where the work is enumerated from an upstream artifact (CI log, PR review, audit). Skips the researcher dispatch cost while preserving research-quality scope.
**Source:** [05.1-CONTEXT.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-CONTEXT.md), missing `05.1-RESEARCH.md` (intentional)

### CI as the verification oracle for warning-cleanup phases
Per CONTEXT.md D-07, phase success = next CI run emits zero of the targeted warning categories on the matched files. SUMMARY.md per-plan source-text assertions confirm the *fix shape*; CI-log greps confirm the *fix effect*.

**When to use:** Any phase whose deliverable is a warning census drop or other CI-observable property. Trade-off: requires CI stability (see lesson on concurrency-cancel).
**Source:** [05.1-CONTEXT.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-CONTEXT.md) D-07

## Surprises

### BACKLOG D3 named the wrong cache step
Plan 12's executor found that 7/7 recent CI runs failed on the **apt-archives** cache step, not the ccache step BACKLOG D3 claimed. ccache had been saving cleanly all along. Re-diagnosis from CI logs was needed.

**Impact:** Saved a counterproductive ccache fix; surfaced a real apt-cache fix that BACKLOG never identified.
**Source:** [05.1-12-SUMMARY.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-12-SUMMARY.md)

### BACKLOG D4 attributed a gap to `ci.yml` that never existed
Plan 13 closed as no-op verification: `git blame` showed `ci.yml` had `--config Release` from its initial real-wiring commit (`e63f061`). Only `release.yml` ever had the gap (fixed earlier in `381c129`). The "latent in ci.yml" claim was bookkeeping drift.

**Impact:** Saved a redundant edit; documented the attribution correction in 05.1-13-SUMMARY for future-archeology.
**Source:** [05.1-13-SUMMARY.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-13-SUMMARY.md)

### Plan 04's tautological halves were on the upper bound, not `< 0`
BACKLOG A4 (with Codex annotation) said the `drawing_mode_ < 0` half was tautological. The actual clang warnings were on the `> BALL_VIEW_MAXIMAL_*` upper bounds (because `MAXIMAL_*` macros = 4 and the enum's largest value = 3). Plan 04's verbatim fix would have left both warnings in place.

**Impact:** Executor extended scope from a 1-token deletion to a 3-half deletion to actually satisfy `must_haves.truths`. The Codex annotation about `DrawingPrecision`'s `-1` sentinel was still correct, just on a different code path.
**Source:** [05.1-04-SUMMARY.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-04-SUMMARY.md)

### Codex D-08 storage audit was narrower than feared
CONTEXT.md D-08 elevated end-to-end storage migration to a hard requirement, fearing `HashMap<long, Position>` declarations in MMFF94StretchBend's *header*. The audit found the HashMap is function-local in the `.C` file, not header-declared; `triangulatedSurface.C`'s casts are comparator-local with no downstream `long` storage; headers in `files_modified` were audited and confirmed correctly typed.

**Impact:** Total source LOC changed was ~30, well within the 30-line ceiling — no checkpoint required. The discipline of *running* the audit was load-bearing; the fix being narrower was a side effect.
**Source:** [05.1-02-SUMMARY.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-02-SUMMARY.md)

### Plan 14 shipped empty Info.plist version fields despite passing local build
The local macOS build succeeded; CFBundleIdentifier was correctly populated. But `${PROJECT_VERSION}` expanded to empty inside BALLView's scope because of the nested-`PROJECT()` shadowing (lesson above). Surfaced only by UAT inspecting the actual artifact with `plutil -p`.

**Impact:** Phase 8 notarization would have rejected the bundle (notarytool requires `CFBundleVersion` AND `CFBundleShortVersionString`, not just identifier). Caught in UAT in-cycle; fixed in commit `61aff67`. **Reminder that artifact-inspection is a distinct quality gate from build-success.**
**Source:** [05.1-UAT.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-UAT.md) Gap 1

### vcpkg baseline regression silently reintroduced by Phase 5 work
Commit `cd912fc` (chore(05-01): point macOS preset at Homebrew qt 6 and switch vcpkg manifest to qtbase) re-added the unresolvable `builtin-baseline` pin that `8bd5294` had previously removed. Both commits were the same author; the second commit didn't reference or know about the first.

**Impact:** Every Windows CI run failed at vcpkg Configure for ~24 hours until the regression was caught during Phase 5.1 CI work. Re-applied the original fix as commit `08ec9c5`.
**Source:** `git log -p vcpkg.json`; commits [`cd912fc`](https://github.com/BALL-Project/ball/commit/cd912fc), [`8bd5294`](https://github.com/BALL-Project/ball/commit/8bd5294), [`08ec9c5`](https://github.com/BALL-Project/ball/commit/08ec9c5)

### Linux Qt 6 CI has never been green on `v1.6-modernization`
Surfaced during 5.1 CI watching: the last green CI run on the branch ([25899905204](https://github.com/BALL-Project/ball/actions/runs/25899905204), 2026-05-15) was *before* commit `a26cafa` migrated Linux to Qt 6 via jurplel/install-qt-action. Every Linux run since has failed on aqtinstall's `qtbase qttools qtopengl` module-list rejection.

**Impact:** Phase 5.1's tri-OS warning-census verification (Linux gcc `-Wformat-overflow`, `-Wstringop-truncation`) can't run until Phase 5 lands the aqtinstall fix. Doesn't block 5.1 code-completion but defers the audit.
**Source:** [05.1-08-SUMMARY.md](.planning/phases/05.1-build-warnings-and-latent-bugs/05.1-08-SUMMARY.md); `gh run list --status success`
