<objective>
Fix BACKLOG.md Task **A5** — `-Wformat-overflow` in the CIF parser (19 instances).

Around `source/FORMAT/CIFParserParser.y:230,233,236,239` (the generated `.C` is what
gcc actually compiles), the error-reporting path calls `sprintf` into buffers that
gcc has proven (via `__builtin___sprintf_chk`) can overflow: `%s` writes up to 2549
bytes into a 1-2550-byte buffer; the terminating nul can land past buffer end.

Replace every `sprintf` in this file with `snprintf` passing the actual destination
buffer size. The Bison skeleton may be a contributing factor — verify against the Bison
version. Not Codex cross-checked; fix proposal is the canonical hardened-printf swap.

Severity: security-adjacent — memory corruption on malformed CIF input is possible if
the parser path is reachable from untrusted data. BALL is desktop software so the attack
surface is narrow, but the corruption is real on a hostile or corrupted `.cif` file.

Purpose: BACKLOG.md task A5.
Output: 19 `sprintf` -> `snprintf` swaps across `source/FORMAT/CIFParserParser.y`.
</objective>

    file, rewrite as `snprintf(buf, sizeof(buf), fmt, ...)`. The destination buffer is
    nearly always a stack array (`char buf[N];`) — `sizeof(buf)` resolves to `N` at
    compile time. If the destination is a `char*` pointer (rare; if encountered, the
    function's `char*` parameter must be paired with an explicit size_t parameter — read
    surrounding context to decide), pass the explicit size constant.

    Where the BACKLOG flags lines 230, 233, 236, 239 specifically, those are the highest-
    risk sites (the `%s` instances writing up to 2549 bytes into a 1-2550-byte buffer).

    `CIFParserParser.y` is in this plan).

    Do NOT silence the warning with `#pragma GCC diagnostic ignored`. The point of A5 is
    to actually bound the writes.

    After editing, the Bison toolchain regenerates `CIFParserParser.C` at build time; no
    explicit `bison` invocation needed in the source tree.
