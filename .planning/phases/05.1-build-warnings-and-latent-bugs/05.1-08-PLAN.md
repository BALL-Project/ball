<objective>
Fix BACKLOG.md Task **B3** — C4251 STL members of DLL-exported classes (3495 instances).

C4251 is the endemic Windows DLL warning: exported classes have `std::vector<T>` /
`std::string` / etc. members, and MSVC warns clients linking against the DLL might see a
different STL ABI. Cosmetic when the entire surface uses one MSVC toolchain (Phase 4's
vcpkg pin guarantees this); genuinely dangerous only when mixing CRTs.

BALL already partially silences this in `include/BALL/COMMON/exception.h:18` but only
inside a narrow push/pop window for `std::string`. The fix per BACKLOG is to broaden to a
project-wide `#pragma warning(disable: 4251)` in `global.h` under `BALL_COMPILER_MSVC`,
with a comment.

**Sequencing (CONTEXT.md D-06):** This plan is wave 2, gated on plan 05.1-07 (B1+B2)
landing. After 05.1-07 lands, the post-fix C4251 count must be re-measured from CI — if
it drops materially from 3495 (e.g. because the now-honest `extern template` exports
quieted a non-trivial subset), B3's project-wide pragma may be reducible in scope or
skipped entirely. The decision tree:

- **C4251 stays at ~3495 (~unchanged):** apply the project-wide pragma as planned.
- **C4251 drops materially but stays in the hundreds:** apply the project-wide pragma —
  the residual count is still noise.
- **C4251 drops to zero or a small handful:** consider narrowing the pragma to only the
  files that still emit it, OR skipping B3 entirely. Record the decision in SUMMARY.

Plan is non-autonomous because the measurement-driven scope decision needs a maintainer
sign-off.

Not Codex cross-checked.

Purpose: BACKLOG.md task B3.
Output: ~3-line addition to `include/BALL/COMMON/global.h` under `BALL_COMPILER_MSVC`
(or, if measurement shows the pragma is no longer needed, an explanatory note in the
SUMMARY and no source edit).
