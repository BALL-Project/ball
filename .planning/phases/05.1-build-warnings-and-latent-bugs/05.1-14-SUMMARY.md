# Phase 05.1 Plan 14: BALLView.app Bundle Identity (BACKLOG D5) Summary

Set the `MACOSX_BUNDLE_*` target properties on the `BALLView` CMake target so the generated `BALLView.app/Contents/Info.plist` carries non-empty bundle-identity fields — fixing the v1.6.0-release defect where `CFBundleIdentifier` and six other identity fields were empty strings. `CFBundleIdentifier` is now `de.uni-tuebingen.ball.ballview` (per CONTEXT.md D-10 default — institutional reverse-DNS). Phase 8 notarization prerequisite cleared.

## Outcome

- `SET_TARGET_PROPERTIES(BALLView ...)` block added in `source/APPLICATIONS/BALLVIEW/CMakeLists.txt` under `IF(APPLE)` after `TARGET_LINK_LIBRARIES`.
- All seven empty bundle-identity fields are now populated: `CFBundleIdentifier`, `CFBundleName`, `CFBundleVersion`, `CFBundleShortVersionString`, `CFBundleLongVersionString`, `CFBundleGetInfoString`, `NSHumanReadableCopyright`.
- One commit: `3c028a8 fix(05.1-14): D5 BALLView.app bundle identity — populate Info.plist fields`.
- Local CMake configure verified clean: `cmake -S . -B build/d5-test -DBALL_HAS_VIEW=ON -DBALL_PYTHON_SUPPORT=OFF` reported "Configuring done … Generating done … Build files have been written".

## What Was Done

### Forensic root cause

The pre-existing `cmake/MacOSXBundleInfo.plist.in` (45 lines) uses the standard CMake `${MACOSX_BUNDLE_*}` substitution placeholders for every bundle-identity field. The template is correct.

The pre-existing `source/APPLICATIONS/BALLVIEW/CMakeLists.txt` at line 26-30 set **only** `MACOSX_BUNDLE_ICON_FILE` as a directory-scope variable, and added the `MACOSX_BUNDLE` flag to the executable property list. All other `MACOSX_BUNDLE_*` variables were unset — so CMake substituted them as empty strings into the Info.plist. That's why the v1.6.0 release artifact's `plutil -p` reported empty `CFBundleIdentifier`, `CFBundleName`, etc.

### Fix

Inserted a `SET_TARGET_PROPERTIES(BALLView PROPERTIES MACOSX_BUNDLE_* ...)` block immediately after `TARGET_LINK_LIBRARIES(BALLView ...)`, wrapped in `IF(APPLE) … ENDIF()`:

```cmake
IF(APPLE)
    SET_TARGET_PROPERTIES(BALLView PROPERTIES
        MACOSX_BUNDLE                      TRUE
        MACOSX_BUNDLE_GUI_IDENTIFIER       "de.uni-tuebingen.ball.ballview"
        MACOSX_BUNDLE_BUNDLE_NAME          "BALLView"
        MACOSX_BUNDLE_BUNDLE_VERSION       "${PROJECT_VERSION}"
        MACOSX_BUNDLE_SHORT_VERSION_STRING "${PROJECT_VERSION}"
        MACOSX_BUNDLE_LONG_VERSION_STRING  "BALLView ${PROJECT_VERSION}"
        MACOSX_BUNDLE_COPYRIGHT            "© BALL maintainers. LGPL-2.1."
        MACOSX_BUNDLE_INFO_STRING          "BALLView ${PROJECT_VERSION} — molecular visualization (LGPL-2.1)"
        MACOSX_BUNDLE_ICON_FILE            "BALLView.icns"
    )
ENDIF()
```

Each variable maps 1:1 onto the corresponding `${...}` placeholder in `cmake/MacOSXBundleInfo.plist.in`. `${PROJECT_VERSION}` is `1.6.0` (set at top-level `PROJECT("BALL" VERSION 1.6.0)` in `CMakeLists.txt:23`).

### Why the chosen CFBundleIdentifier

`de.uni-tuebingen.ball.ballview` — chosen from the three candidates in CONTEXT.md D-10:

| Candidate | Verdict |
|-----------|---------|
| `de.uni-tuebingen.ball.ballview` (institutional reverse-DNS) | **Chosen.** Strongest provenance for a Developer ID certificate registered to Universität Tübingen in Phase 8; BACKLOG D5 names this as the recommended default; reflects BALL's institutional origin. |
| `org.ball-project.ballview` (GitHub org) | Rejected. Would require ball-project.org domain ownership verification; weaker institutional tie. |
| `de.ball-project.ballview` (variant) | Rejected. Neither institutionally-true nor hosting-true; weakest of the three. |

The string contains only lowercase ASCII letters, digits, dots, and dashes — Apple's CFBundleIdentifier character constraints satisfied.

**Important:** because macOS preferences, sandbox identity, code-signing identity persistence, and LaunchServices "Open With" entries all key off CFBundleIdentifier, this string is hard to change once distributed. The plan-time decision lock is intentional.

### Why Option A (target properties) over Option B (template hardcode)

The `cmake/MacOSXBundleInfo.plist.in` template was already wired with `${MACOSX_BUNDLE_*}` placeholders for all the empty fields. The defect was at the variable-binding layer, not the template. Setting the variables via `SET_TARGET_PROPERTIES` keeps the template purely declarative (one source of truth for the Plist structure) and the substitution layer maintainable (identifier string + version live in CMake, where they belong alongside `PROJECT_VERSION`).

Option B (hardcoding the identifier in `MacOSXBundleInfo.plist.in`) would have worked but would have split the identity-data definition across two files and made `CFBundleVersion` / `CFBundleShortVersionString` fall back to literal `@PROJECT_VERSION@` literals (or required matching template edits).

## Phase 8 Linkage

This plan is a **Phase 8 (packaging-and-distribution) prerequisite**. See `.planning/phases/08-packaging-and-distribution/08-SIGNING-RESEARCH.md` for the downstream notarization flow. Specifically:

- Apple `notarytool submit` REQUIRES a non-empty `CFBundleIdentifier` — Phase 8 cannot ship a notarized macOS bundle without this fix.
- Developer ID Application code-signing validates the bundle's `CFBundleIdentifier` against the certificate's authorized bundle IDs at submission time. The `de.uni-tuebingen.ball.ballview` choice should match the Developer ID Application certificate that the Phase 8 signing flow registers (or a wildcard cert covering `de.uni-tuebingen.*`).
- macOS preferences / sandbox / LaunchServices identity now stabilized — Phase 8 can rely on a deterministic bundle identifier for "Open With" associations and user-pref persistence.
