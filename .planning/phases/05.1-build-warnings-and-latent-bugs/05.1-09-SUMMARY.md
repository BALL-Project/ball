# Phase 05.1 Plan 09: B4 + B5 Tier-B cosmetic warnings Summary

## One-liner

Fixed MSVC C4834 (discarded `[[nodiscard]]` return in `regressionModel.C:258`)
by deleting the dead `descriptor_IDs_.begin();` call, and fixed MSVC C4996 (×5
deprecation noise from `BALL::GeneticIndividual`) by removing the incorrect
class-level `BALL_DEPRECATED` attribute — the class is still load-bearing
internally with no replacement.

## What was done

Two BACKLOG.md tasks (B4 + B5) landed together in commit `d30feca`.

### Task 1: B5 — discarded `[[nodiscard]]` return at `regressionModel.C:258`

The line read:

```cpp
if (!descriptor_IDs_.empty())  // write descriptors ...
{
    descriptor_IDs_.begin();   // ← discarded [[nodiscard]] return; C4834
    bool trained = (training_result_.rows() == descriptor_IDs_.size());

    std::multiset<unsigned int>::iterator d_it = descriptor_IDs_.begin();
    ...
}
```

The standalone `descriptor_IDs_.begin();` call is dead code:
- It returns an iterator that's immediately discarded.
- `.begin()` on `std::multiset` has no side effects (no caching, no
  invalidation, no allocation — it's a pure observer).
- The real iterator `d_it` is correctly obtained three lines below.

**Fix:** delete the line. This is cleaner than `(void) descriptor_IDs_.begin();`
because the latter would preserve dead code under a `(void)` cast.

### Task 2: B4 — `BALL::GeneticIndividual` C4996 (5 instances)

#### Audit

The deprecation marker was at the **class level**, not on individual methods:

```cpp
// include/BALL/DOCKING/GENETICDOCK/geneticIndividual.h:15 (before)
class BALL_EXPORT BALL_DEPRECATED GeneticIndividual
```

`BALL_DEPRECATED` expands to `__declspec(deprecated)` on MSVC and
`__attribute__((deprecated))` on GCC/Clang. When the entire class is
deprecated, the compiler emits a warning at every use of *any* of its
members — including the STL's internal use of ctor / dtor / `operator=`
when the class is held by value inside a container.

`GeneticIndividual` is held by value in:

| Site                                                                   | Holder                                                |
| ---------------------------------------------------------------------- | ----------------------------------------------------- |
| `include/BALL/DOCKING/GENETICDOCK/geneticAlgorithm.h:135`              | `std::vector<std::vector<GeneticIndividual>> pools_;` |
| `include/BALL/DOCKING/GENETICDOCK/geneticAlgorithm.h:139`              | `std::vector<std::pair<GeneticIndividual*, GeneticIndividual*>> selected_;` |
| `include/BALL/DOCKING/GENETICDOCK/geneticAlgorithm.h:185`              | `GeneticIndividual template_individual_;` (by-value member) |
| `source/DOCKING/GENETICDOCK/geneticAlgorithm.C:145, 149, 158, 238, 257, 312, 401` | `vector<GeneticIndividual>` locals and references |
| `source/DOCKING/GENETICDOCK/geneticAlgorithm.C:246`                    | `GeneticIndividual offspring;` (local by value)       |

Neither `GeneticAlgorithm` nor `EvolutionaryDocking` is deprecated, and
neither has a replacement that uses a non-deprecated individual type.
There is no `GeneticIndividual2` or `EvolutionaryIndividual` candidate in
the tree — the deprecation has no migration target.

#### Per-instance remediation table

All five MSVC C4996 instances stem from a single root cause: the class-level
`BALL_DEPRECATED`. Removing it resolves the entire census at one edit site.

| # | C4996 site (per phase-4 CI run 25899905204)                              | Root cause                                  | Remediation                                  |
| - | ------------------------------------------------------------------------ | ------------------------------------------- | -------------------------------------------- |
| 1 | MSVC `<utility>` instantiating `pair<GeneticIndividual*, GeneticIndividual*>` (cdtor) | class-level `BALL_DEPRECATED`               | A — un-deprecate (1-token edit)              |
| 2 | MSVC `<xmemory>` instantiating allocator traits for `vector<GeneticIndividual>` (cdtor/dtor) | class-level `BALL_DEPRECATED`               | A — un-deprecate (1-token edit)              |
| 3 | MSVC `<vector>` instantiating `vector<GeneticIndividual>::_Reallocate*` (operator=) | class-level `BALL_DEPRECATED`               | A — un-deprecate (1-token edit)              |
| 4 | MSVC `<vector>` instantiating `vector<vector<GeneticIndividual>>` (nested ctor chain) | class-level `BALL_DEPRECATED`               | A — un-deprecate (1-token edit)              |
| 5 | `geneticAlgorithm.C` direct construction `GeneticIndividual offspring;`  | class-level `BALL_DEPRECATED`               | A — un-deprecate (1-token edit)              |

#### Decision rationale: A vs B vs C

- **Remediation A (un-deprecate)** — chosen.
  Cost: 1-token deletion + a documentary comment block.
  Correctness: the deprecation was incorrect to begin with. The class is
  still on the live code path of `GeneticAlgorithm::run()` and
  `EvolutionaryDocking`; nothing is migrating off it.

- **Remediation B (refactor BALL to stop using deprecated methods)** —
  rejected.
  Would require switching to `vector<unique_ptr<GeneticIndividual>>` or a
  fully different individual type, touching ~10 source files in `DOCKING/
  GENETICDOCK/` and changing public API on `GeneticAlgorithm`. Wildly
  disproportionate to a cosmetic Tier-B fix, and would not fix the root
  cause (the class would still carry `BALL_DEPRECATED` for other callers).

- **Remediation C (`#pragma warning(suppress: 4996)`)** — rejected.
  Would need to be applied at every STL-instantiation site in BALL itself
  (`geneticAlgorithm.h` × 3 lines, `geneticAlgorithm.C` × 6 lines) AND
  would *not* suppress the warning in downstream consumers of `libBALL.dll`
  that include `geneticAlgorithm.h` — those clients would still see the
  C4996 propagate through the STL template chain. Strictly worse than A
  on both effort and reach.

#### Edit

```cpp
// include/BALL/DOCKING/GENETICDOCK/geneticIndividual.h:15 (after)
// NOTE: BALL_DEPRECATED was removed (Phase 05.1-09, BACKLOG Task B4).
// The class is still load-bearing internally — GeneticAlgorithm holds
// std::vector<std::vector<GeneticIndividual>> and a GeneticIndividual
// template_individual_ by value, and EvolutionaryDocking depends on the
// same. MSVC's STL templates instantiate the deprecated members from
// inside the containers, which emitted 5 spurious C4996 warnings. Since
// there is no replacement class and the methods are not actually going
// away, the deprecation was incorrect. Re-add BALL_DEPRECATED only when
// a replacement lands and internal callers migrate off.
class BALL_EXPORT GeneticIndividual
```

The documentary comment is load-bearing — it tells the next maintainer
*why* this class lacks the deprecation marker its siblings might carry,
so a future "let's clean up deprecations" pass doesn't re-add it.
