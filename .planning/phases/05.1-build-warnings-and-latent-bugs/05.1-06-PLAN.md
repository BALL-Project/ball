<objective>
Fix BACKLOG.md Task **A6** — `-Wstringop-truncation` audit of `strncpy` sites (10 instances
per CI run 25899905204).

gcc's `-Wstringop-truncation` flags `strncpy` calls where the specified bound equals the
destination size or the source length — both common cases where the resulting buffer is
not nul-terminated. BACKLOG does not enumerate the exact source sites (gcc traces to
`__builtin___strncpy_chk` in `string_fortified.h:95` but the call sites must be derived
from the CI log).

This is an audit, not a uniform mechanical swap. Each site must be inspected to decide
whether truncation is a bug (rewrite as `std::string` assignment / longer buffer) or
intentional (rewrite as `memcpy` + explicit nul-termination to silence the warning
deliberately).

Not Codex cross-checked. Severity: memory safety, case-by-case.

Plan is non-autonomous because the case-by-case audit involves human judgement on each
site; a maintainer should review the audit table in the SUMMARY before merge.

Purpose: BACKLOG.md task A6.
Output: per-site audit table in the SUMMARY plus a set of file edits across the affected
source files (exact files determined by the audit).
</objective>

    **Step 2 — per-site audit.** For each flagged site, decide which remediation applies:

      - **Remediation A — std::string assignment.** When the destination is owned by code
        that already accepts std::string, or when the buffer can be widened safely, rewrite
        the strncpy as `dest = std::string(src);` (or equivalent). Eliminates truncation
        entirely.

      - **Remediation B — memcpy + explicit nul-termination.** When truncation is
        intentional (fixed-width record, on-disk format, legacy API contract), rewrite as
        `memcpy(dest, src, N - 1); dest[N - 1] = '\0';` with a one-line comment recording
        the intentional truncation. Silences the warning deliberately.

      - **Remediation C — retained with audit note.** Rare. Only when both A and B are
        worse than the current behaviour AND the truncation is provably safe. In this case,
        add an explanatory comment AND a localised `#pragma GCC diagnostic ignored
        "-Wstringop-truncation"` around the line. Record the rationale in the SUMMARY.
