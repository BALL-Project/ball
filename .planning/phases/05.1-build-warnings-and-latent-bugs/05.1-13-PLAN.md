<objective>
Fix BACKLOG.md Task **D4** — Windows release workflow `LNK1104: tbb12_debug.lib` —
`--config Release` missing on multi-config generator.

`cmake --build --preset ci-windows --target BALL VIEW BALLView` runs against Visual
Studio's *multi-config* generator. Without `--config Release` the build defaults to
**Debug**, which makes MSBuild link against `tbb12_debug.lib`. The vcpkg
`x64-windows-release` overlay triplet (used per Phase 4) builds only Release variants
to save ~50% time + space on CI — so `tbb12_debug.lib` doesn't exist and the linker
fails with `LNK1104: cannot open file 'tbb12_debug.lib'`.

Why this didn't trip the regular `ci.yml` Windows job earlier: that job had been
running for weeks with a warm vcpkg binary cache populated *before* the release-only
triplet landed, so Debug TBB binaries were in the cache and linked silently. The
`release.yml` workflow ran with a cold cache (different cache key — it's a brand-new
workflow), forced a fresh vcpkg install, and the Debug-variant gap surfaced.

Apply the one-line fix to **both** `release.yml` (the immediate gap — blocking the
v1.6.0 Windows installer) AND `ci.yml` (latent — will fail the moment the warm cache
expires or the cache key changes).

Surfaced: release workflow run 25908337693 on tag `v1.6.0` (2026-05-15).

Per planning_context, D4-mac is already landed pre-phase — this plan covers only the
Windows-side fix.

Not Codex cross-checked.

Purpose: BACKLOG.md task D4 (Windows path).
Output: one-line addition (`--config Release`) per workflow file, twice.
</objective>
