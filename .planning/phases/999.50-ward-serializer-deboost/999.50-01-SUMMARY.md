# Phase 999.50 Plan 01: Ward Serializer De-boost Summary

**Eliminated boost::serialization from the PoseClustering Ward cluster-tree serializer, replacing four boost archive flavors + adj_list serialization + ClusterProperties::serialize with a hand-rolled "BALLWARD" magic+version format — the single-TU compile drops from tens of minutes to ~4 seconds.**

## Performance

- **Duration:** ~18 min
- **Completed:** 2026-05-21
- **Tasks:** 3 / 3
- **Files modified:** 4 (1 SUMMARY created)

## Accomplishments
- Rewrote `poseClusteringSerialization.C` as a boost-free, hand-rolled magic+version-headed reader/writer over the trivial Ward-tree payload (graph order, root bundle, per-vertex poses/size/merged_at, edge list). No `boost::archive`, `boost/serialization`, or adjacency-list serialization remains.
- Deleted the `ClusterProperties::serialize` template member from the header and the `.C` file. Public API and the `bool binary` flag are byte-identical.
- Old/wrong files now fail loudly via `Exception::InvalidFormat(__FILE__, __LINE__)` on a leading magic/version mismatch instead of silently mis-parsing.
- Regenerated `test/data/PoseClustering_wardtree.dat` in the new TEXT format (246 bytes, ASCII) by redirecting the existing test3:312 serialize call and then reverting — re-verified the fixture-read CHECK before commit.
- Documented the on-disk format break under a v1.7.2 "Breaking changes" heading in `RELEASE-NOTES-v1.7.md`.
- Both PoseClustering tests pass; both TOOLS callers compile/link unchanged; the graphviz sibling TU is untouched.
