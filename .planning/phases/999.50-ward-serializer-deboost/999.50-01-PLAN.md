<objective>
Eliminate `boost::serialization` from the Ward cluster-tree serializer — the single
heaviest Boost component to compile and the bulk of the (already-quarantined)
`poseClusteringSerialization.C` cost. Replace the four boost archive flavors
(binary/text × in/out) + `adj_list_serialize.hpp` + `ClusterProperties::serialize`
with a hand-rolled, magic+version-headed reader/writer for the trivial payload the
tree actually holds. Keep the public API and the `bool binary` flag identical; only
the on-disk format changes.

This is maintainer plan item ① (the lead item / the real Windows-build-time killer)
plus its required format-break follow-through (fixture regen + RELEASE-NOTES).

Purpose: Drop that TU's compile from tens of minutes to ~seconds, removing the
boost::serialization template-instantiation cost from the build entirely.
Output: A boost-free serializer, a regenerated new-format fixture, callers still
building, tests green, and the format break documented.
</objective>

    Rewrite source/DOCKING/COMMON/poseClusteringSerialization.C so it no longer includes or uses
    boost::archive (binary_oarchive/binary_iarchive/text_oarchive/text_iarchive),
    boost/graph/adj_list_serialize.hpp, or boost/serialization/set.hpp. Delete those includes.
    Also delete the `ClusterProperties::serialize` template member: remove its definition from this
    .C file AND its declaration (the `template <class Archive> void serialize(Archive&, const unsigned int);`
    member) from include/BALL/DOCKING/COMMON/poseClustering.h. Keep boost/graph/iteration_macros.hpp and
    boost/version.hpp only if still needed; the directed adjacency_list ClusterTree type itself stays
    (it is the in-memory representation, not the on-disk format).

    Implement a hand-rolled writer in `void serializeWardClusterTree(std::ostream& out, bool binary)`
    and reader in `void deserializeWardClusterTree(std::istream& in, bool binary)` over the EXISTING
    `cluster_tree_` member. Preserve both signatures exactly (defaults live in the header).

    Header: write a magic + format-version prefix (the literal magic string "BALLWARD" followed by a
    single version byte, e.g. 0x01). On read, verify the magic and version first; on mismatch throw a
    BALL::Exception subclass with __FILE__, __LINE__ and a message naming the expected magic/version
    (so old boost files fail loudly). Use the IDENTICAL header in both binary and text variants.

    Payload (exactly today's content, center excluded), in this order:
    (1) graph order = boost::num_vertices(cluster_tree_);
    (2) the root vertex index = cluster_tree_[boost::graph_bundle] (an unsigned int);
    (3) per vertex v in [0, order): the std::set<Index> poses (write count, then each Index), the Size size,
        the float merged_at;
    (4) the edge list: write the edge count, then for each edge (boost::source, boost::target) as a
        (parent_index, child_index) pair of vertex indices.

    Deserialize: read+verify header; read order; read root; rebuild the graph by calling boost::add_vertex
    `order` times into a freshly-cleared cluster_tree_ (clear/assign an empty ClusterTree first so a reused
    object does not accumulate stale vertices), filling each vertex's ClusterProperties (poses/size/merged_at);
    read the edge count and for each call boost::add_edge(parent, child, cluster_tree_); finally set
    cluster_tree_[boost::graph_bundle] = root. Because ClusterTree uses vecS for vertices, add_vertex returns
    descriptors 0..order-1 in order, so stored integer indices map directly to descriptors — no remapping.

    Binary variant: write/read the fixed-width fields with stream write/read of the raw object bytes
    (ostream::write / istream::read over the integer/float values and each set element). Text variant:
    write whitespace-separated decimal tokens via operator<< / operator>>, one logical record per the layout
    above, so the output is plain ASCII (the committed fixture is ASCII text — keep it that way). Both variants
    MUST share the same header bytes and the same field ordering so the only difference is the encoding of the
    scalars. Match CLAUDE.md conventions: modeline header already present, 2-space indent, Allman braces,
    `namespace BALL`, BALL::Exception with __FILE__,__LINE__. Do not add center/eigen serialization (leave the
    existing TODO intent — center stays unserialized). Update the file's top comment to state the TU now uses a
    hand-rolled format and no longer instantiates boost archives.

    Implements BUILD-ACCEL-06 item ① per .planning/v1.7.2-BUILD-ACCEL-PLAN.md.
  </action>
