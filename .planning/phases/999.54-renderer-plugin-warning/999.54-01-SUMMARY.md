# Phase 999.54 Plan 01: Renderer Plugin Warning Summary

**BALLView now emits a non-fatal, clearly-worded startup warning (Log.warn + important status-bar message) when renderer registration leaves `Scene::renderers_` empty, closing GitHub #501's silent-no-render failure.**

## Performance

- **Duration:** ~12 min
- **Started:** 2026-05-21T14:35Z (approx)
- **Completed:** 2026-05-21T14:47Z
- **Tasks:** 2
- **Files modified:** 2

## Accomplishments
- Added `bool no_renderers_warning_` to `scene.h` (initialized false in the ctor initializer list).
- Added a zero-renderer guard at the end of `Scene::registerRenderers_()`: on `renderers_.empty()` it sets the flag and emits one non-fatal `Log.warn` naming the cause (no renderer backend/plugin found → molecules won't display). No throw/return/exit/abort — control falls through and the ctor completes.
- Surfaced the condition on the VIEW status bar from `Scene::initializeWidget(MainControl&)`, gated on the flag, via `main_control.setStatusbarText(..., important=true)` using the guaranteed-valid `main_control` reference (not the null-during-construction `getMainControl()`).
- Verified `libVIEW` compiles and links cleanly with the change (`scene.C.o` rebuilt, `libVIEW.dylib` linked).

## Final Warning Strings Used
- **Log (registerRenderers_):** `[Scene] No renderers were registered — the 3D scene cannot be displayed. This usually means no renderer backend/plugin was found. BALLView will continue to run, but molecules will not be visible.`
- **Status bar (initializeWidget):** `No renderers available — the 3D scene cannot be displayed (no renderer backend was found). BALLView is running, but molecules will not be visible.`

The warning text and wiring are confirmed by static inspection + compile only.

## Decisions Made
- Split surfacing across construction phases (Log.warn in ctor path, status bar in `initializeWidget`) because `getMainControl()` is null while `registerRenderers_()` runs (it precedes `registerWidget(this)`). Calling the status-bar API there would dereference null.
- Used the `main_control` parameter directly in `initializeWidget()` rather than `Scene::setStatusbarText(...)` (which routes through `getMainControl()`), matching the surrounding call-site convention and guaranteeing validity.
- `important=true` so the warning is not instantly overwritten by routine status text.

Behavior is identical; the bool is deterministically initialized false.)
