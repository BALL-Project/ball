# Phase 999.43 Plan 01 — Shared widget set + About rewrite + 10-dialog QSS hookup + icon-browser dev tool

## Objective

Ship the shared-widget vocabulary that Phase 999.44 (Inspector) hard-depends on, replace the legacy `aboutDialog.ui` with hand-coded `aboutDialog.{h,C}` + `data/BALLView/about/authors.json`, wire `objectName` QSS hooks into 10 named dialogs, add a search field + verify inline recorder on `shortcutDialog`, and ship an `IconBrowser` dev tool gated behind `BALL_UI_V2 && BALL_DEBUG`.

Everything that affects user-visible behavior is gated behind `BALL_UI_V2` (default OFF in v1.7-RC stages; flipped ON in 999.48). The shared widgets compile in both branches (they are not behavior changes, just additional VIEW classes); the About rewrite compiles unconditionally (it replaces the .ui — there is no "old path" once .ui is gone); the IconBrowser is only registered/menu-shown when `BALL_UI_V2 && (debug build)`.

## Scope-trim breadcrumbs (recorded upfront)

- The Handover §03 ambition to rewrite every Preferences page as a hand-coded `QWidget` subclass using `SectionHeader` + `FormRow` is **forwarded to Phase 999.46** with breadcrumb. The 10 named dialogs in this phase get the cheaper-but-load-bearing treatment: (a) shared widgets are available and exemplified in the About dialog rewrite, (b) every dialog's top-level + main child widgets get stable `objectName` values so the QSS in `theme-neutral.qss` can target them, (c) `shortcutDialog` specifically gets the search-field UX upgrade per Handover §03. The deep page-rewrite is properly an Inspector-sibling effort and is sequenced with 999.46 (legacy-settings retirement) rather than blocking 999.44 dispatch.
- `setCamera` and `setClippingPlane` get `objectName` only; their conversion to Inspector panels is explicitly 999.44 scope per ROADMAP §999.43 line 2018-2019.
- IconBrowser ships **minimal** (grid of all icons from `theme.qrc` with name + 4 state tints); the fancier "missing-icon CI check" hook is deferred to 999.46.

## Tasks

### Task 1 — Add shared-widget skeleton + `SectionHeader` (with test)

type=auto

`include/BALL/VIEW/WIDGETS/sectionHeader.h` + `source/VIEW/WIDGETS/sectionHeader.C` — a `QWidget` containing a chevron toggle + 11px uppercase-tracked label + hairline `QFrame::HLine`. Public API: ctor `(QString title, QWidget* parent=nullptr)`, `setExpanded(bool)`, `bool isExpanded() const`, signal `expandedChanged(bool)`. Default state: expanded. The chevron is a `QToolButton` flat with `Icons::get("actions/chevron-down")` (we add this icon if missing). Register in `source/VIEW/WIDGETS/sources.cmake` as both source and moc target.

Add `source/VIEW/WIDGETS/sectionHeader_test.C` covering: ctor sets title, `setExpanded(false)` flips state + emits signal, `setExpanded(true)` after false flips back + emits.

Commit: `feat(999.43/01): add SectionHeader shared widget + unit test`

### Task 2 — `FormRow` shared widget + test

type=auto

`include/BALL/VIEW/WIDGETS/formRow.h` + `source/VIEW/WIDGETS/formRow.C` — row helper: ctor `(QString label, QWidget* control, QWidget* parent=nullptr)` builds a horizontal `[label | control]` layout with label-column min-width 140 px and right-aligned label. Optional `setHint(QString)` adds a small dim italic line below (default empty → no hint widget). Public: `QLabel* labelWidget()`, `QWidget* control()`, `setHint(QString)`, `clearHint()`.

Test: ctor places label + control, `setHint("x")` adds the hint label as a child, `clearHint()` removes it. Register in sources.cmake + moc.

Commit: `feat(999.43/02): add FormRow shared widget + unit test`

### Task 3 — `LabeledSlider` shared widget + test

type=auto

`include/BALL/VIEW/WIDGETS/labeledSlider.h` + `.C` — composes a `QSlider` (horizontal) + `QSpinBox` (synchronized) + optional units suffix label + reset button (`Icons::get("actions/reset")` — alias to lucide rotate-ccw). Public: ctor `(int min, int max, int defaultValue, QString units="", QWidget* parent=nullptr)`, `value() const`, `setValue(int)`, `signal valueChanged(int)`, `reset()` slot. Slider + spinbox are bi-directionally synced (Qt's standard pattern: connect both `valueChanged` signals through a guard to break the feedback loop).

Test: setting slider updates spinbox + emits once; setting spinbox updates slider + emits once; reset returns to default + emits.

Commit: `feat(999.43/03): add LabeledSlider shared widget + unit test`

### Task 4 — `SwatchButton` shared widget + test

type=auto

`include/BALL/VIEW/WIDGETS/swatchButton.h` + `.C` — replacement for `ColorButton` that respects QSS-driven theming. Public: ctor `(QColor initial, QWidget* parent=nullptr)`, `QColor color() const`, `setColor(QColor)`, signal `colorChanged(QColor)`. On click, opens `QColorDialog::getColor`; if accepted, updates the swatch and emits `colorChanged`. The swatch itself is the button's background-rect (paintEvent draws a rounded-rect filled with `color_`, hairline 1px border in mid-grey). objectName `"swatchButton"` so theme QSS can target it.

Test: ctor stores color, `setColor` updates + emits when different, no emit when identical (avoid spurious notifications).

Commit: `feat(999.43/04): add SwatchButton shared widget + unit test`

### Task 10 — IconBrowser dev tool (BALL_UI_V2 && debug build only)

type=auto

`source/APPLICATIONS/BALLVIEW/iconBrowser.{h,C}` — a `QDialog` showing all icons from the `theme.qrc` bundle in a `QListWidget` grid (icon mode, 64×64 cells, name as text under each icon). Reads the icon list from a static manifest array embedded in `iconBrowser.C` (initial pass; future enhancement: scan `theme.qrc` at build time). Each cell tooltip shows the four state tints (Normal/Active/Selected/Disabled) rendered as a small horizontal pixmap strip in the tooltip text.

Wiring in `mainframe.C`: only add a `Tools › Developer › Icon Browser` menu entry when `defined(BALL_UI_V2)` AND `!defined(NDEBUG)`. In release builds with `BALL_UI_V2=ON`, no menu entry. In all OFF builds, no compilation of the menu hook.

Add `iconBrowser.h` to `MOC_SOURCES_LIST`, `iconBrowser.C` to `SOURCES_LIST`. Both wrap in `#ifdef BALL_UI_V2` inside the file (cheap stub if flag off) — or alternately, add to CMake only when `BALL_UI_V2`. Pick the inline `#ifdef` form so the matrix's UI-V2-OFF cells still build the same TU set (Phase 999.42 set the precedent).

Commit: `feat(999.43/10): add IconBrowser dev tool (BALL_UI_V2 + debug only)`
