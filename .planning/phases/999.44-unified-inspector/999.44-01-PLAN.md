# Phase 999.44 Plan 01 — Unified Inspector (Handover Phase 4)

## Objective

Land the architectural shell + Controller-extraction pattern + an exemplar Scene-tab section for the BALLView Refresh Unified Inspector. Replaces (incrementally) the 10+ legacy modal-dialog soup with a right-rail `QDockWidget`-based Inspector containing 3 tabs (Selection / Representation / Scene) and ~13 collapsible sections. All new surface behind `BALL_UI_V2`.

This plan delivers the **risk-mitigation prerequisite** (Controller extraction pattern + one exemplar) plus the **architecturally load-bearing shell** (sub-PR 4.1) plus the **interim home for legacy dialogs** (sub-PR 4.6). Sub-PRs 4.2/4.3/4.4/4.5 full coverage is **scope-trimmed to v1.7 RC patch cycle** with breadcrumb (see Deferred section) — the architecture this plan ships makes them mechanical follow-ups.

### Task 1 — Inspector shell (sub-PR 4.1): InspectorDock + InspectorView + InspectorTabs + InspectorBody

**Type:** auto

**Files:**

- NEW: `include/BALL/VIEW/WIDGETS/inspector/inspectorDock.h`
- NEW: `include/BALL/VIEW/WIDGETS/inspector/inspectorView.h`

- NEW: `source/VIEW/WIDGETS/inspector/inspectorView.C`
- NEW: `source/VIEW/WIDGETS/inspector/inspectorTabs.C`
- NEW: `source/VIEW/WIDGETS/inspector/inspectorBody.C`
- NEW: `source/VIEW/WIDGETS/inspector/inspectorSection.C`
- MODIFIED: `source/VIEW/WIDGETS/sources.cmake` (add inspector/ subtree)

**Behavior:**

- `InspectorDock` is a `QDockWidget`, right area, title-less on macOS (`setTitleBarWidget(new QWidget)` per Handover §Cross-platform notes). Hosts `InspectorView`.
- `InspectorView` is the root `QWidget`. Owns the `InspectorTabs` (top, 28px tab strip) + `InspectorBody` (scrollable, 1 page per tab — `QStackedWidget` under a `QScrollArea`).
- `InspectorTabs` exposes the 3 tabs Selection / Representation / Scene; emits `tabChanged(int)` consumed by `InspectorBody`.
- `InspectorBody` is a `QStackedWidget` with one page per tab. Each page is a vertical `QVBoxLayout` of `InspectorSection`s with `addStretch(1)` at the bottom.
- `InspectorSection` is the per-section host: header (`SectionHeader` from 999.43) + content `QWidget`. Owns its expanded/collapsed state and a `QPropertyAnimation` on the content's `maximumHeight` (160ms `OutCubic`). Emits `expandedChanged(bool)`.
- All headers behind `BALL_UI_V2`. CMake `sources.cmake` conditionally adds `inspector/*.C` under `IF(BALL_UI_V2)` — no-op when flag is OFF so the existing build path is unaffected.

**Done when:**

- All 5 headers + 5 implementation files compile under `BALL_UI_V2=ON` (local macOS-arm64).
- `sources.cmake` does not include inspector files when `BALL_UI_V2` is OFF (existing CI cells stay green).
- No mainframe wiring yet — that's Task 2.

**Type:** auto

  ```ini
  [Inspector]
  visible=true
  tab=Representation
  Selection.Properties=expanded
  Representation.Model=collapsed
  Scene.Stage=expanded
  ```

**Behavior:**

- Mainframe adds the dock with `addDockWidget(Qt::RightDockWidgetArea, inspector_dock_)` inside the existing `#ifdef BALL_UI_V2` block (already in place from 999.42/.43).
- View menu gets a checkable `Hide Inspector` action wired to the dock's `setVisible()`. Shortcut `Ctrl+\` (Qt's `Meta+\` maps to ⌘ on macOS).
- `InspectorView` reads the `[Inspector]` group on construction and applies (visible / current tab / per-section collapsed states). Writes on each change with a 250ms debounced timer.
- INI keys use the schema `<tab>/<section>=expanded|collapsed`. Unknown keys are ignored (forward-compat).
- Persistence is wired via `QSettings(IniFormat)` pointed at the existing `.BALLView` config file path so it lives in the same file as the legacy preferences.

**Done when:**

### Task 4 — Controller extraction pattern (sub-PR 4.5 prerequisite): StageController exemplar

**Type:** auto

**Files:**

- NEW: `include/BALL/VIEW/KERNEL/controllers/stageController.h`
- NEW: `source/VIEW/KERNEL/controllers/stageController.C`
- MODIFIED: `source/VIEW/KERNEL/sources.cmake` — add controllers/ subtree under `IF(BALL_UI_V2)`.

**Behavior:**

- `StageController` is a `QObject` that owns the presentation logic currently embedded in `StageSettings` (`stageSettings.C` — 720 LOC). Constructor takes a `Stage*` + a `Scene*` (the two collaborators `StageSettings` reaches for). Provides:
  - `void apply()` — push current model state to the `Stage`/`Scene`.
  - `void revert()` — read from the `Stage`/`Scene`, populate model state.
  - **Properties exposed via Qt property system** (`Q_PROPERTY`) for each setting: `backgroundColor`, `showCoordinateSystem`, `mouseSensitivity`, `wheelSensitivity`, `fogActive`, `environmentMapActive`, etc. Each property emits a `xxxChanged` signal on mutation. Both the legacy `StageSettings` dialog (when re-wired in a future plan) and the new Inspector `StageSection` (Task 5) bind to these properties.
- The controller does NOT depend on Qt **widgets** — only on `QObject` + `QColor`. Verified by the includes: `<QtCore/QObject>`, `<QtGui/QColor>`, `<BALL/VIEW/KERNEL/stage.h>`. No `<QtWidgets/*>` in the header. This is what "headless-testable" means for Task 4's acceptance.
- Initial extraction is **read-only mirror** of stage state — the methods that actually mutate `Stage`/`Scene` are stubbed with a `TODO(999.44-RC-patch): mirror StageSettings::apply()` comment plus a `Log::warn` so the future cut-over is visible. This keeps the plan landed in this session reviewable and atomic; the legacy `StageSettings` dialog continues to do all the actual mutation until a follow-up plan migrates the apply logic across (controller-shared invariant from Handover acceptance criteria).
- The Controller-extraction PATTERN this exemplifies is documented in the controller header preamble (5-line comment block: "this is the template — extract one Controller per legacy dialog, both surfaces bind to it"). Future Controllers (LightController / CameraController / ModelController / ColoringController / MaterialController / LabelController / ClippingController / StereoController) are stubbed as one-line `// TODO(999.44-RC-patch): extract per pattern` items in a new `source/VIEW/KERNEL/controllers/PATTERN.md` file co-located in the controllers/ subtree.

**Done when:**

- Header + impl compile under `BALL_UI_V2=ON` (libBALL_VIEW link).
- `StageController` has zero `<QtWidgets/*>` includes (verified by grep).
- `PATTERN.md` enumerates the 8 remaining Controllers as TODOs with file-name and source-dialog mapping.

### Task 5 — Scene tab StageSection (partial sub-PR 4.5): binds to StageController

**Type:** auto

**Files:**

- NEW: `include/BALL/VIEW/WIDGETS/inspector/sections/stageSection.h`
- NEW: `source/VIEW/WIDGETS/inspector/sections/stageSection.C`
- MODIFIED: `source/VIEW/WIDGETS/sources.cmake` — add the new source.
- MODIFIED: `source/VIEW/WIDGETS/inspector/inspectorView.C` — wire StageSection into the Scene tab when a Stage exists.

**Behavior:**

- `StageSection` is an `InspectorSection` subclass titled "Stage". Header (`SectionHeader`) + content panel with:
  - A `SwatchButton` for background colour.
  - A `LabeledSlider` (0-100) for mouse sensitivity.
  - A `LabeledSlider` (0-100) for wheel sensitivity.
  - A `QCheckBox` for "Show coordinate system".
  - A `QCheckBox` for "Fog enabled".
- All controls bind bidirectionally to `StageController` properties via Qt's `connect()` of `xxxChanged` signal ↔ widget setter. Slider/swatch user-edits debounce through a `QTimer::singleShot(100, ...)` to coalesce drag streams (the "100ms-debounced live commits" requirement). On debounce fire, calls `controller_->apply()` (which is currently the stubbed mirror — actual mutation cut-over is in a follow-up plan; for now `apply()` emits its `appliedStub` signal which `inspectorView` can wire to a `Log::info` line so the live-commit pipeline is end-to-end observable).
- Empty state replacement: when `Stage*` is non-null, the Scene tab `forNoScene` empty state is replaced by a `QVBoxLayout` containing the StageSection (+ stretch). When the scene is closed (no Stage), the section is removed and the empty state returns.

**Done when:**

- `BALL_UI_V2=ON` build green; loading a PDB shows the Stage section in the Scene tab.
- Toggling the section header collapses/expands the content with the 160ms animation.
- Section's collapsed/expanded state persists across restart under `[Inspector] Scene.Stage=...`.
- Moving a slider logs a debounced "Stage settings applied (stub)" line (≤1 line per 100ms regardless of drag rate).
