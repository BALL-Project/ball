# Phase 999.58 Plan 03: scene.C dialog cut-over + stereo relocation Summary

**scene.C now constructs none of LightSettings/MaterialSettings/StageSettings, registers none in the Preferences stack, reads its (deferred) stereo config from a Scene-owned StereoScreenConfig struct, computes stereo defaults in-Scene, and the tutorial dialog is repointed off the scene dialog accessors — the VIEW-CLEAN-03 construction grep proof passes and the BALLView build links green (BALL_UI_V2=ON), GUI render UAT pending.**

## Performance

- **Duration:** ~25 min
- **Tasks:** 3 of 3 code/build tasks complete (Task 4 is the BLOCKING human-verify checkpoint — pending)
- **Files modified:** 3

## Accomplishments
- **Scene-owned StereoScreenConfig (Task 1):** added a `StereoScreenConfig` struct + `stereo_screen_config_` member to scene.h, holding the 9 fields the StageSettings stereo accessors returned (left/right/control screen index default -1; left/right eye geometry default-empty QRect; control + stereo-screens renderer type default `OPENGL_RENDERER`; stereo mode default `NO_STEREO`). Repointed all four deferred stereo bodies (`enterStereo`, `enterDualStereo`, `enterDualStereoDifferentDisplays`) to read this struct instead of `stage_settings_->get*`. The guard-and-return at the head of each body is **unchanged** — the bodies stay dead/deferred to Phase 5; only the config SOURCE below the return changed (T-99858-07 mitigation preserved).
- **applyStereoDefaults relocated (Task 1):** inlined the geometry-based eye-separation/focal-distance computation from `StageSettings::computeDefaultPressed()` directly into `Scene::applyStereoDefaults()`, writing through `stage_->setEyeDistance/setFocalDistance` and `setDownsamplingFactor()`; the dialog-only slider refreshes were dropped and the dialog's fixed .ui distance defaults (150/6) inlined as constants.
- **Dialog constructions + Preferences stack removed (Task 2):** deleted `light_settings_(new LightSettings)`/`material_settings_(new MaterialSettings)` from the constructor init list and the `stage_settings_=new StageSettings(this)` statement; removed the three `insertEntry`/`removeEntry`+null-out blocks from `initializePreferencesTab`/`finalizePreferencesTab` (EditSettings preserved); removed the `REMOVE_COORDINATE_SYSTEM` `stage_settings_->updateFromStage()` dialog readback; removed the stale `if (light_settings_ == 0) return;` guard; removed the members, forward decls, and `getStageSettings()`/`getMaterialSettings()` accessors from scene.h.
- **Tutorial repointed (Task 3):** dropped all 6 demoTutorialDialog reach-throughs (`getStageSettings()->updateFromStage()` ×3, `getMaterialSettings()->updateDefaultMaterialsFromStage()`, `LightSettings::getInstance(0)->updateFromStage()` ×2) — UI-refresh calls with no target now — while preserving every surrounding Stage mutation + `applyPreferences()`. All sites are inside `#ifdef BALL_HAS_RTFACT` (dormant this era).
- **Unused dialog includes dropped** from both consumers so they compile after 999.53 deletes the headers.
- **Build green:** `cmake --build build-ui-on --target BALLView` (BALL_UI_V2=ON, macOS arm64) — libVIEW.dylib + BALLView.app link clean, only the pre-existing Qt/GLEW header `#warning`s.

## Decisions Made
See `key-decisions` in frontmatter. Core decisions: (1) the StereoScreenConfig holds ONLY the screen/geometry/mode/renderer-type fields (not eye/focal/swap, which are Stage/StereoController-owned) to avoid a double-write race; (2) applyStereoDefaults inlines computeDefaultPressed's math with the dialog's fixed .ui distance defaults as constants; (3) the stale light_settings_ guard was removed since it only fired during Preferences teardown.
